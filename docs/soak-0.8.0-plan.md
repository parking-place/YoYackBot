# 0.8.0-P5 8시간 시험 사전 기준

이 기준은 시험 시작 전에 고정한다. 개발 LXC의 서비스는 시작 시 기록한 정확한 구현 SHA로 8시간 이상 유지하며, 가용 시간이 짧아진 시험은 통과로 계산하지 않는다. 기준선 측정 시 봇 서비스 메모리는 약 35 MiB, DB는 약 49 KiB, 호스트 가용 메모리는 약 8 GiB였다. 다른 서비스의 자원을 점유하지 않도록 입력은 합성값만 사용한다.

## 부하와 관측

- 60초마다 별도 격리 DB와 가짜 Discord 채널에서 수집→모델→게시 워크플로를 한 번 실행한다. 여섯 채널을 순환하여 성공·중복 대기 시간 안내를 반복한다.
- 15회마다 모델 timeout, 저장소 용량 부족, 대기열 포화, 생성 시각 기준 TTL 삭제를 합성 장애로 주입한다. 실제 호스트 디스크를 채우지 않는다.
- 실제 인증 모델에 합성 대화만 넣는 비게시 probe를 시작·중간·끝에 세 번 실행한다. 대화문이나 모델 출력은 시험 기록에 쓰지 않는다.
- 4시간 지점에서 개발 봇 서비스를 계획적으로 한 번 재시작해 Discord 연결 복원과 주시 설정·대기 시간 보존을 확인한다.
- 최소 8시간의 monotonic 경과, 분당 표본 최소 460개, 실제 서비스 준비 상태 99% 이상(계획 재시작 전후 최대 2분 제외), 합성 순환 최소 460회, 세 모델 probe 성공을 요구한다.

## 사전 통과 임계값

| 항목 | 임계값 |
|---|---:|
| 서비스 메모리 최대 | 512 MiB |
| 서비스 CPU 60초 구간 평균 최대 | 단일 코어의 200% |
| 서비스 작업 수 최대 | 32개 |
| DB 크기 증가 | 20 MiB 이하 |
| 서비스 전용 journal 크기 | 50 MiB 이하 |
| 계획 외 재시작 | 1회 이하 |
| 종료 시 요청 임시 디렉터리·원문 백업·7일 초과 메시지 | 각 0개 |
| 합성 장애 후 영구 대기열·채널 잠금 | 0개 |

모든 표본은 시각·SHA·숫자·성공 여부만 비공개 JSONL로 저장한다. 중간 실패, 누락 표본, 고정 SHA 변화 또는 임계값 초과가 있으면 결과를 FAIL로 기록하고 원인을 수정한 새 SHA로 8시간을 다시 시작한다. 계획 재시작은 시스템 장애 재시작과 별도로 센다. 결과 문서에는 총 시간과 최대값, 실패 횟수, 제한만 옮긴다.
