# 1.1.3 승격과 복귀

1. [1.1.3 상태](../Plans/0.DevelopPhase/1.1.3/STATUS.md)의 P1~P2 원격 완료와 P3 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.1.3`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. **진행 중 요약이 없는지** 서비스 로그로 확인한 뒤(서비스 시작 이후 `summary_request_parsed` 수와 결과 줄 수가 같은지) 중지한다. 중지 전에 Gateway·주시 채널·DB 무결성을 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. **DB schema는 5 그대로이며, 관리 역할용 선택 테이블이 처음 시작할 때 생긴다.**
4. 시작 후 명령어 동기화로 `/채널 설정`과 `/관리권한 설정`이 등록된다. 실행 판정은 봇이 하므로 처음에는 관리자(관리자·채널 관리 권한)만 쓸 수 있다. 필요한 서버는 `/관리권한 설정`이나 운영 명령 `manager-roles`로 봇 관리 역할을 넣는다. 저장 시 `manager_roles_saved at=… count=…`가 남는다.
5. 시험 서버에서 일반 계정의 `/채널 설정` 거절, 관리자의 `/관리권한 설정` 저장, 그 역할 계정의 `/채널 설정` 사용, `!!요약좀 도움` 마지막 줄을 확인한다. 실제 확인을 하지 못하면 **NOT_RUN**으로 남긴다.

복귀가 필요하면 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.1.2a)의 wheel `1.1.2.1`과 checkout SHA `0e6db0c`를 함께 복원한다. schema가 같으므로 DB는 그대로 쓴다. **복귀하면 관리 역할 표는 무시되고 슬래시 명령어는 다시 `애플리케이션 명령어 사용` 권한이 있는 누구나 쓰게 되며, `/관리권한 설정`은 다음 동기화 때 사라진다.** `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
