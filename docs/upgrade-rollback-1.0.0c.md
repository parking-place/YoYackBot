# 1.0.0c 승격과 복귀

1. [단계 상태](../Plans/0.DevelopPhase/1.0.0c/STATUS.md)의 P1~P4 원격 완료와 P5 후보의 LXC 전체 시험·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 모두 `1.0.0.3`이고 checkout SHA가 동일해야 한다. 전용 Gateway는 한 개만 실행한다.
2. 서비스 중지 전에 현재 요약 작업 수, Gateway 상태, 주시 채널 수, SQLite `quick_check`, 백업 경로를 비밀·원문 없이 기록한다. 전용 데이터 경로에서 SQLite 백업을 만든 뒤 다시 무결성을 검사한다. 백업·인증 파일을 GitHub에 올리지 않는다.
3. 서비스를 정상 중지하고 정확한 후보 wheel을 전용 가상환경에 설치한 뒤 같은 SHA로 checkout을 맞춘다. `check-ready`와 설치 모듈 경로를 확인하고 서비스를 시작한다. Gateway 준비·단일 프로세스·기존 주시 설정·DB 무결성을 확인한다. 재연결 간격의 History 재확인이 끝날 때까지 요약 요청은 준비 전 안내를 받을 수 있다.
4. 새 기본 정책은 모델 실행 동시성 **1**, 모델 대기 슬롯 **8**, 최대 대기 **600초**, 모델 실행 상한 **120초**다. 운영 환경 변수에 이전 명시값이 있으면 새 기본값을 덮어쓰므로 실제 적용값을 확인한다. 대기열이 꽉 차면 포화 안내를 보내며 무한 대기하지 않는다. 처음 주시하는 채널의 과거 수집은 전체 최대 3페이지·서버당 최대 2페이지로 제한한다. Discord 요청 제한·권한 오류에서는 해당 채널의 커서와 실패 상태를 확인한다.
5. 새 채널의 시작·완료 공지, 준비 중 요청 차단, 여러 채널의 합성 요약 게시, 중복 안내·서버별 자료 분리, 채널별 쿨타임을 시험 Discord에서 확인한다. 시험이 불가능하면 **NOT_RUN**으로 기록하고 자동·실서비스 상태 검사와 혼동하지 않는다. 8/24시간 연속 시험은 사용자의 지시에 따라 생략한다.

복귀가 필요하면 서비스를 정상 중지하고 `v1.0.0b-1`의 검증된 wheel `1.0.0.2`와 checkout을 함께 복원한다. 이 버전은 P3의 병렬 수집 코드가 없고 대기열 기본값 4/180초다. 환경에 명시한 8/600초 값은 자동으로 옛 기본값으로 돌아가지 않으므로 복귀 정책을 함께 점검한다. DB와 인증 파일은 삭제하지 않는다. SQLite 무결성·설치 버전·Gateway를 다시 확인하고 필요한 경우 보호된 백업을 사용한다. 실제 복귀를 수행하지 않았다면 사전 호환성 검사만 증거로 남긴다.
