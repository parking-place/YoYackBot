# 1.4.0 승격과 복귀

1. **사전 확인**: [1.4.0 상태](../Plans/0.DevelopPhase/1.4.0/STATUS.md)에서 P1~P6 원격 완료를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.4.0`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다.
2. **중지 전 백업**: 진행 중 요약·`!!말하자면`이 없는지 서비스 로그로 확인한다(접수 줄 수 = 결과 줄 수). SQLite 온라인 백업과 설정 전용 백업을 만든 뒤 중지한다.
3. **설치와 점검**: 후보 wheel을 설치하고 checkout을 같은 SHA로 맞춘다. `check-ready`, 설치 모듈 버전, 프롬프트 `1.4.0-p6-v1`, Gateway·`health`·DB `quick_check`(schema 5)를 확인한다. 선택 테이블 `execution_settings`·`execution_roles`·`guild_notices`는 시작할 때 생긴다. 슬래시 명령이 8개(채널·관리권한·도움말·말투·속도·말하자면·처형설정·처형)로 동기화되는지 본다. 서비스 환경은 바뀌지 않는다.
4. **Discord 권한**: 봇 역할에 **감사 로그 보기**와 **멤버 타임아웃** 권한을 주고, 처형 대상이 될 역할보다 위에 둔다. intent는 `moderation`(특권 아님)을 더 요청한다.
5. **확인**: 시험 서버에서 `/처형설정 채널관리`로 로그 채널을 정하고 `/처형설정 관리역할`로 처형 역할을 고른다. Discord 화면에서 한 타임아웃·해제와 `/처형`의 로그(처형자가 명령을 쓴 사람인지)를 본다. `/말투`로 서버 말투를 저장한 뒤 결과 알림과 안내 문구가 바뀌는지, 기본값으로 되돌리면 돌아오는지 본다. 실제 확인을 하지 못한 항목은 **NOT_RUN**으로 남긴다.

**복귀**가 필요하면 서비스를 정상 중지한 다음 [`v1.3.4`](https://github.com/parking-place/YoYackBot/releases/tag/v1.3.4)의 wheel `1.3.4`와 checkout `1491025`를 함께 복원한다. DB·서비스 환경은 그대로 쓴다. 복귀하면 처형 로그·`/처형`·`/처형설정`과 서버별 안내 문구가 사라지고, 저장한 서버 말투는 1.3.4의 말투 단락으로 그대로 쓰인다. 새 표의 행은 남지만 1.3.4는 읽지 않으며, 1.4.0을 다시 올리면 봇이 없는 서버의 행을 정리한다.
