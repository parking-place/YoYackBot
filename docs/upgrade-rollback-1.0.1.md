# 1.0.1 승격과 복귀

1. [1.0.1 상태](../Plans/0.DevelopPhase/1.0.1/STATUS.md)의 P1~P5 원격 완료와 P6 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.0.1`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. 중지 전에 Gateway·주시 채널·DB 무결성과 실행 중 요약 수를 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다. 인증·DB·대화 원문은 GitHub 산출물에 넣지 않는다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. **이 버전은 DB schema와 설정 항목을 바꾸지 않는다.**
4. `!!요약좀 사용량`은 서비스 계정으로 고정 CLI의 `app-server`를 짧게 실행한다. 요청별 `request-usage-*` 임시 디렉터리(입력 경로 아래, 0700)에 인증 사본을 두며, 비정상 종료로 남으면 다음 시작 때 기존 요청 정리와 함께 지운다. 인증 갱신은 요약과 같은 비교·교체로만 저장한다.
5. `!!요약좀 상태`의 DB 크기는 모든 서버가 함께 쓰는 SQLite 주 파일(+WAL이 있으면 합산)이다. 주시 채널 수·캐시 건수·마지막 요약은 요청한 서버의 값만 보인다.
6. 시험 채널에서 `도움`, `사용량`, `상태`, `[범위] 자세히`, `[범위] 짧게`를 확인한다. 실제 게시 확인을 하지 못하면 **NOT_RUN**으로 남긴다. 8/24시간 연속 시험은 생략한다.

복귀가 필요하면 새 요청을 막고 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.0.0d)의 wheel `1.0.0.4`와 checkout SHA를 함께 복원한다. schema가 같으므로 DB는 그대로 쓴다. DB와 인증 파일은 지우지 않으며 `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
