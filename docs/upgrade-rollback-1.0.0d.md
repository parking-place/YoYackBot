# 1.0.0d 승격과 복귀

1. [단계 상태](../Plans/0.DevelopPhase/1.0.0d/STATUS.md)의 P1~P4 원격 완료와 P5 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.0.0.4`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. 중지 전에 Gateway·주시 채널·DB 무결성과 실행 중 요약 수를 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다. 인증·DB·대화 원문은 GitHub 산출물에 넣지 않는다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. 이 버전은 DB schema를 바꾸지 않는다.
4. 모델 실행 동시성은 기본 **4**, 최대 **4**다. 대기 슬롯은 기본 8, 최대 대기는 600초, 개별 모델 상한은 120초다. 환경에 `YOYACK_CODEX_CONCURRENCY=1` 같은 명시값이 있으면 그대로 적용되므로 실제 설정을 확인한다. 동시 요청은 요청별 인증 사본을 쓰고, 갱신 파일은 원본 사본과 같을 때만 원자적으로 교체한다. 다른 요청이 이미 갱신한 경우 오래된 사본을 버린다. 갱신 경쟁 중 한 요청의 인증이 실패할 수 있으며, 다음 요청은 최신 공유 인증을 다시 읽는다.
5. 시험 채널에는 합성 대화만 게시하고 화자명·동명이인·개명·멘션 안전성·장문 분할을 확인한다. 사용자가 실제 게시 결과 미확인 상태의 진행을 허용했으므로 시험 불가 시 **NOT_RUN**으로 남긴다. 8/24시간 연속 시험도 생략한다.

복귀가 필요하면 새 요청을 막고 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.0.0c)의 wheel `1.0.0.3`과 checkout SHA를 함께 복원한다. 동시성 기본값도 1로 돌아간다. DB와 인증 파일은 지우지 않으며, schema 호환성을 격리 사본에서 확인하고 `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
