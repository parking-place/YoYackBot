# 1.3.0 승격과 복귀

1. **사전 확인**
   - [1.3.0 상태](../Plans/0.DevelopPhase/1.3.0/STATUS.md)에서 P1~P6 원격 완료를 확인한다. P7 후보는 개발 LXC 검사·CI를 통과해야 한다.
   - `VERSION`, wheel, 설치 모듈이 `1.3.0`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. **중지 전 백업**
   - **진행 중 요약이 없는지** 서비스 로그로 확인한다. 서비스 시작 이후 `summary_request_parsed` 수와 결과 줄 수가 같아야 한다. 그다음 중지한다.
   - 중지 전에 Gateway·주시 채널·DB 무결성을 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다.
3. **설치와 점검**: 서비스를 정상 중지하고 후보 wheel을 설치한 뒤 checkout을 같은 SHA로 맞춘다. 다음을 확인한다.
   - `check-ready`, 설치 모듈 버전, 프롬프트 `1.3.0-p6-v3`
   - Gateway 재연결, `health`의 `collection_worker=running`, DB `quick_check`
   - 슬래시 명령 `/말투` 등록
   - DB 변경: **schema 5는 그대로**다. 처음 열 때 선택 테이블 `recent_ratings`·`guild_tones`가 생긴다. 1.2.0의 선택 테이블과 메시지 삭제 trigger는 그대로 쓴다.
4. **시험 채널 확인**: 실제 확인을 하지 못한 항목은 **NOT_RUN**으로 남긴다.
   - `/말투` 보기·수정·기본값으로, 바뀐 말투로 `!!요약좀`
   - 메시지에 답장으로 `!!요약좀`(기간을 함께 쓴 경우 포함)
   - 여러 번 요약해 떡밥 한줄 평가가 겹치지 않는지
   - `!!말하자면` 한 줄·이모지·서버 말투 미적용·일반 요약과의 공통 쿨타임
   - 기존 `사용량`·`상태`·`채널`·`도움`·`/채널 설정`·`/관리권한 설정`

**복귀**가 필요하면 서비스를 정상 중지한 다음 [`v1.2.0`](https://github.com/parking-place/YoYackBot/releases/tag/v1.2.0)의 wheel `1.2.0`과 checkout `613856e`를 함께 복원한다. 서비스 환경에 `YOYACK_CODEX_REASONING_EFFORT=medium`이 있으면 1.2.0은 이를 허용하지 않아 요약이 사용 불가가 되므로 그 줄도 지운다(기본 `low`).
- DB는 그대로 쓴다. 1.2.0은 `recent_ratings`·`guild_tones`를 읽지 않는다. 그래서 기본 말투·이전 평가 방식으로 돌아가고 `/말투`·`!!말하자면`·답장 범위가 사라진다. 1.2.0의 버그 수정·수집 진행·답글 연결은 유지된다.
- 1.2.0은 `!!말하자면`을 일반 대화로 저장할 수 있다. 1.3.0으로 다시 올리면 읽을 때 그 행을 대화에서 뺀다.
- 1.2.0으로 복귀한 동안 주시를 해제한 채널의 최근 평가는 1.3.0이 DB를 다시 열 때 정리된다. **복귀 중 봇이 서버를 나간 경우 그 서버의 말투는 남는다**(1.2.0은 이 표를 모른다). 다시 초대되면 이전 말투가 적용되므로, 필요하면 `/말투`에서 기본값으로 되돌린다.
- 복귀 뒤 `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
