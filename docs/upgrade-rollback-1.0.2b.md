# 1.0.2b 승격과 복귀

1. [1.0.2b 상태](../Plans/0.DevelopPhase/1.0.2b/STATUS.md)의 P1~P2 원격 완료와 P3 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.0.2.1`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. 중지 전에 Gateway·주시 채널·DB 무결성과 실행 중 요약 수를 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다. 인증·DB·대화 원문은 GitHub 산출물에 넣지 않는다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. **이 버전은 DB schema와 설정 항목을 바꾸지 않는다.**
4. `!!요약좀 채널`은 주시 설정과 Discord 채널 캐시만 읽는다. 명령한 사람의 채널 보기 권한으로 목록을 거르므로, 비공개 주시 채널은 볼 수 있는 사람에게만 보인다. 로그에는 보낸 채널 수만 남는다.
5. 시험 서버에서 주시 채널의 `!!요약좀 채널`(목록), 미주시 채널의 `!!요약좀 채널`(미주시 안내만), `!!요약좀 도움`의 새 줄을 확인한다. 실제 확인을 하지 못하면 **NOT_RUN**으로 남긴다. 8/24시간 연속 시험은 생략한다.

복귀가 필요하면 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.0.2)의 wheel `1.0.2`와 checkout SHA `ee17265`을 함께 복원한다. schema가 같으므로 DB는 그대로 쓴다. `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
