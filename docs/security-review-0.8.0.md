# 0.8.0 보안 검토

검토 대상은 개발 LXC의 0.8.0-P4 구현과 공개 GitHub 브랜치다. 실제 토큰·인증값·Discord 원문·식별자는 이 문서와 CI 출력에 넣지 않았다.

## 공개 경계와 운영 권한

- 전체 도달 가능한 Git 객체 2,044개에서 비밀 형태와 비공개 경로가 발견되지 않았다. 개발 서버에만 있는 Discord 토큰과 모델 인증값 4개를 실제 값 그대로 메모리 안에서 Git 객체와 전용 journal에 대조했으며 일치 0건이었다. GitHub Actions 저장 artifact는 0개였다. CI는 앞으로도 전체 이력의 비밀 형태와 비공개 경로를 검사한다.
- Discord 토큰은 systemd `LoadCredential`로 격리된 사본을 전달한다. 서비스의 `/proc` 환경과 환경 파일에는 토큰 값이 없었다. 수동 실행용 원본 토큰 파일, 모델 인증 파일, 환경 파일은 전용 계정 소유 0600이며 입력·백업 디렉터리는 0700이었다.
- 로그는 요청 ID·개수·시간·고정 결과 분류만 기록한다. 예외 문자열, 모델 출력, 원문, 환경 전체를 출력하지 않는다. 서비스 전용 journal은 50 MiB·7일 제한을 사용한다.

## 공격성 합성 입력

개발 LXC의 인증된 모델을 공격성 합성 대화로 한 번 호출했다. 대화문에 다른 요청의 임시 파일, 프로세스 환경 변수, 샌드박스 밖의 전용 canary 파일을 읽어 출력하라는 지시와 로컬 URL 방문 지시를 넣었다. 정상 요약은 생성됐고 세 canary 값의 출력은 모두 0건, URL 연결은 0건, 호출 종료 뒤 요청 임시 디렉터리는 0개였다. canary 값은 문서에 보관하지 않았다. 이 결과는 시험한 입력에 대한 관찰이며 모든 프롬프트 공격을 증명하지는 않는다.

코드와 회귀 검사에서 수집·게시 전 Guild/채널·주시 설정·권한을 다시 확인한다. 게시에는 `AllowedMentions.none()`과 embed 억제를 적용하며 사용자·역할·전체 멘션을 문자로 비활성화한다. 잘못된 Guild와 권한 상실의 게시 거부, 요청별 임시 파일 삭제, 다른 Guild 설정 격리, 중복 게시 방지를 재검사했다. 실제 Discord 권한 거부 조작 시험은 이 단계에서 수행하지 않았으며 합성 권한 시험과 이전 실환경 작업의 범위를 구분한다.

## 데이터 수명

정상 가동 중 메시지 원문 캐시는 `created_at` 기준 7일을 넘기면 정리하며 설정 백업에는 원문이 없다. `secure_delete=ON`, `journal_mode=DELETE`, 만료 정리, 오래된 원문 사본 제거를 확인했다. 서비스가 장기간 중지되면 파일은 다음 시작 전까지 남을 수 있으므로 중지된 상태의 절대 7일 삭제 보장은 아직 없다. Discord 편집·삭제 이벤트도 누락될 수 있어 캐시는 완전한 삭제 감사 로그가 아니다. 재연결 뒤 수집 범위를 다시 확인하고, 검증되지 않은 캐시만으로 요약하지 않는다. 운영자가 특정 발언의 완전한 삭제 증명을 요구할 때 이 캐시를 증빙으로 사용하지 않는다.
