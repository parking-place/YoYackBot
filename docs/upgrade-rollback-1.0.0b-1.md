# 1.0.0b-1 승격과 복귀

검증된 **정확한 SHA**에서 만든 `1.0.0.2` wheel만 설치한다. 현재 개발 LXC와 봇 전용 계정을 그대로 사용하며, Gateway 프로세스는 한 개만 실행한다. 운영 DB·Discord 인증·Codex 인증·대화 원문은 저장소와 GitHub Release에 넣지 않는다.

## 승격 전 점검

1. [단계 상태](../Plans/0.DevelopPhase/1.0.0b-1/STATUS.md)의 P1~P5 완료와 P6 후보의 전체 자동 검사 결과를 확인한다. `VERSION`, 패키지 메타데이터, 설치 wheel의 버전은 모두 `1.0.0.2`여야 한다.
2. 현재 서비스의 설치 버전·checkout SHA·Gateway 연결·실행 중 요약 수와 SQLite `quick_check`를 값과 식별자 노출 없이 기록한다. DB는 보호된 경로에만 백업하고 원문을 로그로 출력하지 않는다.
3. 운영 환경의 `YOYACK_QUEUE_WAIT_SECONDS`를 확인한다. 명시값이 있으면 새 기본값 180초를 덮어쓴다. 모델 동시성 1, 대기 슬롯 4, 모델 실행 상한 120초를 함께 확인한다.
4. 별도 후보 경로에서 전체 테스트, Lint, 버전 출력, 격리 DB로 `check-ready`, 1.0.0a 소스로 읽는 스키마 호환성, 실제 모델의 합성 대량 입력을 확인한다. 이 단계는 운영 Gateway를 실행하지 않는다.

## 적용과 확인

1. 서비스가 처리 중인 요약을 확인한 뒤 정상 중지한다. 검증된 wheel을 전용 가상환경에 설치하고 checkout도 같은 SHA로 맞춘다. 실제 `site-packages` 모듈 경로와 `python -m yoyackbot version`을 확인한 다음 `check-ready`를 실행한다.
2. 서비스를 시작하고 `health.ready`, `gateway_ready`, 단일 Gateway, 주시 설정 보존을 확인한다. 기존 주시 채널은 한 번 최근 30일의 접근 가능한 History를 전체 수집한다. 이관 중 요약은 준비 전 안내를 받고, 신규 첫 주시 채널과 달리 시작·완료 문구를 소급 게시하지 않는다.
3. 신규 시험 채널은 `안녕하시오. 요약을 위해 데이터 수집중이오.`를 보내고 과거 기록을 수집한다. 그동안 들어온 메시지는 Gateway로 즉시 DB에 기록한다. 과거 페이지를 끝내면 **첫 수집 시작부터 그 완료 시각까지를 History로 한 번 더 조회**하고 메시지 ID 중복을 제거한다. 이 재확인이 끝나야 `이제부터 요약을 해줄 수 있을 것 같소.`를 게시하고 요약 요청을 받는다. 그 전 요청에는 `참을성을 기르시오 아직 준비가 되지 않았소.`만 답한다.
4. 일반 요약은 DB에서만 선택하고 요청마다 History를 재조회하지 않는다. 연결이 끊긴 뒤의 누락 구간은 별도 복구 작업으로 확인한다. 권한 거부는 저장된 커서에서 차단 상태로 남고, 접근 권한이 회복되면 그 위치부터 재개한다. 429·일시적 네트워크 오류는 커서를 보존한 채 재시도한다.
5. 개인 대화가 없는 시험 채널에서 100건 초과 합성 입력의 요약 게시, 빈 대화, 재확인 중 요청 차단, 다른 채널의 독립 진행을 확인한다. 실제 Discord 결과와 격리 합성 결과를 따로 기록한다. 사용자의 결정에 따라 8시간·24시간 연속 시험은 요구하지 않는다.

30일 캐시 전체가 모델의 요청별 입력 한도를 넘을 수 있다. 이때 일부만 요약해 전체 결과처럼 게시하지 않고, `요약할 대화가 너무 많소. 기간이나 메시지 개수를 줄여 다시 명하시오.`라고 안내한다. 캐시 보관 30일과 단일 요청이 처리할 수 있는 대화량은 서로 다른 한도다.

## 복귀

정상 중지 후 `v1.0.0a`의 검증된 wheel과 checkout을 설치하고 `check-ready`·버전·Gateway를 다시 확인한다. 후보가 추가한 `backfill_state`·삭제 기록과 차단 사유 열은 스키마 5의 선택적 확장이므로 이전 리더가 무시할 수 있다. 사전 격리 복귀 시험을 통과한 경우에만 같은 DB로 서비스를 시작하며, 접근·무결성 문제가 있으면 서비스를 정지한 상태에서 원인을 조사한다. DB와 인증 파일을 삭제하거나 강제로 재설정하지 않는다. 이전 버전은 요청별 History 보충 경로를 다시 사용하므로 복귀 뒤 대량 요청의 성능·동작은 후보와 다를 수 있다.

실행 결과와 SHA·wheel 해시는 [P6 상태](../Plans/0.DevelopPhase/1.0.0b-1/STATUS.md)에서 연결할 증거에 기록한다. 이 문서는 절차이며 실제 배포 성공 증거가 아니다.
