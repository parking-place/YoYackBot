# 1.3.1 승격과 복귀

1. **사전 확인**
   - [1.3.1 상태](../Plans/0.DevelopPhase/1.3.1/STATUS.md)에서 P1~P3 원격 완료를 확인한다. P4 후보는 개발 LXC 검사·CI를 통과해야 한다.
   - `VERSION`, wheel, 설치 모듈이 `1.3.1`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. **중지 전 백업**
   - **진행 중 요약이 없는지** 서비스 로그로 확인한다. 서비스 시작 이후 `summary_request_parsed` 수와 결과 줄 수가 같아야 한다. 그다음 중지한다.
   - 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다.
3. **설치와 점검**: 서비스를 정상 중지하고 후보 wheel을 설치한 뒤 checkout을 같은 SHA로 맞춘다. 다음을 확인한다.
   - `check-ready`, 설치 모듈 버전, 프롬프트 `1.3.0-p6-v3`(1.3.1에서 바뀌지 않음)
   - Gateway 재연결, `health`의 `collection_worker=running`, DB `quick_check`
   - 슬래시 명령 `/도움말`·`/속도 설정` 등록
   - DB 변경: **schema 5는 그대로**다. 처음 열 때 선택 테이블 `idiom_cooldowns`·`guild_fast_mode`가 생긴다. 모든 서버는 빠른 모드 꺼짐으로 시작한다.
   - 서비스 환경의 `YOYACK_CODEX_REASONING_EFFORT`(운영 `medium`)는 그대로 둔다.
4. **시험 채널 확인**: 실제 확인을 하지 못한 항목은 **NOT_RUN**으로 남긴다.
   - `!!말하자면`이 시작 안내 없이 한 줄로 답하는지, 성공 직후 `!!요약좀`이 바로 되는지(그 반대도)
   - 일반 구성원이 `/도움말`을 쓰면 본인에게만 보이는지, `!!요약좀 도움`이 한 줄 안내만 남기는지
   - `/속도 설정` 켜기·끄기, 켠 뒤의 `!!요약좀`·`!!말하자면`(지표 `speed=fast`)
   - 기존 `사용량`·`상태`·`채널`·`/채널 설정`·`/관리권한 설정`·`/말투`

**복귀**가 필요하면 서비스를 정상 중지한 다음 [`v1.3.0`](https://github.com/parking-place/YoYackBot/releases/tag/v1.3.0)의 wheel `1.3.0`과 checkout `df159cc`를 함께 복원한다. 서비스 환경은 바꾸지 않는다(1.3.0도 `medium`을 허용한다).
- DB는 그대로 쓴다. 1.3.0은 `idiom_cooldowns`·`guild_fast_mode`를 읽지 않는다. 그래서 `!!말하자면`은 다시 시작 안내를 보내고 요약과 쿨타임을 함께 쓴다. 모든 서버가 보통 속도가 되고, `!!요약좀 도움`은 다시 채널에 도움말 전체를 올린다. `/도움말`·`/속도 설정`은 명령 목록에서 사라진다.
- 복귀한 동안 주시를 해제한 채널의 `idiom_cooldowns` 행은 1.3.1이 DB를 다시 열 때 정리된다. **복귀 중 봇이 서버를 나간 경우 그 서버의 빠른 모드 설정이 남는다**(1.3.0은 이 표를 모른다). 다시 초대되면 빠른 모드가 켜진 채로 돌아오므로, 필요하면 `/속도 설정`에서 끈다.
- 복귀 뒤 `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
