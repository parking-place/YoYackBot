# 1.4.1b 승격과 복귀

1. **사전 확인**: [1.4.1b 상태](../Plans/0.DevelopPhase/1.4.1b/STATUS.md)에서 P1 원격 완료를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.4.1.1`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다.
2. **중지 전 백업**: 진행 중 요약·`!!말하자면`이 없는지 서비스 로그로 확인한다(접수 줄 수 = 결과 줄 수). SQLite 온라인 백업과 설정 전용 백업을 만든 뒤 중지한다.
3. **설치와 점검**: 후보 wheel을 설치하고 checkout을 같은 SHA로 맞춘다. `check-ready`, 설치 모듈 버전, 프롬프트 `1.4.0-p6-v1`(변경 없음), Gateway·`health`·DB `quick_check`(schema 5)를 확인한다. 슬래시 명령이 10개(1.4.1의 9개 + 처형도움)로 동기화되는지 본다. DB·서비스 환경·봇 권한은 1.4.1과 같다.
4. **확인**: 시험 서버에서 처형·사면을 해서 로그가 구분선·빈 줄·끝 간격이 있는 새 모양인지, 풀리는 시각이 맞는지 본다. `/처형도움`이 부른 사람에게만 보이는지 본다. 실제 확인을 하지 못한 항목은 **NOT_RUN**으로 남긴다.

**복귀**가 필요하면 서비스를 정상 중지한 다음 [`v1.4.1`](https://github.com/parking-place/YoYackBot/releases/tag/v1.4.1)의 wheel `1.4.1`과 checkout `18ec31e`를 함께 복원한다. DB·서비스 환경은 그대로 쓴다. 복귀하면 로그가 1.4.0 모양으로 돌아가고 `/처형도움`이 사라진다. 1.4.1b가 더한 문구 행은 1.4.1이 읽지 않는다.
