# 0.9.0-P4 짧은 부하·보존 경계 사전 기준

[사용자 결정](../Plans/0.DevelopPhase/DURATION_WAIVER.md)에 따라 24시간 연속 시험은 수행하지 않는다. 개발 LXC의 정확한 후보 SHA에서 기존 `scripts/soak_080.py`의 격리 `--test-mode`로 **최소 120초, 1초 간격, 최소 110개 표본과 합성 요청 110회**를 실행한다. 실제 봇 서비스는 게시하지 않는 합성 모델 probe 한 번과 상태 표본으로 확인한다. 진짜 Discord 사용자 메시지는 이 부하에 넣지 않는다.

시작 전에 0.8.0의 자원 한도를 그대로 고정한다: 준비 표본 비율 99% 이상, RSS 최대 512 MiB, cgroup 메모리 최대 768 MiB, CPU 구간 평균 단일 코어 200% 이하, 작업 수 최대 32, DB 증가 20 MiB 이하, 전용 journal 50 MiB 이하. 합성 fault drill은 15회마다 timeout·저장소 full·대기열 포화·TTL을 주입한다. 실행 오류, SHA 불일치, 종료 시 요청 디렉터리·대기/실행 큐·원문 DB 백업·만료 메시지가 있으면 이 짧은 검사를 실패로 본다.

별도 격리 SQLite fixture로 `created_at` 7일 경계의 메시지와 coverage 절단, 2~4주 요청의 비영속 처리를 검사한다. 실제 서비스 DB에서는 만료 메시지 수와 무결성을 읽기 전용으로 확인한다. 모델/Discord 외부 장애와 제품 결함은 0.9.0-P3의 분류 결과를 참고하되 이 2분 실행을 24시간 가용성·누적 누수 증거로 부르지 않는다.

`--test-mode`는 의도적으로 장시간 `eligible=false`를 기록한다. 이번 단계의 짧은 검사는 위 사전 기준을 별도로 판정하고, 24시간 항목은 `SKIPPED_BY_USER`로 남긴다. 비공개 JSONL 원본·인증·Discord 원문은 저장소에 올리지 않는다.
