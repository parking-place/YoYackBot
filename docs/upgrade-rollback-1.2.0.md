# 1.2.0 승격과 복귀

1. **사전 확인**
   - [1.2.0 상태](../Plans/0.DevelopPhase/1.2.0/STATUS.md)에서 P1~P6 원격 완료를 확인한다. P7 후보는 개발 LXC 검사·CI를 통과해야 한다.
   - `VERSION`, wheel, 설치 모듈이 `1.2.0`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. **중지 전 백업**
   - **진행 중 요약이 없는지** 서비스 로그로 확인한다. 서비스 시작 이후 `summary_request_parsed` 수와 결과 줄 수가 같아야 한다. 그다음 중지한다.
   - 중지 전에 Gateway·주시 채널·DB 무결성을 확인한다. 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다.
3. **설치와 점검**: 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. 다음을 확인한다.
   - `check-ready`(실패하면 사유 이름이 나온다)
   - 설치 모듈 경로·버전, 프롬프트 `1.2.0-p6-v1`
   - Gateway 재연결, `health`의 `collection_worker=running`, DB `quick_check`
   - DB 변경: **schema 5는 그대로**다. 처음 열 때 선택 테이블 `backfill_progress`·`message_reply_refs`와 메시지 삭제 trigger 하나가 생긴다. 기존 캐시의 답글은 "대상 미확인"으로 시작하며 강제 재수집은 없다.
4. **시험 채널 확인**: 실제 확인을 하지 못한 항목은 **NOT_RUN**으로 남긴다.
   - `!!요약좀 채널`(DM 전달·공개 안내)
   - `!!요약좀 상태`(이 채널 수집 형편)
   - 답글이 섞인 대화의 `!!요약좀`
   - 기존 `사용량`·`도움`·`/채널 설정`·`/관리권한 설정`

**복귀**가 필요하면 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.1.3a)의 wheel `1.1.3.1`과 checkout SHA `d51c72a`를 함께 복원한다.
- DB는 그대로 쓴다. 1.1.3a는 새 선택 테이블을 읽지 않는다. 메시지 삭제 trigger는 남아 1.1.3a의 삭제·정리·주시 해제 때도 답글 링크를 지운다.
- 다시 1.2.0으로 올리면 DB를 열 때 고아 진척·링크 행을 정리한다. 1.1.3a가 진행한 수집 회차의 쪽 수는 "확인할 수 없소"로 표시한다.
- 복귀하면 목록이 다시 공개 채널에 게시되고, 상태의 채널 구역·답글 연결·worker 보호가 빠진다.
- 복귀 뒤 `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
