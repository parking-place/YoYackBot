# 1.0.2c 승격과 복귀

1. [1.0.2c 상태](../Plans/0.DevelopPhase/1.0.2c/STATUS.md)의 P1~P3 원격 완료와 P4 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.0.2.2`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. 중지 전에 Gateway·주시 채널·DB 무결성과 실행 중 요약 수를 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다. 인증·DB·대화 원문은 GitHub 산출물에 넣지 않는다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. **이 버전은 DB schema를 바꾸지 않는다.**
4. 설정 파일에 `YOYACK_SUCCESS_COOLDOWN_SECONDS`가 없으면 쿨타임은 60초다. 다른 값을 쓰려면 설정 파일에 명시한다. 업그레이드 직전 5분으로 걸린 채널은 남은 시간이 60초로 줄어든다.
5. 요약 말투는 신뢰 프롬프트 `1.0.2c-p2-v2`를 쓴다. 공개 서버에서 비속어가 나오는 점을 운영자가 알고 있어야 한다. 집단 비하어는 자동으로 막지만, 실제 사람을 성적으로 다뤘는지는 사람이 확인해야 한다.
6. 시험 채널에서 요약 1건의 말투·사실, 성공 직후 같은 채널 재요청의 `01분 00초` 이하 안내, 1분 뒤 재요청 입장을 확인한다. 실제 확인을 하지 못하면 **NOT_RUN**으로 남긴다. 8/24시간 연속 시험은 생략한다.

복귀가 필요하면 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.0.2b)의 wheel `1.0.2.1`과 checkout SHA `8ef4f59`를 함께 복원한다. schema가 같으므로 DB는 그대로 쓴다. **복귀하면 쿨타임 기본값이 다시 5분**이 되고 요약 말투도 이전 하오체로 돌아간다. `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
