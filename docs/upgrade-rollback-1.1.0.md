# 1.1.0 승격과 복귀

1. [1.1.0 상태](../Plans/0.DevelopPhase/1.1.0/STATUS.md)의 P1~P4 원격 완료와 P5 후보의 개발 LXC 검사·CI를 확인한다. `VERSION`, wheel, 설치 모듈이 `1.1.0`이고 checkout이 후보의 정확한 코드 SHA인지 확인한다. Gateway는 전용 계정에서 한 개만 실행한다.
2. **진행 중 요약이 없는지** 서비스 로그로 확인한 뒤(마지막 `summary_request_parsed`마다 결과 줄이 있는지) 중지한다. 중지 전에 Gateway·주시 채널·DB 무결성을 확인하고, 전용 계정만 읽는 경로에 SQLite 온라인 백업과 설정 전용 백업을 만든다.
3. 서비스를 정상 중지하고 후보 wheel을 전용 가상환경에 설치한 뒤 서비스 checkout을 같은 코드 SHA로 맞춘다. `check-ready`, 설치 모듈 경로·버전, Gateway 재연결, 주시 채널 준비 상태, DB `quick_check`를 확인한다. **이 버전은 DB schema와 설정 항목을 바꾸지 않는다.**
4. 기본 요약이 짧아지고 `길게`·`자세히`·추가 요청이 생긴다는 점을 서버에 알린다. 추가 요청은 사용자가 쓴 문장이 모델 입력에 들어가므로, 요약 결과가 이상하면 해당 요청 문장과 함께 확인한다(로그에는 원문이 없고 유무·길이만 남는다).
5. 시험 채널에서 `!!요약좀`(짧게), `!!요약좀 길게`, `!!요약좀 [범위] 자세히`, `!!요약좀 2분 길게 시간순으로 해줘`, `!!요약좀 자세히 2시간`(사용법 안내), `!!요약좀 도움`을 확인한다. 실제 확인을 하지 못하면 **NOT_RUN**으로 남긴다. 8/24시간 연속 시험은 생략한다.

복귀가 필요하면 서비스를 정상 중지한 다음 [이전 검증 릴리스](https://github.com/parking-place/YoYackBot/releases/tag/v1.0.2c)의 wheel `1.0.2.2`와 checkout SHA `fd1ecbe`를 함께 복원한다. schema가 같으므로 DB는 그대로 쓴다. **복귀하면 기본 요약이 다시 길어지고**, `길게`와 추가 요청 문장은 사용법 안내가 되며, 말투도 1.0.2c로 돌아간다. `check-ready`·Gateway·DB 무결성을 다시 검사한다. 실제 복귀를 하지 않았다면 격리 호환성 검사와 절차만 증거로 기록한다.
