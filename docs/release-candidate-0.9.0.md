# 0.9.0 출시 후보 검토

이 문서는 1.0.0 진입을 위한 개발 후보를 고정한다. 정식 배포, `v1.0.0` 태그 또는 GitHub Release가 아니다. 최종 후보와 단계별 원격 증거 SHA는 [0.9.0-P5 증거](../Plans/0.DevelopPhase/evidence/0.9.0-P5.md)에 기록한다.

## 고정 대상

| 항목 | 후보 |
|---|---|
| 마지막 제품 코드 변경 | `8085be4a6958826045be37d423a1806bbf2ecd87`; 이후 0.9.0에서 `src`, `tests`, `deploy`, `scripts`, 설정 예시·잠금 파일 변경 없음 |
| 런타임 | LXC Python 3.13 계열, `discord.py==2.7.1`, 잠금 파일 SHA-256 `5625a66a79a2fc5958fd50bf1fc93b63eeb43456a51b21251afa5269091403af` |
| DB·보존 | schema 5, 생성 시각 기준 7일 영속 캐시, 설정 전용 백업·격리 복원 |
| 모델·프롬프트 | Codex CLI `gpt-6-luna`, reasoning `low`, 프롬프트 `0.6.0-p5-v2` |
| 서비스 | 전용 `systemd` 계정/credential, 단일 Gateway 프로세스, 구조화된 안전 로그와 상태 검사 |

`pyproject.toml`과 패키지 내부 버전은 아직 `0.1.0`이다. **1.0.0-P2에서** 배포 산출물과 함께 `1.0.0`으로 바꾸어 깨끗한 경로에서 재현성을 검증해야 한다. 이번 후보 문서가 1.0.0 버전 식별을 대신하지 않는다.

## 확인한 근거

- [전체 요구 회귀](../Plans/0.DevelopPhase/evidence/0.9.0-P1.md): §53의 46개 항목을 연결하고 정확 SHA에서 221개 자동 검사·실제 인증 모델 합성 probe를 실행했다.
- [개발 Discord 베타](../Plans/0.DevelopPhase/evidence/0.9.0-P2.md): 여덟 옵션의 빈 대화 안내, 도움말, 합성 대화의 실제 모델 요약 게시와 성공 대기 안내를 확인했다. 모델 21개 합성 사례 중 중대한 오류 0, 필수 근거 44/45, 하오체 21/21이었다.
- [장애 복구](../Plans/0.DevelopPhase/evidence/0.9.0-P3.md): 격리 장애 검사와 실제 프로세스 비정상 종료 후 약 10초 복귀, 설정·대기 기록 보존을 확인했다.
- [짧은 부하·보존](../Plans/0.DevelopPhase/evidence/0.9.0-P4.md): 올바른 상태 파일 경로의 120초/120회 실행이 사전 자원 기준을 통과했고 7일 경계 fixture가 통과했다. 초기 계측 경로 오류 실행은 무효로 따로 기록했다.

## 알려진 제한과 대응

| 제한 | 영향과 대응 |
|---|---|
| 8시간 및 각 24시간 지속 시간 [사용자 생략](../Plans/0.DevelopPhase/DURATION_WAIVER.md) | 장시간 가용성과 누적 누수 부재는 미검증이다. 운영자는 상태·자원·전용 journal을 계속 확인한다. |
| 실제 Discord 권한 회수와 일반 사용자 설정 거부 조작 미실행 | 격리 권한 검사만 통과했다. 운영자는 주시/권한 변경 뒤 실제 채널에서 재확인하고 실패 시 주시 해제·서비스 중지를 우선한다. |
| 모델 출력 한 사례에서 ‘내일’ 시점 생략 | 21개 합성 사례의 필수 근거 44/45(97.8%). 화자 오귀속·날조는 관찰되지 않았다. 날짜가 중요한 요약은 원문 확인을 안내한다. |
| 장기간 서비스 중지 시 DB 파일의 절대 7일 삭제 지연 | 시작 시 정리하지만 중지 중에는 실행되지 않는다. 운영자는 장기 중지·복구 전에 보존 상태를 확인한다. |
| 자동 외부 경고 미설정 | `health`와 전용 journal의 운영 점검 기준을 따르며 장애 발견이 늦어질 수 있다. |

현재 관측된 치명/높음 결함은 0건이다. 위 미실행·제한은 PASS로 바꾸지 않는다. 1.0.0-P1에서 선행 50단계의 원격 증거와 이 제한을 다시 검토하고, P2~P4에서 패키지·롤백·실배포를 검증한 뒤에만 정식 릴리스 여부를 판정한다.
