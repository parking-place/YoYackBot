# 1.1.2a-P2 — 닉네임 밑줄

- 상태: **PLANNED** · 검사: `T112a-P2-A/B` · 환경: 개발 LXC, 합성 대역(모델 호출 없음)

## 선행 조건·작업

[P1](01-command-permission.md)의 원격 완료 뒤 [계약](CONTRACT.md) 2절대로 요약 후처리에 화자 이름 밑줄을 넣는다. 이번 요청의 화자 표시 이름(`speaker_labels`)을 긴 이름부터 찾아 서술자 문장 안에서 `__이름__`으로 감싼다. 코드 블록·인라인 코드·`>` 인용·따옴표 인용·이미 밑줄 친 이름·평가 머리말은 건드리지 않고, 한 글자 이름은 앞뒤가 공백·문장부호·줄 끝일 때만 감싼다. 이모지 제거·평가 줄 처리·미결 조롱 검사·주제 비평 지표와 같은 후처리 순서 안에 넣고, 메시지 분할은 밑줄을 붙인 뒤 한다.

## 검증·완료 기준

- `T112a-P2-A`: 합성 출력에서 짧게 문장·굵은 화자 불릿(`**__이름__**`)·조사가 붙은 이름(“가람은”)·이름 겹침(“가람”/“가람이”)·`사용자 (1)`·전각 문자로 바뀐 이름이 정확히 한 번씩 감싸지고, 인용·코드·이미 밑줄·한 글자 이름이 낱말 일부인 경우는 그대로다. 같은 입력을 두 번 처리해도 결과가 같다.
- `T112a-P2-B`: 합성 엔진 대역으로 `이모지 빼고`·`평가 빼줘`·`시간순으로`와 함께 동작하고, 평가 줄·거절 안내·미결 조롱·주제 비평 판정이 바뀌지 않으며, 긴 요약 분할이 2,000 단위 안에서 밑줄을 쪼개지 않는다. 전체 회귀 통과.

같은 SHA의 결과를 [증거 양식](../EVIDENCE_TEMPLATE.md)에 남기고 구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 각각 commit·GitHub push·원격 확인한다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
