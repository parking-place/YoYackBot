# 1.1.2a-P3 — 통합·배포·출시

- 상태: **PLANNED** · 검사: `T112a-P3-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1·P2](STATUS.md)의 원격 완료를 확인한다. `CHANGELOG`·`docs/upgrade-rollback-1.1.2a.md`(복귀 대상 `v1.1.2`, wheel `1.1.2`, schema 변경 없음)를 갱신한다. 패키지·`VERSION`을 `1.1.2.1`로, 버전 대응표와 저장소 검증기에 1.1.2a의 3단계·6검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 진행 중 요약이 없음을 확인하고 이전과 같은 절차로 배포한다. 명령어 등록 정보(이름·기본 권한)는 바뀌지 않으므로 서버 관리자가 이미 해 둔 연동 권한 설정은 그대로 유지돼야 한다. 이전 `v1.1.2` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 서버에서 확인한다: (1) 서버 설정 → 연동 → 요약봇에서 관리자가 아닌 역할이나 사람에게 `/채널 설정`을 허용, (2) 그 사람이 `/채널 설정`을 열고 저장, (3) 허용하지 않은 일반 사용자에게는 명령어가 보이지 않음, (4) `!!요약좀 도움`의 새 문구. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T112a-P3-A`: 전체 회귀와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T112a-P3-B`: 후보·서비스 SHA 대조, 시험 Discord 사용자 확인과 서비스 로그(`watched_channels_saved`) 대조, 배포·복귀·비밀정보 비노출·P1~P2 원격 증거, 병합 후 `main` CI를 기록한다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합한다. 태그 `v1.1.2a`와 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
