# 1.1.2a 짧은 도움말·마크다운 요약·닉네임 밑줄·슬래시 명령어 권한 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 출시된 `v1.1.2`(2026-10-01) 코드를 기준으로 작성했다.

## 1. 도움말을 짧게 (사용자 요청, 2026-10-01)

`!!요약좀 도움`(1.1.2 기준 1,163자)을 아래 문안으로 바꾼다. 사용자가 준 문안(최종 수정본)을 글자 그대로 쓰되, 최대 기간 숫자만 지금처럼 설정값(`YOYACK_MAX_DAYS`, 기본 30)에서 넣는다(아래 `{max_days}`). 빈 줄과 줄 끝 공백 두 칸(Discord 줄바꿈)은 문안대로 둔다.

```text
📜 **요약 사용법**

`!!요약좀` → 최근 1시간  
`3` → 3시간 / `30분` `2시간` `100개` `오늘` `2일` `1주` `{max_days}일` 지원  
※ 숫자만 쓰면 시간, 최대 {max_days}일

🔍 `길게` → 흐름·결정 포함  
🔎 `자세히` → 가장 상세  
✏️ 뒤에 요청 추가 가능: `시간순으로`, `욕 빼고`, `평가 빼줘` 등  
※ 추가 요청 200자, 범위 변경·허위 생성 불가

⚙️ `사용량` → Codex 한도  
📊 `상태` → 채널·캐시·DB·마지막 요약  
📡 `채널` → 주시 채널

진행 중엔 현재 범위, 수집 중엔 준비 중이라고 답하오.  
주시 채널은 `/채널 설정`에서 정하시오.
```

- 최대 기간이 2일보다 짧게 설정되면 `2일` 예를 뺀다(거절될 예를 보여 주지 않는 지금 원칙).
- 빈 주시 목록 안내(`!!요약좀 채널`)는 “관리자가”를 빼고 “지금 보고 있는 채널이 없소. `/채널 설정`으로 정하시오.”로 바꾼다.

## 2. 요약문에 마크다운 적극 사용·주제 한줄 비평 인용 형식

요약 본문에서 Discord 마크다운을 적극적으로 써서 훑어보기 쉽게 한다. 형식 예(합성 대화, 실제 대화가 아님):

```text
### 🚀 배포 날짜
__가람__이 ~~금요일~~ 대신 **목요일 오후 2시**로 바로잡았고 __나래__가 찬성했소. ✅ **결정**: **목요일 오후 2시** 배포
> ↳ _배포 얘기 틈에 점심 메뉴까지, 화제가 휙휙 튀오_ 🌀

### 🧯 롤백 담당
__다온__이 롤백 담당을 물었고 다음 회의에서 정하자고 했소. ⏳ **진행 중**: 롤백 담당
> ↳ _롤백 소리만 나와도 다들 등골이 서늘한 모양이오_ 🥶

**요약창섭의 떡밥 한줄 평가** : 달력 한 장에 이렇게 요란 떨 일이오? 🔥
```

| 요소 | 1.1.2 | 1.1.2a |
|---|---|---|
| 주제 소제목 | `**🚀 주제**`(굵은 줄) | **`### 🚀 주제`**(Discord 제목) |
| 결정·진행 중 묶음(길게·자세히) | `**✅ 결정 난 거**` | `### ✅ 결정 난 거` / `### ⏳ 진행 중인 거` |
| 주제 한줄 비평 | `↳ *…*` | **`> ↳ _…_ 이모지`**(인용 블록 + 기울임) |
| 화자 닉네임 | 그대로(굵은 불릿만 `**이름**`) | **밑줄 `__이름__`**, 굵은 불릿은 `**__이름__**` |
| 핵심 숫자·시간·금액·결정 | 굵게 가능 | **굵게 적극 사용** |
| 정정·철회된 안 | 글로만 | **취소선** `~~금요일~~ → **목요일**`(원문에서 실제로 정정·철회된 것만) |
| 떡밥 한줄 평가 | `**요약창섭의 떡밥 한줄 평가** : …` | 그대로(머리말 글자 유지) |

- **닉네임 밑줄은 모델에게 맡긴다**(사용자 결정). 프롬프트가 “scope의 `speaker_names` 이름을 본문에 쓸 때마다 `__이름__`”을 지시하고, 코드는 밑줄이 빠진 이름 수를 지표(`name_underline=all/partial/none/na`)로만 남긴다(재생성 없음). 주제 한줄 비평·떡밥 한줄 평가에는 이름을 쓰지 않는다(기울임 `_…_` 안에서 밑줄이 섞여 깨지는 것을 막음). 이름은 표시 이름 정리 단계에서 Markdown 특수 문자가 전각으로 바뀌어 있어 밑줄이 깨지지 않는다.
- 주제 한줄 비평은 **인용문** `> ↳ _비평_ 이모지` 한 줄이다(사용자 요청: 인용문으로). `>`는 지금까지 “원문 인용 전용”이라 검사(비하어·미결 조롱)가 건너뛰었으므로, **`> ↳`로 시작하는 줄은 서술자 줄로 검사**하도록 코드를 바꾼다. 원문을 인용할 때는 `> "원문"`처럼 따옴표를 붙인다.
- 마크다운이 사실을 바꾸지 않는다: 취소선은 원문에서 실제로 정정·철회된 안에만, 굵게는 강조일 뿐 결정 여부를 바꾸지 않는다. 스포일러(`||…||`)·링크·`#`/`##` 큰 제목은 쓰지 않는다(`###`만).
- 추가 요청(`시간순으로`, `표로`, `이모지 빼고`, `욕 빼고`, `비평 빼줘` 등)은 1.1.1 규칙대로 기본 형식보다 먼저다. `이모지 빼고`의 코드 제거는 `### ` 소제목·`> ↳` 비평 줄에서도 마크다운을 깨지 않아야 한다.
- 코드 검사·지표를 새 형식에 맞춘다: 주제 소제목 인식(`### …`와 이전 굵은 줄 모두), 주제 비평 인식(`> ↳`와 `↳` 모두), `topic_critique`, 미결 조롱·비하어 검사, 이모지 제거, 메시지 분할(인용 블록·제목 줄 경계).

## 3. 슬래시 명령어 권한

`/채널 설정`을 비롯한 **모든 슬래시 명령어**(이후 추가되는 것 포함)를 **`애플리케이션 명령어 사용` 권한이 있는 사람이면 누구나** 쓰고 설정할 수 있게 한다(사용자 결정).

| 경우 | 1.1.2 | 1.1.2a |
|---|---|---|
| 서버 관리자 / 채널 관리 권한 | 사용 가능 | 사용 가능 |
| `애플리케이션 명령어 사용` 권한이 있는 일반 사용자(Discord 기본값: 모든 사람) | 명령어가 안 보임 | **처음부터 보이고 사용·저장 가능** |
| 그 권한을 서버·채널에서 끈 사람 | 사용 불가 | 사용 불가(Discord가 막음) |
| 서버 설정 → 연동에서 명령어를 막은 역할·사람·채널 | 사용 불가 | 사용 불가(Discord가 막음) |
| DM·서버 밖 | 거절 | 거절 |

- 명령어 등록의 기본 권한을 `manage_channels`에서 **`use_application_commands`**로 바꾼다. 설치 직후부터 적용되고, 이미 설치된 서버도 다음 명령어 동기화 때 바뀐다. 서버 관리자가 연동 화면에서 해 둔 개별 설정은 Discord가 그대로 우선한다.
- 봇의 자체 권한 검사(`can_manage`: 관리자·채널 관리)를 없애고 Discord의 판단을 따른다. 명령어 실행 시에는 서버 안 상호작용인지만 확인한다.
- 이후 추가되는 명령어도 같은 규칙을 따르도록 **공통 등록 도우미**(서버 전용 + 기본 권한 `use_application_commands`)를 만들고, 명령어 트리에 등록된 모든 명령어·그룹이 그 규칙을 따르는지 검사하는 시험을 둔다.
- 설정 화면(버튼·채널 선택)은 **화면을 연 본인만** 조작할 수 있고 제한 시간(120초)도 그대로다. 저장 시 봇 접근 가능 채널·텍스트 채널 검사, 동시 수정 감지는 그대로다. 동시 수정 안내는 “다른 관리자가” → “다른 사람이”.
- **변경 기록**: 저장할 때 지표 로그 `watched_channels_saved`에 **시각과 채널 수만** 남긴다(서버 ID는 기존 로그 규칙대로, 사용자 ID·채널 이름 없음).
- 알아 둘 점: 서버의 누구나 주시 채널을 추가·제거·전체 해제할 수 있게 된다. 막고 싶은 서버는 서버 설정 → 연동에서 역할별로 제한할 수 있다(채널 설정 문서에 적음). `!!요약좀` 텍스트 명령의 권한은 바뀌지 않는다.

## 4. 실제 모델 확인

마크다운·비평 줄·닉네임 밑줄이 모두 프롬프트로 바뀌므로 합성 사례로 **6건**(짧게 4 + 길게 2, 사용자 결정)을 비게시로 돌려 확인한다.
