# 1.1.2a 짧은 도움말·닉네임 밑줄·슬래시 명령어 권한 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 출시된 `v1.1.2`(2026-10-01) 코드를 기준으로 작성했다.

## 1. 도움말을 짧게 (사용자 요청, 2026-10-01)

`!!요약좀 도움`(1.1.2 기준 1,163자)을 아래 문안으로 바꾼다. 사용자가 준 문안을 그대로 쓰되, 최대 기간 숫자는 지금처럼 설정값(`YOYACK_MAX_DAYS`, 기본 30)에서 넣는다(아래 `{max_days}`). 문단 사이 빈 줄과 줄 끝 공백 두 칸(Discord 줄바꿈)은 문안대로 둔다.

```text
📜 **요약 사용법**

`!!요약좀` → 최근 1시간 요약  
`!!요약좀 3` → 3시간  
`30분` `2시간` `100개` `오늘` `2일` `1주` `{max_days}일`도 가능하오.  
※ 숫자만 쓰면 시간, 기간은 최대 {max_days}일이오.

🔍 `길게` → 흐름·결정·진행사항 포함  
🔎 `자세히` → 가장 촘촘하게  
`짧게` → 기본과 같소.

✏️ 뒤에 원하는 형식을 적어도 되오.  
예: `!!요약좀 오늘 길게 시간순으로`, `!!요약좀 욕 빼고`  
※ 추가 요청은 200자까지이며 범위 변경·허위 생성은 듣지 않소.

🍡 기본적으로 끝에 **요약창섭의 떡밥 한줄 평가**가 붙소.

⚙️ `사용량` → Codex 한도  
📊 `상태` → 채널·캐시·DB·마지막 요약  
📡 `채널` → 볼 수 있는 주시 채널

요약 중 다시 부르면 진행 범위를 알려주며, 수집 중이면 준비 중이라고 답하오.  
주시 채널은 관리자가 `/채널 설정`에서 정하시오.
```

- 최대 기간이 2일보다 짧게 설정되면 `2일` 예를 빼고(지금 도움말과 같은 원칙: 거절될 예를 보여 주지 않음), `{max_days}일`이 30이 아니어도 그 값을 쓴다.
- 마지막 줄 “관리자가”는 3절(누구나 `/채널 설정` 사용)과 맞지 않는다. 사용자 문안을 따르되, 확인 결과에 따라 “주시 채널은 `/채널 설정`에서 정하시오.”로 바꿀 수 있게 결정 표에 둔다.
- 빈 주시 목록 안내(`!!요약좀 채널`)의 “관리자가 `/채널 설정`으로 정하시오.”도 같은 결정을 따른다.

## 2. 요약 속 닉네임에 밑줄

요약 본문에 나오는 **화자 닉네임**(scope의 `speaker_names` 표시 이름)을 Discord 밑줄(`__이름__`)로 표시한다. 형식 예(합성 대화, 실제 대화가 아님):

```text
__가람__은 배포를 금요일로 하자고 했다가 목요일 오후 2시로 바로잡았고, __나래__는 그 시간에 찬성했소. ✅ **결정**: 목요일 오후 2시 🚀
- **__다온__**: 롤백 담당을 물었소. ❓
```

- **코드가 결정적으로 붙인다**(모델에게 맡기지 않음). 요약이 끝난 뒤 이번 요청의 화자 표시 이름 목록으로 서술자 문장 안의 이름을 찾아 `__…__`로 감싼다. 굵게 쓴 화자 불릿(`- **가람**:`)은 `- **__가람__**:`가 된다.
- 감싸지 않는 곳: 코드 블록·인라인 코드, `>` 인용 줄, 따옴표 인용(원문 인용), 이미 밑줄이 있는 이름, 떡밥 한줄 평가 머리말. 다른 화자 이름의 일부인 경우(예: `가람`과 `가람이`가 둘 다 화자)에는 긴 이름을 먼저 감싼다. 한 글자 이름은 다른 낱말의 일부와 구별하기 어려워 앞뒤가 공백·문장부호·줄 끝일 때만 감싼다.
- 이름은 이미 표시 이름 정리 단계에서 Markdown 특수 문자(`_`·`*`·`~`·`|` 등)를 전각 문자로 바꿔 두므로 밑줄이 깨지지 않는다. 모델이 이름 뒤에 붙인 호칭(“의원” 등)은 이름이 아니므로 밑줄 밖에 둔다.
- `이모지 빼고`·`평가 빼줘`·`시간순으로` 같은 추가 요청과 함께 동작한다. 메시지 길이 계산은 밑줄을 붙인 뒤 한다.

## 3. 슬래시 명령어 권한

`/채널 설정`을 비롯한 **모든 슬래시 명령어**(이후 추가되는 것 포함)를 **`애플리케이션 명령어 사용` 권한이 있는 사람이면 누구나** 쓰고 설정할 수 있게 한다(사용자 결정).

| 경우 | 1.1.2 | 1.1.2a |
|---|---|---|
| 서버 관리자 / 채널 관리 권한 | 사용 가능 | 사용 가능 |
| `애플리케이션 명령어 사용` 권한이 있는 일반 사용자(Discord 기본값: 모든 사람) | 명령어가 안 보임 | **처음부터 보이고 사용·저장 가능** |
| 그 권한을 서버·채널에서 끈 사람 | 사용 불가 | 사용 불가(Discord가 막음) |
| 서버 설정 → 연동에서 명령어를 막은 역할·사람·채널 | 사용 불가 | 사용 불가(Discord가 막음) |
| DM·서버 밖 | 거절 | 거절 |

- 명령어 등록의 기본 권한을 `manage_channels`에서 **`use_application_commands`**로 바꾼다. 설치 직후부터 적용되고, 이미 설치된 서버도 다음 명령어 동기화 때 바뀐다. 서버 관리자가 연동 화면에서 해 둔 개별 설정은 Discord가 그대로 우선한다.
- 봇의 자체 권한 검사(`can_manage`: 관리자·채널 관리)를 없애고 Discord의 판단을 따른다. 명령어 실행 시에는 서버 안 상호작용인지만 확인한다.
- 이후 추가되는 명령어도 같은 규칙을 따르도록 **공통 등록 도우미**(서버 전용 + 기본 권한 `use_application_commands`)를 만들고, 명령어 트리에 등록된 모든 명령어·그룹이 그 규칙을 따르는지 검사하는 시험을 둔다.
- 설정 화면(버튼·채널 선택)은 **화면을 연 본인만** 조작할 수 있고 제한 시간(120초)도 그대로다. 저장 시 봇 접근 가능 채널·텍스트 채널 검사, 동시 수정 감지는 그대로다. 동시 수정 안내는 “다른 관리자가” → “다른 사람이”.
- **변경 기록**: 저장할 때 지표 로그 `watched_channels_saved`에 **시각과 채널 수만** 남긴다(서버 ID는 기존 로그 규칙대로, 사용자 ID·채널 이름 없음).
- 알아 둘 점: 서버의 누구나 주시 채널을 추가·제거·전체 해제할 수 있게 된다. 막고 싶은 서버는 서버 설정 → 연동에서 역할별로 제한할 수 있다(채널 설정 문서에 적음). `!!요약좀` 텍스트 명령의 권한은 바뀌지 않는다.

## 4. 실제 모델 확인

밑줄은 코드가 붙이므로 프롬프트는 바꾸지 않는 것이 기본이다. 실제 출력에서 이름 감싸기가 맞는지 보려고 합성 사례로 **6건**(짧게 4 + 길게 2)을 비게시로 돌려 확인한다.
