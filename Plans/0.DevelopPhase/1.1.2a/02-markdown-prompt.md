# 1.1.2a-P2 — 마크다운·인용 비평·닉네임 밑줄 프롬프트

- 상태: **PLANNED** · 검사: `T112a-P2-A/B` · 환경: 개발 LXC, 합성 대역(모델 호출 없음)

## 선행 조건·작업

[P1](01-command-permission.md)의 원격 완료 뒤 [계약](CONTRACT.md) 2절대로 신뢰 프롬프트를 고친다.

- 형식 단락: 주제 소제목 `### 🚀 주제`, 길게·자세히 묶음 `### ✅ 결정 난 거`/`### ⏳ 진행 중인 거`, 핵심 숫자·시간·금액·결정 굵게, 원문에서 실제로 정정·철회된 안만 취소선, `###`보다 큰 제목·스포일러·링크 금지. 마크다운이 사실·결정 여부를 바꾸지 않는다는 문장.
- 닉네임: scope `speaker_names` 이름을 본문에 쓸 때마다 `__이름__`, 굵은 화자 불릿은 `**__이름__**`, 비평 줄·평가 줄에는 이름을 쓰지 않음.
- 주제 한줄 비평: 형식을 인용문 `> ↳ _비평_ 이모지`로 바꾸고(정확히 한 줄, 묶음 제외, 진행 중 조롱 금지 그대로), “`>`는 원문 인용 전용” 문장을 “원문 인용은 `> "원문"`처럼 따옴표를 붙이고, `> ↳`는 비평 줄 전용”으로 바꾼다.
- 짧게 형식 예와 추가 요청 단락(`이모지 빼고`·`비평 빼줘` 등)을 새 형식에 맞춘다. 떡밥 한줄 평가 머리말은 그대로.

프롬프트 버전을 `1.1.2a-p2-v1`로 올린다.

## 검증·완료 기준

- `T112a-P2-A`: 세 길이 × (일반·추가 요청·재시도) 프롬프트에 `### ` 소제목, `> ↳ _…_` 비평, `__이름__`·`**__이름__**`, 굵게·취소선 규칙, 금지 마크다운이 있고, 옛 `↳ *한줄 비평*`·굵은 줄 소제목 지시가 없다. 짧게 형식 예가 새 형식이고 실제 대화·평가 사례와 겹치지 않는 합성 이름이다.
- `T112a-P2-B`: 1순위 규칙·추가 요청 우선·진행 중 원칙·평가 줄·이모지 규칙 시험이 그대로(또는 새 문구로) 통과한다. 전체 회귀 통과.
