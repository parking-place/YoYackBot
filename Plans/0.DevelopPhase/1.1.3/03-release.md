# 1.1.3-P3 — 문서·통합·배포·출시

- 상태: **PLANNED** · 검사: `T113-P3-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1·P2](STATUS.md)의 원격 완료를 확인한다. 도움말 마지막에 [계약](CONTRACT.md)의 `/관리권한 설정` 한 줄을 더하고(2,000자 미만), `docs/channel-settings.md`에 판정 규칙·`/관리권한 설정`·연동 화면과의 관계·운영 명령을 적고, README·`CHANGELOG`·`docs/upgrade-rollback-1.1.3.md`(복귀 대상 `v1.1.2a`, wheel `1.1.2.1`, checkout `0e6db0c`, schema 5 유지 — 복귀하면 관리 역할 표는 무시되고 명령어가 다시 누구나 쓰는 상태가 됨)를 갱신한다. 패키지·`VERSION`을 `1.1.3`으로, 버전 대응표와 저장소 검증기에 1.1.3의 3단계·6검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 진행 중 요약이 없음을 확인하고 이전과 같은 절차로 배포한다. 이전 `v1.1.2a` wheel로의 복귀 호환성은 관리 역할 표가 있는 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 서버에서 확인한다: (1) 관리자 권한이 없고 관리 역할도 없는 계정은 `/채널 설정`이 거절됨, (2) 관리자가 `/관리권한 설정`으로 어떤 역할을 고르고 저장, (3) 그 역할의 계정이 `/채널 설정`을 열어 저장할 수 있음, (4) `!!요약좀 도움` 마지막 줄. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T113-P3-A`: 전체 회귀와 버전·문서 링크를 같은 SHA에서 확인한다.
- `T113-P3-B`: 후보·서비스 SHA 대조, 시험 Discord 사용자 확인과 서비스 로그(`manager_roles_saved`·`watched_channels_saved`) 대조, 배포·복귀·비밀정보 비노출·P1~P2 원격 증거, 병합 후 `main` CI를 기록한다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합한다. 태그 `v1.1.3`과 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
