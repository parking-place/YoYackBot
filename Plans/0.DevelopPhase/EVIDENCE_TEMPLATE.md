# 단계 검증 증거 양식

실행할 때 아래 양식을 `evidence/<version>-P<n>.md`로 복사한다. 계획 작성 시에는 실행 증거 파일을 만들거나 결과를 미리 채우지 않는다. 공개 가능한 합성 데이터와 익명화한 결과만 사용한다.

```markdown
# <version>-P<n> — <단계 이름>

- 상태: PUSH_PENDING
- 작업자 / 검증자:
- 검증 시각 및 시간대:
- 대상 브랜치:
- 구현 커밋 C 전체 SHA:
- 원격에서 확인한 증거 커밋 E SHA / URL: push 확인 후 후속 문서에서 기록
- 환경: 문서 검사 / LXC mock / LXC 실제 Discord / LXC 실제 Codex
- 런타임·SDK·CLI 버전 및 설정 식별자:
- 선행 단계와 원격 증거:
- 변경 내용과 산출물:

| 검사 ID | 입력·절차 | 기대 결과 | 실제 결과 | PASS/FAIL/NOT_RUN | 증거 |
|---|---|---|---|---|---|
| <TEST_MATRIX의 ID> | | | | NOT_RUN | |

- 실행한 명령 또는 재현 절차(비밀값 제외):
- 문서·소스 구조 검사와 제품 실행 검증의 구분:
- 실제 Discord/Codex 검증 여부와 계정 정보 제외 확인:
- 실패·제약·남은 문제:
- 원문·비밀정보·개인 식별값 제거 확인:
- git push 결과 / 확인 시각 / 원격 브랜치:
- 필수 CI 결과 / 해당 SHA / 또는 비대상 사유:
- 롤백 방법과 이전 정상 SHA:
- 다음 단계 진입 판정:
```

DONE은 [Git 완료 절차](GIT_WORKFLOW.md)의 마지막 원격 확인까지 충족해야 한다. 아직 하지 않은 검사는 NOT_RUN이다. 합성 입력 기반 PASS를 실제 Discord 또는 모델 PASS로 바꾸어 적지 않는다.
