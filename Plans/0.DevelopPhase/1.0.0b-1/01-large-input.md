# 1.0.0b-1 P1 — 대량 입력·모델 오류

상태: **IN_PROGRESS**. 검사: `B1A/B1B`. 1.0.0a 출시를 기준선으로 삼는다. [폐기된 1.0.0b P1 진단](../evidence/1.0.0b-P1.md)과 P2 후보 코드는 재검토할 입력이지 이 단계의 완료 증거가 아니다.

## 작업

운영의 원문 없는 집계에서 100건 초과 요청 6건 중 모델 오류 3건(선택 298/858/574건)과 모델 대기열 만료 3건(300/200/150건)을 구분한다. 이전 모델 오류의 세부 원인은 미확인이다. 합성 입력으로 CLI의 진단 출력 버퍼와 실제 요약 본문 한도를 분리한 후보를 같은 SHA에서 재검증한다. 필요하면 바이트/토큰 예산과 분할 요약을 명시적으로 설계하며, 일부만 처리한 결과를 전체 요약으로 게시하지 않는다.

## 통과 기준

- `B1A`: 101~1000건 합성 입력의 선택 건수·실제 포함 건수·입력 바이트·성공/실패 종류·실행 시간을 동일 SHA로 확인한다. 실제 과거 장애의 원인을 근거 없이 확정하지 않는다.
- `B1B`: 긴 본문, Unicode, 편집/삭제, 출력 과다와 입력 상한에서 누락·중복·시간순 붕괴가 없고 진단 로그에 원문·닉네임·ID·토큰이 없다.

개발 LXC에서 검증하고 [검증 목록](TEST_MATRIX.md)에 증거를 남긴다. **이 단계만의 구현 C → 증거 E → 종료 D를 각각 commit·GitHub push하고 원격 포함·필요 CI를 확인해야 DONE**이다. [Git 규칙](../GIT_WORKFLOW.md)을 따른다.
