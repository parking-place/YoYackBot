# 1.0.0b-1 P4 — 모델 대기열 시간 정책

상태: **PLANNED**. 검사: `B4A/B4B`. P3 원격 완료 후 개발 LXC에서 수행한다.

## 작업

`job_queue.py`의 모델 동시성 1, 대기 슬롯 4, 현재 60초 대기 정책을 실제 지연과 비교한다. 120초 모델 작업 뒤 정상 후속 요청이 단지 60초 대기 제한으로 만료되는 경우를 줄이되, 유한한 대기 상한과 명확한 만료 안내를 유지한다. 180초는 측정할 후보값이지 확정값이 아니다. 초기 수집의 대기/재시도와 모델 대기열을 분리하고 Discord rate limit 아래 여러 채널이 진행하도록 한다. 취소·종료·포화에서 슬롯을 반환한다.

## 통과 기준

- `B4A`: 120초 선행 작업과 후속 요청을 시간 제어 시험으로 재현해 기존 실패와 새 유한 정책의 성공/명시적 만료를 비교한다.
- `B4B`: 여러 채널·초기 수집·취소·서비스 종료·포화 상태에서 무한 대기나 모델 슬롯 누수가 없다. 초기 수집은 모델 슬롯을 점유하지 않는다.

개발 LXC에서 검증하고 [검증 목록](TEST_MATRIX.md)에 증거를 남긴다. **이 단계만의 구현 C → 증거 E → 종료 D를 각각 commit·GitHub push하고 원격 포함·필요 CI를 확인해야 DONE**이다. [Git 규칙](../GIT_WORKFLOW.md)을 따른다.
