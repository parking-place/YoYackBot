# 1.0.0b-1 P2 — 첫 주시 전체 수집과 실시간 DB 전환

상태: **PLANNED**. 검사: `B2A/B2B`. P1 원격 완료 후 개발 LXC에서 수행한다.

## 작업

관리자가 새 텍스트 채널을 주시 목록에 저장하면 그 시점 기준 최근 30일 안에서 봇이 조회할 수 있는 **과거 일반 사용자 메시지 전체**를 첫 수집 작업으로 가져온다. 채널 설정 저장은 긴 History 작업을 기다리지 않는다. 페이지 묶음마다 채널/주시 revision, 기준 시각, 30일 컷오프, 다음 커서, 수집 범위와 상태를 영속 저장하고 재시작 후 이어간다. 과거 페이지를 끝까지 읽거나 컷오프에 도달해도 즉시 COMPLETE로 바꾸지 않는다. 권한·네트워크·용량 한도·취소의 부분 결과는 별도 상태로 남긴다.

고부하 시험 채널의 읽기 전용 측정은 1시간 5페이지/2.1초, 1일 53페이지/55.5초, 7일 153페이지/160.2초, 조회 가능한 전체 207페이지/218.8초였다. 현재 요청별 30초·100페이지 상한을 첫 수집에 적용하지 않는다. 유한한 동시 수집/디스크 예산과 Discord rate limit을 지키되, 제한에 닿았다고 완료로 표시하지 않는다. 첫 수집 중에도 Gateway로 들어온 새 메시지는 즉시 DB에 저장하고 같은 메시지 ID의 과거 페이지와 중복 제거한다.

첫 수집을 시작할 때 채널의 시작 경계(시각과 Discord 메시지 snowflake)를 저장한다. 과거 페이지의 끝에 도달하면 완료 경계를 고정하고, **시작~완료 경계 사이의 History를 한 번 더 조회**해 그동안 올라온 메시지와 Gateway 누락을 확인한다. 이 겹침 구간은 메시지 ID upsert로 중복 제거한다. 경계의 포함/제외 규칙을 고정해 시작·완료 순간의 메시지도 빠뜨리지 않는다. 재확인 작업 역시 페이지별 커서를 저장·재개하고, 범위 전체를 확인한 뒤에만 COMPLETE로 바꾼다. 그 뒤의 메시지는 이미 켜진 실시간 경로가 계속 저장한다. 재확인 실패·권한 부족이면 PARTIAL 상태로 남기고 준비 완료 안내를 보내지 않는다.

**첫 수집 완료 뒤 수집의 기본 경로는 Gateway→DB다. 요약의 기본 경로는 DB→모델이다.** 일반 요약 요청에서 Discord History API를 호출하는 기존 보충 경로를 제거/차단하고 DB의 보유 범위만 선택한다. 재접속·Gateway 누락이 감지되면 요약 요청과 무관한 별도 복구 작업이 누락 구간만 History로 확인한다. 복구가 끝나기 전 범위를 완전하다고 표시하지 않는다. 30일이 지난 캐시는 정기 정리한다. 업그레이드 전에 이미 주시하던 채널도 한 번 전체 수집해 전환한다. 이 이관은 신규 첫 주시와 구분하고, 전체 수집이 끝나지 않은 범위의 요약을 완전한 결과로 내지 않는다. DB 스키마는 1.0.0a로 롤백 가능한 방식으로 확장한다.

## 통과 기준

- `B2A`: 200페이지 초과 합성 History와 실제 시험 채널에서 컷오프까지 조회 가능한 기록 전체가 누락/중복 없이 저장된다. 시작~완료 사이 메시지를 재조회하고 실시간 저장분과 중복 제거하며, 시작/완료 경계의 메시지와 후속 실시간 메시지도 빠짐없이 저장한다. 봇·웹훅·명령 및 30일 밖의 메시지는 제외한다.
- `B2B`: 정상 요약은 DB만 읽고 History API를 호출하지 않는다. 재확인 중 재시작·429·연결 누락·권한 변경·주시 재등록·30일 정리에서는 별도 복구 작업의 커서·범위·상태가 정확하다. 재확인이 끝나지 않으면 COMPLETE가 아니다. Discord에서 이미 삭제되거나 접근 불가한 기록까지 수집했다고 주장하지 않는다.
