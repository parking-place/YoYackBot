# 1.0.2b-P3 — 통합·배포·출시

- 상태: **IN_PROGRESS** · 검사: `T102b-P3-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P2](STATUS.md)의 원격 완료를 확인한다. 패키지·`VERSION`을 `1.0.2.1`로, 저장소 검증기에 1.0.2b의 3단계·6검사 집계를 넣는다. `CHANGELOG`·README·`docs/upgrade-rollback-1.0.2b.md`(복귀 대상 `v1.0.2`, schema 변경 없음)를 갱신한다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤 1.0.2와 같은 절차(DB 온라인 백업·설정 백업·wheel 설치·checkout 일치·`check-ready`·health·DB 무결성)로 개발 LXC 서비스에 배포한다. 이전 `v1.0.2` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 서버에서 직접 확인한다: 주시 채널의 `!!요약좀 채널`(목록), 미주시 채널의 `!!요약좀 채널`(미주시 안내만), `!!요약좀 도움`의 새 줄. 가능하면 권한이 다른 계정으로 비공개 주시 채널이 목록에서 빠지는지도 본다. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T102b-P3-A`: 전체 회귀(요약 범위·모드·사용량·상태·시작/진행 중 안내·준비 상태·쿨타임)와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T102b-P3-B`: 후보 SHA와 서비스 SHA를 대조하고, 시험 Discord 결과를 사용자 확인과 서비스 로그(`channel_list_request`)로 대조하며, 배포·복귀·비밀정보 비노출·P1~P2 원격 증거를 기록한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합하고 **병합 후 `main` CI 결과**를 확인해 기록한다. 태그 `v1.0.2b`와 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
