# 1.0.2b — 주시 채널 목록 명령

- 상태: **IN_PROGRESS** (P1 완료, P2 진행 중)
- 단계 수: **3단계**
- 선행 버전: 출시된 [1.0.2](../1.0.2/README.md)(`v1.0.2`, 2026-09-29)

## 목표

`!!요약좀 채널`로 현재 서버에서 봇이 주시 중인 채널을 알려준다. `!!요약좀 도움`에 새 명령을 추가한다.

```text
!!요약좀 채널
지금 본인이 보고 있는 채널을 알려주겠소
 - 잡담
 - 개발
 - 기획
이상이오.
```

응답 위치·권한 필터·빈 목록·분할·로그 등 세부 규칙은 [명령 계약](COMMAND_CONTRACT.md)에 있다. 사용자 결정(2026-09-30)에 따라 **주시 채널에서만** 답하고, 명령한 사람이 볼 수 있는 채널의 **이름만** 적는다.

## 단계

| 순서 | 단계 | 검증 ID | 상태 |
|---|---|---|---|
| 1 | [P1 — 명령 라우팅·현재 서버 주시 채널 조회](01-channel-list.md) | `T102b-P1-A/B` | DONE |
| 2 | [P2 — 응답 문구·분할·도움말](02-reply-help.md) | `T102b-P2-A/B` | IN_PROGRESS |
| 3 | [P3 — 통합·배포·출시](03-release.md) | `T102b-P3-A/B` | PLANNED |

[검증 목록](TEST_MATRIX.md)은 현재 전부 `NOT_RUN`이며 [상태](STATUS.md)는 전부 `PLANNED`이다. 각 단계는 구현·LXC 검증·증거 기록·**독립 commit → GitHub push → 원격 반영 및 필요한 CI 확인**을 마쳐야 DONE이다. 기존 [Git 완료 규칙](../GIT_WORKFLOW.md)의 C/E/D 절차를 따르며, 종료 커밋 D는 증거 커밋 E의 **CI 성공을 확인한 뒤에만** 만든다.

## 검증 방침

- 모델·요약 경로를 쓰지 않으므로 실제 모델 평가는 없다(봇 계정 한도 사용 0).
- 실제 시험 Discord 확인은 P3 배포 뒤 사용자가 직접 입력한다. 확인하지 못하면 `NOT_RUN`으로 남긴다.
- 시간에 따라 결과가 바뀌는 시험은 고정 시계를 주입한다(1.0.2-P4 재개 교훈).
- 8시간·24시간 연속 시험은 필수 게이트가 아니다. 태그·Release는 배포 코드가 최종 게이트를 통과한 뒤에만 만든다.

버전 표기는 [버전 대응표](../PATCH_VERSIONING.md)대로 계획·태그 `1.0.2b` / `v1.0.2b`, Python 패키지 `1.0.2.1`이다.
