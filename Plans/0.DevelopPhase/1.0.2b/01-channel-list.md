# 1.0.2b-P1 — 명령 라우팅·현재 서버 주시 채널 조회

- 상태: **DONE** · 검사: `T102b-P1-A/B` · 환경: 개발 LXC, 합성 Discord 객체·격리 DB

## 선행 조건·작업

`v1.0.2` 출시와 `main` 통합을 확인한다. [명령 계약](COMMAND_CONTRACT.md)에 따라 옵션이 정확히 `채널`일 때 새 경로(`RouteKind.CHANNELS`)로 보낸다. `도움` 우선순위와 `사용량`·`상태`·요약 옵션 해석은 그대로 둔다.

현재 서버의 주시 설정(`WatchStore.snapshot`)을 읽고, Discord 캐시에서 텍스트 채널만 골라 **명령한 사람이 볼 수 있는 채널**만 남긴 뒤 Discord 채널 목록 순서로 정렬하는 순수 함수를 만든다. `사용량`·`상태`와 같은 주시 게이트를 거쳐 **주시 채널에서만** 응답하고, 미주시 채널에는 기존 미주시 안내를 보낸다. 주시 설정을 읽지 못하면 기존 설정 확인 실패 안내를 보낸다. 이 경로는 메시지 캐시·요약 대기열·진행 중 상태·쿨타임을 건드리지 않는다.

## 검증·완료 기준

- `T102b-P1-A`: 라우팅(`채널`, 앞뒤 공백, `채널 도움`→도움, `채널 부탁하오`·`3시간 채널`·`채널좀`→요약 옵션 해석), 두 서버 격리, 사라진 채널·비텍스트 채널 제외, 권한 없는 비공개 채널 제외, 채널 순서가 결정적이다.
- `T102b-P1-B`: 주시 채널에서만 목록을 보내고 미주시 채널은 미주시 안내만(목록 조회 0회) 받으며, 설정 DB 오류는 추측 없이 실패 안내, 요약 진행 중에도 즉시 처리되며 워크플로·모델·쿨타임 호출이 0회다. 로그에 채널 이름·ID가 없다.
