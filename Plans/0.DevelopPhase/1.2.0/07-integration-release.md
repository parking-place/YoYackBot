# 1.2.0-P7 — 통합·복귀·출시

- 상태: **PLANNED** · 검사: `T120-P7-A`~`D`
- 환경: 개발 LXC·격리 복귀 DB·GitHub CI·시험 Discord의 사용자 확인
- 선행: [P1~P6](STATUS.md) 원격 완료, 14개 결함과 F02/F10의 검증 증거

## 작업

1. 신규 기능이 F02/F10만인지 최종 대조한다. `/말투`·답장 범위·평가 후보·심사·최근 평가 기억이 유입되지 않았는지 검사한다. [범위 추적표](SCOPE_MAP.md)의 16개 항목을 빠짐없이 닫는다.
2. `VERSION`, 패키지, 운영 표시를 `1.2.0`으로 올리고 README·CHANGELOG·관련 운영 문서·`docs/upgrade-rollback-1.2.0.md`를 갱신한다. `scripts/verify_repo.py`에 새 1.2.0의 7단계·28검사와 후속 1.3.0의 6단계·12검사를 반영한다. 이 변경은 계획 작성 때가 아니라 이 구현 단계에서 한다.
3. 목록 DM 전달·현재 채널 상태·답글 관계의 사용자 설명을 갱신한다. 1.3.0의 도움말 불변 결정은 이후 1.2.0에서 출시한 도움말을 기준으로 적용한다.
4. 정확한 후보 SHA의 wheel·의존성·CLI·스키마·설정 백업을 기록한다. `v1.1.3a` / wheel `1.1.3.1`의 실제 복귀 코드 SHA를 기존 [출시 증거](../evidence/1.1.3a-P3.md)와 대조해 고정한다.
5. 격리 DB에서 1.1.3a → 1.2.0 → 1.1.3a → 1.2.0을 검증한다. 선택 테이블이 있는 상태에서 구버전 편집·삭제·retention·주시 해제·서버 탈퇴를 실행한 뒤 고아 참조·삭제 데이터 부활이 없는지 본다. 설정 백업에는 F02/F10 캐시 데이터가 없어야 한다.
6. 후보 CI와 LXC 검증이 성공하면 진행 중 작업을 정리하고 기존 절차로 배포한다. 실제 Discord 확인은 배포 후 사용자가 수행한다. 확인 항목·대상 SHA·서비스 로그를 대조하고 확인하지 못한 결과는 NOT_RUN으로 남긴다.

## 검사와 인수

- `T120-P7-A`: 같은 후보 SHA에서 Ruff·전체 pytest·문서/비밀정보 검사와 새 단계 집계가 통과한다. B01~B14/F02/F10의 실제 현행 workflow 통합 회귀와 호출 상한·기본 동작을 확인한다.
- `T120-P7-B`: 위 업그레이드/복귀/재업그레이드·설정 백업/복원과 깨끗한 설치를 검증한다. 상대/절대 CLI 경로의 준비·실행 판정도 대조한다.
- `T120-P7-C`: 시험 Discord에서 공개/비공개 목록의 개인 전달·DM 실패 fallback, 역할 저장, F02 최초/차단/완료 상태, F10 질문·답변 요약, 기존 명령을 사용자가 확인한다. 비공개 원문/이름을 공개 증거로 옮기지 않는다. 실환경 미확인 항목을 합성 PASS로 대체하지 않는다.
- `T120-P7-D`: 후보·설치 코드/패키지·서비스 SHA, P1~P6 C/E/D, PR 리뷰·main 병합 후 CI, 제품 태그/Release가 같은 검증 이력을 가리키는지 확인한다. 계획 브랜치의 문서 게시를 출시 증거로 사용하지 않는다.

## 종료와 다음 버전

마지막 단계는 출시 전 품질 검증과 출시 후 이력 확인을 분리한다. `T120-P7-D`는 사후 확인이며 태그 생성의 선행 조건으로 사용하지 않는다.

1. P1~P6 원격 완료, 후보 SHA의 `T120-P7-A/B/C`와 후보 CI 성공을 확인한다. 구현 C와 사전 증거 `E_pre`를 push하고 원격·CI를 확인한다. P7 상태는 PUSH_PENDING으로 유지한다.
2. main으로 PR·리뷰·병합하고 main CI를 확인한다. 검증·배포 코드와 통합 코드가 일치하는지 대조한다. 코드가 바뀌었다면 해당 검증을 다시 한다.
3. 위 출시 전 게이트가 모두 통과한 코드에만 태그 `v1.2.0`과 Release를 만든다. 이어 `T120-P7-D`의 태그·서비스·패키지·이력 일치를 확인한다.
4. 사후 검사까지 담은 최종 증거 E를 main에 반영하고 CI 성공을 확인한 뒤, STATUS에 DONE을 기록하는 종료 D를 반영한다. D의 원격 반영·필요 CI 확인 후 P7 완료를 보고한다.

각 기록은 공통 [Git 규칙](../GIT_WORKFLOW.md)을 따르며 보호 규칙을 우회하지 않는다. 미검증 품질 게이트가 남으면 태그·출시를 진행하지 않고, 사후 검사가 미확인인 상태에서는 P7을 DONE으로 바꾸지 않는다.

1.3.0 착수 시 이번에 출시한 정확한 태그·wheel·SHA를 그 버전의 선행·복귀 기준으로 기록한다. 1.3.0을 과거 `v1.1.3a`에서 바로 구현하지 않는다.
