# 기존 1.2.0 → 1.3.0 이동과 새 1.2.0 이력

2026-10-02 사용자 요청에 따라 **기존 계획을 먼저 머지하고, 이동 커밋을 만든 뒤 새 계획을 추가**한다. 내용을 덮어쓴 채 옛 계획 브랜치가 미병합 상태로 남는 상황을 피하기 위한 순서다.

이동 커밋은 문서 버전·검사 ID를 `1.3.0`·`T130`으로 바꾸고, 선행/복귀 기준을 새 1.2.0으로 연결했다. 기존 6단계·12검사, 말투·답장·평가 방식과 사용자 결정은 보존했다. 새 1.2.0은 별도 추가 커밋으로 작성하며 7단계·28검사, B01~B14·F02·F10만 포함한다.

```text
                    ↑                                 new-1.2.0
        기존 계획 최종 c512cd8 포함
```

## 이후 병합 규칙

1. 새 계획 PR은 `new-1.2.0 → main`으로 검토한다. 이동 커밋과 새 계획 추가 커밋을 분리해 검토할 수 있다. 이 문서 작성 시 이동·추가 커밋의 main 원격 통합은 새 계획 PR에서 이뤄질 후속 작업이다.
2. 기존 `c512cd8`은 이미 main과 새 브랜치의 조상이다. 기존 계획의 문서들을 다시 복사하거나 cherry-pick하지 않는다. 옛 브랜치에서 새 1.2.0 작업을 계속하지 않는다.
3. 후속 1.2.0 구현은 새 계획이 통합된 최신 main에서 `develop/1.2.0`으로 시작한다. 1.3.0 구현은 1.2.0 출시·main 통합 이후 시작한다.
4. 1.3.0은 1.2.0의 캐시·권한·출력 검증과 F02/F10을 유지한다. F10 답글 관계와 1.3.0 답장 범위의 책임을 섞지 않는다.
5. 미래 동시 수정의 충돌까지 없다고 보장하지 않는다. 최종 병합 때 최신 main을 다시 확인하고 문서 ID·범위·선행·복귀 기준을 재검사한다. 원격 브랜치 강제 push나 옛 계획 삭제로 충돌을 덮지 않는다.

## 검증과 보존

- 기존 계획의 마지막 CI 성공과 PR merge를 확인하고, `c512cd8`이 main 병합 커밋의 조상임을 검사했다.
- 기존 `.claude/`와 감사 문서는 전환 전에 이름 있는 로컬 stash로 보존한 뒤 내용 해시가 같은 상태로 복원했다. `.claude/`는 공개 커밋에서 제외한다.
- 감사 원문은 현재 사용자 작업 위치인 `Plans/1.Improvements/`에 보존한다. 당시 문서의 1.2.0 언급은 역사적 기준이며 이번 이동 후 제품 계획과 혼동하지 않는다.
- `src`, `tests`, `scripts`, 패키지·VERSION·lock·배포·CI 파일은 새 계획 기준 main과 동일하게 유지한다. 로컬의 오래된 main을 최신 원격으로 fast-forward하며 이미 출시된 코드가 반영된 것은 이번 기능 구현이 아니다.
- 저장소의 기존 `scripts/verify_repo.py`는 통과했다. 이 검증기는 아직 1.2.0/1.3.0 집계를 다루지 않으므로 별도 문서 검사로 7단계·28검사와 6단계·12검사, PLANNED/NOT_RUN, 링크·코드 블록, B01~B14/F02/F10 대응을 확인했다. 기존 사용자 결정 표 8건은 원본과 일치한다. 검증기 코드는 이번 작업에서 수정하지 않았다.
- 제품 단계는 PLANNED/NOT_RUN이다. 이번 문서·Git 이력 검증은 1.2.0/1.3.0 제품 개발·배포 완료로 계산하지 않는다.
