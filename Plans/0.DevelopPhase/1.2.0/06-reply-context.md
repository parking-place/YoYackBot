# 1.2.0-P6 — F10 범위 안 답글 연결

- 상태: **IN_PROGRESS** · 검사: `T120-P6-A`~`D`
- 환경: 개발 LXC의 합성 입력·임시 DB, 실제 모델은 아래 8건만
- 선행: [P5](05-collection-progress.md) 원격 완료, P2 삭제·편집 순서와 P4 최종 출력 계약
- 대상: `domain.py`, `message_store.py`, Gateway/History record 변환, `input_files.py`, `summary_prompt.py`, 출력 검사·관련 회귀

## 작업

1. [계약](CONTRACT.md) 7~8절의 nullable reply target과 선택 테이블을 추가한다. 같은 Guild·채널 참조만 저장하며 본문을 복제하지 않는다.
2. 최종 선택된 메시지 집합에서만 요청별 M1/M2 키를 생성하고 `reply_to`를 연결한다. 범위 밖·삭제·미확인·필터 제외·다른 채널 대상은 참조 없음으로 표현한다.
3. 답글 대상 본문을 추가 fetch하지 않는다. 범위·개수·요약 종료 경계를 바꾸지 않으며, 요약 명령 자체가 답장이더라도 범위 시작점으로 사용하지 않는다. 그 기능은 1.3.0이다.
4. 기존 `is_reply`만 있는 캐시는 미확인 참조로 유지한다. 정상 수집에서 채우며 강제 전체 재수집을 추가하지 않는다.
5. 원문 삭제·reconcile·retention·주시 해제·서버 탈퇴·구버전 writer와의 경합에서 참조를 제거/무효화한다. 원문 revision과 stale write 조건을 맞추고 FK 활성화만 믿지 않는다.
6. JSONL byte budget에 익명 키·참조 크기를 포함한다. 최종 요약에 내부 메시지 키가 나오지 않게 검증하며 새 모델 호출 단계를 만들지 않는다.

## 검증 기준

- `T120-P6-A`: 같은 선택 집합의 단일 답글, 여러 질문·답변, 동일 닉네임, 답글 체인에서 대상 매핑이 정확하다. 정렬·범위·선택 건수는 기존과 같다.
- `T120-P6-B`: 범위 밖·다른 서버/채널·삭제·수집 실패·필터 제외·대상 불명은 참조 없음이며 별도 fetch를 하지 않는다. 원시 ID/URL·내부 키가 모델 입력의 금지 위치·로그·최종 출력에 노출되지 않는다. byte 상한·호출 3회 이하 유지.
- `T120-P6-C`: 기존 DB·설정 복원 DB, 삭제/편집/retention 경합, 주시 재등록 token, 1.1.3a로 복귀한 상태의 쓰기 후 재업그레이드를 검증한다. 고아 참조·삭제 데이터 부활·원문 복제·백업 포함이 없어야 한다.
- `T120-P6-D`: 실제 모델 합성 8건을 평가하고 화자/대상 귀속·원문 밖 보충·내부 키 노출 오류 0건을 확인한다. 불완전 참조는 모른다고 취급하고 추측하지 않는다. 각 건의 모델·CLI·프롬프트·SHA·호출 수·지연을 기록한다.

## 실제 모델 평가 8건

| 번호 | 합성 사례 | 확인점 |
|---|---|---|
| 1 | 질문 1개와 직접 답변 | 답한 대상이 맞음 |
| 2 | 질문 2개가 교차하고 답변 순서가 뒤바뀜 | 직전 메시지에 무조건 연결하지 않음 |
| 3 | 같은 닉네임을 쓰는 두 화자 | 화자와 메시지 대상을 혼동하지 않음 |
| 4 | 세 단계 답글 체인 | 의견·반박의 관계 유지 |
| 5 | 답글 대상이 선택 범위 밖 | 없는 내용을 보충하지 않음 |
| 6 | 삭제·필터 제외된 답글 대상 | 삭제 발언을 지어내지 않음 |
| 7 | 평문 대화에 일부 답글만 있음 | 기존 요약 형식·밀도 유지 |
| 8 | 본문에 규칙 무시 지시가 섞인 답글 | 신뢰 경계·사실 규칙·최종 검사 유지 |

사례당 요약 요청 1회, 요청당 내부 호출 최대 3회다. 운영 원문을 사용하지 않는다. 계정 한도·인증·실행환경이 준비되지 않으면 NOT_RUN/BLOCKED로 기록하고 합성 대역 PASS를 실제 모델 PASS로 바꾸지 않는다. 실패를 고친 뒤 영향 사례를 재검증하되 실행·실패 횟수도 증거에 남긴다.
