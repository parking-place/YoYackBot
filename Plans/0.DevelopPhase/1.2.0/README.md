# 1.2.0 — 버그 수정·수집 진행 상태·범위 안 답글 연결

- 상태: **IN_PROGRESS** · 계획 **7단계 / 구현 완료 2단계**
- 선행 제품: [1.1.3a](../1.1.3a/STATUS.md), 패키지 `1.1.3.1`
- 계획 브랜치: `new-1.2.0` · 후속 구현 브랜치: `develop/1.2.0`
- 근거: [Improvements 감사](../../1.Improvements/README.md), [범위 추적표](SCOPE_MAP.md)

## 확정 범위

1. Improvements의 **B01~B14 버그를 모두 수정**한다. 감사의 합성 재현 결과는 수정 PASS가 아니므로 새 구현 SHA에서 회귀 검증한다.
2. 신규 기능은 **F02 수집 진행·차단 원인**과 **F10 범위 안 답글 연결**만 추가한다.
3. 기존 1.2.0의 `/말투`·답장으로 요약 범위 지정·평가 다양화는 [1.3.0](../1.3.0/README.md)으로 이동했다. 기능과 기존 사용자 결정은 그 버전에 유지한다.

F10은 이미 선택된 대화 안에서 질문과 답변 관계를 전달하는 기능이다. **요약 명령의 답장 대상을 범위 시작점으로 사용하는 1.3.0 기능과 다르다.** F01·F03~F09, 새 운영 대시보드, 자동 알림, 사용량 제한 확대는 이번 기능 범위가 아니다. B01의 기존 채널 목록 전달 안전성 수정은 버그 수정에 필요한 최소 변경이다.

## 실행과 완료 기준

- P1~P6은 순서대로 수행하고 각 단계의 **구현 C → LXC 검증·증거 E → E CI 성공 → 종료 D → 원격 확인**을 마친다. 공통 [Git 완료 규칙](../GIT_WORKFLOW.md)을 따른다.
- 현재 계획 게시·문서 검사로 제품 시험을 PASS로 바꾸지 않는다. 실행 결과와 미실행 항목은 STATUS 및 TEST_MATRIX에서 구분한다.
- 실제 모델 평가는 P6의 합성 품질 사례 8건으로 한정한다. 이는 요약 요청 8건이며 각 요청의 내부 호출 상한은 3회다. 실패 수정 후 재검증 횟수는 별도로 기록한다. 그 이전 검증은 대역을 사용한다. 시험 Discord 조작은 P7 배포 뒤 사용자가 확인하고 결과·로그를 대조한다. 미확인 항목은 NOT_RUN이다.
- P7에서만 패키지·`VERSION`을 `1.2.0`으로 올리고 태그 `v1.2.0`을 검토한다. 버전 번호 변경과 출시 판정은 P7에서 수행한다.
- 1.3.0은 새 1.2.0이 출시·main 통합된 뒤 착수한다. 1.2.0의 캐시·출력 검증·선택 테이블 계약을 유지한 상태에서 후속 기능을 추가한다.
