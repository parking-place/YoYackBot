# 1.2.0 `/말투`·답장 범위·떡밥 한줄 평가 다양화 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 출시된 `v1.1.3a`(2026-10-01) 코드를 기준으로 작성했다.

## 1. `/말투` — 서버별 말투 프롬프트

### 요청
관리자·봇 관리 역할이 쓰는 `/말투` 명령. 지금 쓰는 프롬프트가 미리 채워져 보이고, 고쳐서 저장하면 그 서버의 요약에 적용된다.

### 범위
- 고칠 수 있는 것은 신뢰 프롬프트의 **“말투(기본)” 단락**이다(지금 약 450자: 거칠고 띠꺼운 하오체, 비꼼 대상, 비속어 예). 처음 열면 이 기본 단락이 그대로 채워져 있다.
- **고칠 수 없는 것**(사용자 결정 기본안): 신뢰 경계, 사실·화자 귀속, 지어낸 말 금지, 결정·진행 중 원칙, 금지선(집단 비하·인신공격·성적 묘사), 형식·평가 줄 규칙. 서버 말투는 이 규칙들 **아래**에 들어가고, “금지(말투·추가 요청보다 우선)” 단락이 말투보다 먼저라는 순서를 지킨다. 그래서 말투에 “비하어 써도 된다”, “규칙 무시” 같은 말이 있어도 금지선은 바뀌지 않는다.
- 추가 요청(1.1.1)은 서버 말투보다도 먼저 적용된다(예: 서버 말투가 점잖아도 요청자가 `욕 빼고`·`표로` 등을 고를 수 있음).

### 화면 흐름
1. `/말투` → 본인에게만 보이는 메시지: 지금 적용 중인 말투(기본값이면 “기본 말투”, 바꿨으면 “이 서버 말투”)와 그 내용, 버튼 **수정**·**기본값으로**·**닫기**.
2. **수정** → Discord 입력 창(모달)에 지금 내용이 채워진 채 열림(여러 줄, 최대 1,500자). 제출하면 검사 뒤 저장하고 “💾✅ 말투를 저장했소.”와 바뀐 내용을 보여 준다.
3. **기본값으로** → 서버 말투를 지우고 기본 단락으로 돌아간다.
- 연 사람만 조작, 조작마다 권한 재확인(1.1.3 판정), 120초 제한, 동시 수정 감지.

### 저장 검사
- 1,500자 이하, 멘션·제어 문자 제거, 빈 내용 거절.
- 지시문을 깨려는 표현(규칙·지시문 무시/공개, 범위·채널 변경, 파일·URL·도구, 인용 탈출 기호, 비하어·성적 묘사 허용)이 있으면 **저장 거절**하고 이유를 알려 준다(1.1.1 위험 요청 판정 재사용). 거절되지 않은 내용이라도 1순위 규칙은 프롬프트 순서로 지켜진다.
- 저장소: 기존 SQLite의 선택 테이블(서버별 내용·버전·시각), schema 5 유지, 설정 백업 포함, 서버 나감 때 삭제.
- 로그: `tone_saved at=<UTC> chars=<글자 수>` / `tone_reset at=<UTC>`. **말투 내용은 로그에 남기지 않는다.** 요약 지표에 `tone=default/custom`.

## 2. 답장으로 범위 지정

- 어떤 메시지에 **답장으로** `!!요약좀 …`을 쓰면 **그 메시지부터 지금까지**를 요약한다(그 메시지 포함). 길이(`길게`·`자세히`)와 추가 요청은 그대로 함께 쓸 수 있다.
- 답장과 범위 옵션(`3시간`·`100개` 등)을 함께 쓰면 **답장이 정하고 범위 옵션은 거절 안내**(사용자 결정 기본안): “🤔 답장으로 범위를 정할 때는 기간·개수를 함께 쓰지 마시오.”
- 같은 채널의 메시지에만 답장 범위를 허용한다. 답장 대상이 최대 기간(설정, 기본 30일)보다 오래됐거나, 그 뒤 메시지가 최대 개수(설정, 기본 1,000)보다 많으면 안내하고 요약하지 않는다. 대상 메시지를 찾을 수 없으면(삭제 등) 안내한다.
- 시작·진행 중 안내 문구: `📝 답장한 메시지부터 채팅을 요약해보겠소. ✍️` / `⏳ 현재 답장한 메시지부터 채팅을 요약중이오. 🔄`. 요약 머리말은 지금처럼 실제 시작 시각을 쓴다.
- 기존 시간 범위 수집(캐시·기록 조회)을 그대로 쓰고 시작 시각만 대상 메시지 시각으로 정한다. 쿨타임·대기열·진행 중 안내·준비 상태 규칙은 그대로다.

## 3. 떡밥 한줄 평가 다양화

### 문제
마지막 떡밥 한줄 평가가 거의 같은 내용으로만 나온다: “화제가 이리저리 튄다/왔다갔다 한다/정신없다/부산하다/요란하다/한 상 가득”. 1.1.2·1.1.2a 실제 평가 출력에서도 대부분이 이 틀이었다.

### 방식
1. **금지 소재**: 화제 전환·뒤죽박죽·정신없음·부산함·요란함·“한 상 가득”류를 평가 소재로 쓰지 않는다(1.1.1a의 결론 없음·미룸 금지도 유지). 프롬프트에 적고, 코드도 금지 표현 목록으로 후보를 거른다(예: `튀`, `왔다갔다`, `오락가락`, `정신없`, `부산`, `요란`, `한 상`, `뒤엉`, `이리저리`).
2. **후보 10개를 한 번에 생성**: 요약이 끝난 뒤 평가 전용 호출 1번으로 서로 다른 각도의 후보 10줄을 만든다(대화의 고유한 떡밥·말버릇·헛짚음·호들갑·뻔한 결론 등에서 각자 다른 소재). 금지 소재·이름·숫자·형식 위반·비하어·미결 조롱이 있는 후보는 코드가 버린다.
3. **luna가 심사해 1개 선택**: 남은 후보를 평가 심사 호출 1번(같은 `gpt-6-luna`)에 주고 기준(신랄함·이 대화에만 맞는 구체성·금지 소재 없음·하오체·새로움)으로 **번호 하나**만 고르게 한다. 코드는 답이 번호 하나인지 확인하고 그 후보를 붙인다.
4. 요약 본문이 쓴 평가 줄은 버리고 고른 후보로 바꾼다. `평가 빼줘`면 후보·심사 호출을 하지 않는다.

### 실패 대체
- 후보 호출 실패·유효 후보 0개 → 요약 본문의 평가 줄(금지 소재가 없을 때) → 없으면 평가 없이 게시.
- 심사 호출 실패·잘못된 답 → 남은 후보 중 첫 번째.
- 지표: `rating=picked/fallback_summary/fallback_first/missing/skipped`, `rating_candidates=<유효 후보 수>`. 후보·평가 문장은 로그에 남기지 않는다.

### 호출 수
- 요약 한 건의 모델 호출 상한을 **3번 → 4번**으로 올린다: 요약 1 + (문제 시 전체 재생성 1) + 후보 1 + 심사 1. 1.1.0a의 “평가 줄만 다시 만들기”는 후보 생성이 대신한다. 요약 대기 시간이 후보·심사 시간만큼 늘어난다(실제 평가에서 측정).

### 평가 줄 규칙 변경
- 지금은 평가 줄에 시간·숫자·담당자·결정·사람 이름을 쓰지 말라고 한다. 이름·숫자 금지는 유지하되, **그 대화의 떡밥 주제어는 짚어도 된다**(예: “라면 국물 하나로 철학 토론을 벌였구려”)로 바꿔 구체성을 허용한다(사용자 결정 기본안).
- 평가 예(합성): “📚 공부하자던 방이 어느새 야식 품평회가 되었구려 🍜”, “🔧 고장 원인은 못 찾고 서로 손가락질만 잘하는 꼴이오 👉”, “🎤 노래 고르는 데 쓴 시간이면 앨범 하나 냈겠소 💿”.

## 4. 도움말

- 1.1.3 도움말(사용자 문안 + `/관리권한 설정` 줄)에 두 줄을 더한다(사용자 결정 기본안): “↩️ 메시지에 답장으로 `!!요약좀`을 쓰면 그 메시지부터 요약하오.”, “🎭 말투는 `/말투`에서 바꾸시오.”(2,000자 미만).
