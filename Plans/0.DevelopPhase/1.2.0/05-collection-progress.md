- 선행: [P4](04-output-runtime.md)까지 원격 완료, 특히 P2의 검증 경계와 P3의 worker 복구
- 대상: `backfill.py`, `watch_store.py`, `status_report.py`, `discord.py`, 관련 상태·백필 회귀

## 작업

1. [계약](CONTRACT.md) 6절의 현재 채널 상태를 기존 `!!요약좀 상태`와 미완료 안내에 붙인다. 새로운 명령·다른 채널 목록·운영 대시보드를 추가하지 않는다.
2. 최초 History, 재접속/기존 행 대조, retry, blocked, 준비 안내 대기, 요약 가능의 판정을 코드의 실제 상태와 연결한다. B03/B04의 공백이 남거나 준비 안내가 실패하면 완료로 표시하지 않는다.
3. `backfill_progress` 선택 테이블의 token·작업 회차·성공 페이지 수·최근 진척을 페이지/cursor와 원자적으로 commit한다. 실패·stale token·재시도에서 중복 증가하지 않게 한다.
4. 현재 저장 메시지 수와 처리 누계를 구분한다. 이전 버전에서 수집한 누계·조회 실패는 확인 불가로 표시한다. 차단 이유는 고정 분류로 제한한다.
5. 주시 해제·채널 삭제·서버 탈퇴 시 정리하고 설정 백업에서 제외한다. 추가 조회가 전체 원문을 읽거나 History/모델 호출을 유발하지 않게 한다.

## 검증 기준

- `T120-P5-A`: 모든 phase·재시도·차단·준비 안내 실패·worker 종료에서 문구와 요약 가능 여부가 실제 상태와 같다. 공백이 남은 ready와 실제 요약 가능을 구분한다.
- `T120-P5-B`: 페이지 commit 실패·같은 페이지 재시도·오래된 token·동시 live 메시지·재시작·새 공백 회차에서 카운터·시각이 일관된다. 성공하지 않은 페이지는 증가하지 않는다.
- `T120-P5-C`: 다른 채널의 이름·ID·상태·숨은 채널 수, 원문·실제 예외·DB 경로가 응답/로그에 추가되지 않는다. 퍼센트·ETA를 추측하지 않는다. 조회 실패는 0으로 위장하지 않는다.
- `T120-P5-D`: 선택 테이블 없는 기존 DB의 업그레이드, 백업 제외, 해제·탈퇴 정리, 1.1.3a 복귀 뒤 변경·재업그레이드의 안전성을 격리 DB에서 확인한다. 전체 회귀 통과.
