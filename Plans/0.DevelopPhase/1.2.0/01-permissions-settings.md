## 대상 모듈과 작업

| 대상 | 작업 |
|---|---|
| `channel_list.py`, `discord.py` | 기존 `!!요약좀 채널` 목록을 요청자 DM으로 전달한다. 요청자의 현재 Guild 소속·주시 설정·열람권한을 조각마다 재확인한다. 공개 채널에는 성공 또는 DM 실패의 일반 안내만 보낸다. |
| `manager_roles.py`, `discord.py` | 역할 삭제 이벤트가 오래된 전체 집합을 다시 쓰지 않도록 대상 역할 삭제와 revision 증가를 원자화한다. CAS를 쓴다면 충돌 시 최신 집합에서 다시 삭제한다. |
| `channel_config.py`, `role_config.py` | snapshot·권한 저장소 조회·쓰기 전에 defer하고 DB 작업을 이벤트 루프 밖으로 이동한다. 저장 직전 소유자·현재 권한·revision 검사를 유지한다. |
| `role_config.py`, `manager_roles.py` | 오프라인 동안 사라진 역할을 draft 생성/저장 시 정리하고 화면에 정리 사실을 알린다. 유효한 역할과 동시에 발생한 관리자 변경을 보존한다. |

기존 문법·주시 채널 제한은 유지한다. DM은 목록의 전달 수단이며 DM 명령 접수·DM 요약·새 조회 슬래시 명령·운영 화면(F01)을 추가하지 않는다. 공개 응답을 `@everyone` 권한 하나로 안전하다고 판정하지 않는다.

## 실패 경계

- DM 거부·전송 오류·중간 권한 회수 시 공개 fallback에 이름·ID·개수·숨은 채널 존재를 넣지 않는다. 모든 조각에서 멘션과 embed를 억제한다.
- revision 충돌과 DB 실패는 저장 성공으로 알리지 않는다. DB commit 후 화면 갱신만 실패했다면 commit 결과를 보존하고 다음 조회에 실제 저장 상태가 나타나게 한다.
- 삭제된 역할 정리는 새로운 관리 권한을 부여하지 않는다. 권한이 회수된 사용자는 화면을 열어 두었더라도 저장할 수 없다.
