## 목표

1. `!!요약좀 [범위] [길이] [추가 요청…]`의 **추가 요청이 기본 형식·길이·말투·순서 지시보다 우선**하도록 신뢰 프롬프트를 바꾼다. 요청 원문은 프롬프트 끝에 “요청자 원문” 인용으로도 넣어 더 강하게 전달한다. 사실·화자 귀속·신뢰 경계·금지선과 수집 범위는 계속 바꿀 수 없다. `평가 빼줘`는 평가 줄을 뺀다.
2. 떡밥 한줄 평가를 내용 요약이 아니라 **한줄 비평**으로 바꾼다. 예: `이새끼들 또 쓸데없는 소리나 하고 말았구료.`

원인 분석·우선순위 표·요청별 기대 동작·인용 방식·평가 줄 규칙·사용자 결정(2026-10-01)은 [계약](CONTRACT.md)에 있다.

## 검증 방침

- 반영률을 숫자로 본다: 정상 요청 8건 중 **7건 이상**이 요청대로 바뀌어야 하고, 주입·금지선 요청 4건(인용 탈출 시도 포함)은 **모두** 거절·안내 줄이어야 한다. 사실·화자 귀속 오류는 0건, 평가 줄은 요약이 아닌 한줄 비평이어야 한다.
- 요청 원문이 신뢰 프롬프트에 들어가므로 주입 시험을 합성·실제 모델 양쪽에서 강화한다.
- 사용자 보고·실제 대화는 공개 문서에 옮기지 않고 합성 대화만 쓴다. 배포 전 진행 중 요약이 없음을 확인한다. 시간 의존 시험은 고정 시계를 쓴다.
- 실제 시험 Discord 확인은 P4 배포 뒤 사용자가 직접 입력한다. 확인하지 못하면 `NOT_RUN`. 8/24시간 연속 시험은 필수 게이트가 아니다.

버전 표기는 [버전 대응표](../PATCH_VERSIONING.md)대로 계획·태그 `1.1.1` / `v1.1.1`, Python 패키지 `1.1.1`이다.
