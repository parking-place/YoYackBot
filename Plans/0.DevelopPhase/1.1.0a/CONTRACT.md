# 1.1.0a 가독성·떡밥 한줄 평가 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 출시된 `v1.1.0`(2026-09-30) 코드를 기준으로 작성했다.

## 문제 (사용자 보고, 2026-09-30)

기본 요약(짧게)이 한 줄에 여러 사람의 사실과 비아냥을 쉼표로 이어 붙여 읽기 힘들다. 예:

```text
7대선 자선과후원 의원은 항소하면 낼 돈만 늘어난 것 아니냐고 물었고, 교육태만돼지 의원은 자신과 상대 모두 부담이 늘었다고 답했소, 질문은 나왔는데 계산은 깔끔히 안 끝났소.
```

원인: 1.1.0 프롬프트의 “사실 문장 뒤 거의 매번 비아냥 한마디”와 짧게의 “제목 없이 한 줄에 한 요점”이 겹쳐, 사실·비아냥이 한 줄에 뭉친다.

## 1. 모든 길이의 가독성 규칙

- **주제별 묶음**: 대화를 주제 2~4개로 묶고, 묶음마다 굵은 소제목 한 줄(`**주제 이름**`, 앞에 이모지 1개 허용)을 둔다. 묶음 사이는 빈 줄로 나눈다.
- **불릿 한 개 = 한 사람의 한 가지 말**: `- **화자 이름**: 한 일/한 말` 형태. 두 사람의 행동을 한 불릿에 쉼표로 잇지 않는다. 한 불릿은 한두 문장.
- **강조**: 화자 이름은 굵게, 결정·핵심 숫자·기한은 굵게 강조할 수 있다. 과한 강조(문장 전체 굵게, 연속 강조)는 하지 않는다.
- **비아냥은 따로**: 사실 문장에 쉼표로 붙이지 않는다. 주제 묶음마다 **최대 한 줄**, 불릿 아래에 `↳ *비아냥 한마디*` 형태로 분리한다. 비아냥 줄에도 새 사실을 넣지 않는다. 블록 인용(`>`)은 원문 인용 전용이라 비아냥에 쓰지 않는다(출력 검사가 인용 줄을 건너뛰므로).
- **결정·남은 점**: 있으면 마지막 묶음 뒤에 `**결정 난 거**` / `**아직 안 정해진 거**` 불릿으로 둔다. 없으면 만들지 않는다.

### 길이별 분량

| 길이 | 분량 |
|---|---|
| 짧게(기본) | 주제 2~4개, 불릿 **최대 8개**, 비아냥 줄 최대 주제 수만큼. 모바일 한 화면 안팎 |
| 길게 | 주제별 불릿 제한 없음, 결정·남은 점 포함(1.1.0 길게와 같은 내용 범위) |
| 자세히 | 1.1.0 자세히(시간 순서, 빠짐없이)를 같은 형식 규칙으로 |

### 형식 예 (합성 대화, 내용·이름은 표시 예시)

```text
**⚖️ 합방·항고**
- **가람**: 상대가 패배를 인정했을 때 합방을 생각했지만, 주변 반응을 보다 항고가 나와 싸움을 이어갔다고 했소.
- **나래**: 두 사람에게 반감이 크다고 했소.
- **가람**: 악감정보다는 아쉬움이 크다고 했소.
↳ *계획만 떠들다 판이 또 꼬였단 말이오?*

**💸 항소 비용**
- **다온**: 항소하면 낼 돈만 늘어나는 것 아니냐고 물었소.
- **가람**: 자기와 상대 모두 부담이 **늘었다**고 답했소.
↳ *계산기는 두드렸는데 답은 아무도 안 냈구려.*

요약창섭의 떡밥 한줄 평가 : 합방이니 항고니 거창하게 판을 벌이더니 결국 남은 건 서로 지갑 걱정뿐이란 말이오? 참으로 장대한 소모전이오.
```

## 2. 요약창섭의 떡밥 한줄 평가

- **모든 요약**(짧게·길게·자세히, 추가 요청 유무와 무관)의 **맨 마지막 줄**에 정확히 다음 형식으로 한 줄을 붙인다. 앞에 빈 줄 하나.

```text
요약창섭의 떡밥 한줄 평가 : <평가>
```

- 머리말 `요약창섭의 떡밥 한줄 평가 : `(콜론 앞뒤 공백 포함)는 글자 그대로 쓴다. 평가는 **한 줄**, 대화에서 오간 떡밥(주제·논쟁·계획)을 **매우 비꼬고 신랄하게** 평가하며, 문장 끝은 **하오체**다.
- 금지선은 평가 줄에도 그대로다: 없는 사실을 만들지 않고, 실제 사람을 성적으로 다루지 않으며, 집단 비하어·외모/지능 인신공격을 쓰지 않는다. 비꼼 대상은 떡밥과 그 전개다.
- 추가 요청을 무시했을 때의 `(추가 요청 중 일부는 들어줄 수 없었소.)` 줄은 평가 줄 **바로 앞**에 둔다.
- 추가 요청으로 평가 줄을 빼 달라고 해도 빼지 않는다(형식 요청 가운데 예외). 말투 조정 요청은 평가 줄에도 적용된다.

### 출력 검사

- 마지막 비어 있지 않은 줄이 `요약창섭의 떡밥 한줄 평가 : `로 시작하고 뒤에 내용이 있어야 한다. 평가 줄이 여러 개면 형식 위반이다.
- 형식 위반이면 같은 입력으로 **한 번** 다시 생성한다(평가 줄 누락 안내를 붙인 재시도 프롬프트). 그래도 없으면 **요약은 그대로 게시**하고 평가 줄 없이 둔다(요약 자체를 실패시키지 않는다). 로그에 `rating=missing`만 남긴다.
- 기존 집단 비하어 검사는 평가 줄에도 적용된다.

## 3. 유지할 것

범위·길이·추가 요청 문법, 시작·진행 중·쿨타임(1분)·준비 중 안내, 사용량·상태·채널, 사실·화자 귀속·신뢰 경계 규칙, 추가 요청 무시 규칙, 봇 안내 문구는 1.1.0 그대로다. 게시 머리글(`오후 5시 13분부터 지금까지의 요약이오.`)과 1,900자 분할도 그대로다.

|---|---|---|
| 소제목 이모지 | 주제마다 1개 허용 | 이모지 없음 |

| 평가 줄 누락 | 1회 재생성 후에도 없으면 평가 없이 게시 | 1회 재생성 후 없으면 요약 실패 처리 |
