# 1.1.0a-P4 — 도움말·통합·배포·출시

- 상태: **IN_PROGRESS** · 검사: `T110a-P4-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P3](STATUS.md)의 원격 완료를 확인한다. 도움말에 “요약 끝에 요약창섭의 떡밥 한줄 평가가 붙는다”는 한 줄을 넣는다(2,000자 미만). README·`CHANGELOG`·`docs/upgrade-rollback-1.1.0a.md`(복귀 대상 `v1.1.0`, schema 변경 없음, 복귀 시 평가 줄과 형식 규칙이 사라짐)를 갱신한다. 패키지·`VERSION`을 `1.1.0.1`로, 버전 대응표와 저장소 검증기에 1.1.0a의 4단계·8검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 진행 중 요약이 없음을 확인하고 이전과 같은 절차로 배포한다. 이전 `v1.1.0` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 채널에서 확인한다: `!!요약좀`(짧게 형식·평가 줄), `!!요약좀 길게`, `!!요약좀 [범위] 자세히` 중 가능한 것, `!!요약좀 도움`. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T110a-P4-A`: 전체 회귀와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T110a-P4-B`: 후보·서비스 SHA 대조, 시험 Discord 사용자 확인과 서비스 로그(모드·`rating=present/missing`·결과) 대조, 배포·복귀·비밀정보 비노출·P1~P3 원격 증거, 병합 후 `main` CI를 기록한다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합한다. 태그 `v1.1.0a`와 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
