# 1.1.0a-P2 — 떡밥 한줄 평가·출력 검사

- 상태: **PUSH_PENDING** · 검사: `T110a-P2-A/B` · 환경: 개발 LXC, 합성 대역(모델 호출 없음)

## 선행 조건·작업

[P1](01-format.md)의 원격 완료 뒤 [계약](CONTRACT.md) 2절에 따라 신뢰 프롬프트에 “맨 마지막 줄 `**요약창섭의 떡밥 한줄 평가** : <평가>`” 지시(매우 비꼬고 신랄하게, 하오체, 금지선 유지, 추가 요청 무시 안내 줄은 그 바로 앞, 추가 요청으로 뺄 수 없음)를 넣는다. 출력 검사에 평가 줄 형식 검사(마지막 줄 머리말·내용·단 하나, 굵게 빠진 머리말은 코드로 굵게 교정, 여러 개면 마지막만 유지)를 더한다. 평가 줄이 없으면 **평가 한 줄만** 만드는 짧은 신뢰 프롬프트(대화 입력 + 방금 만든 요약 본문)로 **한 번** 더 호출해 형식·비하어 검사를 통과한 줄을 요약 끝에 붙이고, 그래도 없으면 요약을 그대로 게시한다. 지표 로그에 `rating=present/retried/missing`을 남긴다. 요약 한 건의 모델 호출은 최대 3번(본 요약·전체 재생성·평가 재생성)이다. 프롬프트 버전을 `1.1.0a-p2-v1`로 올린다.

## 검증·완료 기준

- `T110a-P2-A`: 세 길이 × 재시도 종류의 프롬프트가 평가 줄 지시를 포함하고, 평가 전용 프롬프트는 대화 입력과 요약 본문만 쓰며 추가 요청 원문을 신뢰 프롬프트에 넣지 않는다. 형식 검사: 올바른 평가 줄, 굵게 빠진 머리말(교정), 누락, 빈 평가, 중간에만 있음, 여러 줄(마지막만 유지), 무시 안내 줄 뒤 평가 줄(정상), 평가 줄 뒤 다른 줄(위반)을 정확히 판정한다.
- `T110a-P2-B`: 누락 → 평가만 1회 재생성해 붙임(`rating=retried`), 평가 재생성도 실패·형식 위반·비하어 → 평가 없이 게시(`rating=missing`), 본 요약의 비하어·화자 표식은 기존 전체 재생성, 호출 수 최대 3번. 게시 분할에서 평가 줄이 마지막 메시지에 온전히 들어간다. 쿨타임·진행 상태·사용량 규칙은 그대로다.

같은 SHA의 결과를 기록하고 구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 각각 commit·GitHub push·원격 확인한다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
