# 0.6.0-P5 프롬프트 보강 및 통합 출력 검증

- 대상 프롬프트: `0.6.0-p5-v2`
- 모델: Codex CLI `0.158.0`, `gpt-6-luna`, reasoning `low`
- 개발 환경: OpenJevLXC 전용 봇 계정과 실제 개발 Discord 주시 채널
- 입력: 합성 fixture 21건; 사용자가 보낸 표식 있는 합성 메시지 3건

## 발견과 수정

첫 실제 수집→모델→게시 실행에서는 한 계정이 전달한 가람·나래의 의견을 요약할 때
간접 인용이 직접 발언처럼 읽힐 여지가 있었고, 단순한 ‘날짜 미정’ 안내를 ‘정정’으로
표현했다. 이 결과를 품질 결함으로 기록하고, 프롬프트에 화자별 간접 인용과 명시적
정정 기준을 추가했다. 단일 계정이 다른 사람의 말을 전달하는 합성 회귀 사례도
`reported_people_one_speaker`로 추가했다.

보강 후 동일한 사용자 합성 메시지 3건을 다시 수집해 실제 모델에 전달하고 같은
주시 채널에 게시했다. 모델은 가람과 나래의 의견을 전달된 내용으로 표현하고
배포 날짜를 미정으로 남겼다. 불필요한 ‘정정’ 표현은 사라졌다. 게시물은 1개였고
한국어 하오체·개수형 최저 시각 머리말·채널 일치·멘션 0건·요청 임시 폴더 0개를
확인했다. History 조회는 1페이지였고 캐시 장애 fallback은 사용하지 않았다.

## 전체 합성 평가 재실행

프롬프트를 바꾼 뒤 기존 20건과 추가 1건을 **모두 실제 모델로 다시 호출**했고,
Codex가 합성 원문과 출력을 개별 대조했다.

| 범위 | 사례 | 결과 |
|---|---|---|
| 합의·가정·반대·농담 | `meeting_agreed`, `tentative_only`, `dissent`, `joke_not_decision` | 4/4 적합 |
| 질문·정정·표시명 | `question_answer`, `corrected_date`, `same_display_name`, `renamed_author` | 4/4 적합 |
| 자료·입력 경계 | `attachment_unknown`, `link_no_visit`, `instruction_in_body` | 3/3 적합 |
| 결정과 조건 | `two_topics`, `budget_option_rejected`, `conditional_approval`, `casual_no_decision` | 4/4 적합 |
| 수량·명령·철회·미해결 | `quantity_corrected`, `quoted_command`, `decision_revoked`, `unanswered_question` | 4/4 적합 |
| 여러 역할·간접 인용 | `three_person_roles`, `reported_people_one_speaker` | 2/2 적합 |

- 주요 근거 항목: **45/45 포함** (합성 fixture의 `required` 기준)
- 중대한 날조·화자 오귀속: **0건**
- 한국어 하오체 적합: **21/21건**
- 빈 답변·비한국어·원문 전체 복사·도구 실행 보고: **0건**
- 모델 호출 오류: **0건**

긴 본문·코드 블록·이모지·멘션·분할 순서는 P3의 LXC 검사와 P4의 실제 2조각
게시로 확인했다. 빈 대화와 부분 전송 실패는 기존 수집·publisher 회귀 검사로
확인했다. 첨부·링크·명령성 본문과 다수 화자는 실제 모델 합성 평가에 포함했다.
실제 사용자 한 명의 3개 메시지 통합 경로와 다수 화자 합성 경로를 구분한다.

이번 수치는 단일 합성 실행의 수동 대조 결과다. 독립적인 사람이 출력 원문을
다시 대조한 것은 아니며, 사용자는 앞선 Codex 평가표를 수락하고 후속 진행을
지시했다. 공개 문서에는 실제 Discord 원문, 인증값, 모델 출력 전문을 싣지 않는다.
명령 자동 연결·동시성·성공 후 쿨타임·운영 배포는 0.7.0 이후의 검증 대상이다.
