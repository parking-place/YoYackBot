## 정책과 구현

현재 retention의 cutoff와 같은 생성 시각은 포함하고 이전 시각은 fetch·도착·쓰기·선택에서 제외한다. 같은 수정 시각은 본문을 다시 덮어쓰지 않으며 과거 이벤트는 무시한다. timestamp 없는/잘못된 raw·cached edit는 확정 본문을 유지하고 현재 주시 채널의 기존 재검증 상태 하나를 갱신한다. 재검증은 최대 현재 retention 30일, 페이지 최대 100건, 기존 동시성 한도로 수행한다.

History가 성공적으로 반환한 내림차순 페이지의 ID 구간만 삭제·upsert·cursor와 함께 commit한다. 미조회 tail·조회 실패·stale generation은 부재 증거가 아니다. 시작/재접속은 모든 phase를 새 세대로 바꾸며 history+overlap 전체 완료 전 pending을 해제하지 않는다. 같은 시각 재접속도 세대를 증가시킨다.

fetch 직전 논리 관측 경계와 이후 live 쓰기를 비교한다. 선택 테이블 `cache_observation_clock`은 식별값·원문 없는 단일 정수이며 최신 행을 삭제해도 순서가 역행하지 않는다. schema 5와 messages 레이아웃은 유지되고 설정 백업의 고정 허용 목록에 이 캐시는 포함되지 않는다. raw delete tombstone도 오래된 페이지보다 우선한다.

실제 `build_workflow → CacheOnlyCollector`가 pending과 검증 세대를 소비한다. 선택 후 모델 대기·실행·게시 및 각 게시 조각에서도 세대·retention을 확인한다. 재접속 예약 실패는 in-memory latch로 요약을 차단하고 worker가 재시도한다.
