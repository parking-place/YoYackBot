## 사전 확인 — “첫 출력”의 뜻 (운영 LXC 봇 계정, 합성 입력)

Codex CLI 0.158.0 격리 실행의 stderr를 줄 종류만 시각과 함께 기록했다(내용 미기록). `!!말하자면` 두 호출:

| 시각 | 줄 |
|---|---|
| ~0.6초 | 시작 머리말(`OpenAI Codex v…`, `--------`, `user`) |
| ~4.1초 | 첫 모델 출력 `codex`(모델의 첫 말) |
| ~4.8초 | `exec`(입력 파일 읽기) |
| 6.4~11.7초 | 마지막 `codex`(답), 곧 `tokens used`, 종료 |

CLI는 답을 조각조각 흘려보내지 않고, 최종 답은 종료 때 stdout·출력 파일로 나온다. 그래서 **첫 출력 = 머리말 뒤 처음 나오는 `codex`·`thinking`·`exec` 줄**로 정했다.

## 구현

- **`timing.py`**: 요청 단위 기록(ContextVar)이다.
  - Discord `on_message`가 `!!요약좀`·`!!말하자면`일 때 0ms를 찍는다. Discord 메시지 시각과의 차이는 `discord_delay_ms`로 남긴다.
  - workflow가 기록을 넘겨받아(직접 호출이면 새로 시작) `admitted`·`start_notice`·`collected`·`queued`·`posted`를 찍는다.
  - 엔진은 Codex 호출마다 이름(`summary`·`summary_retry`·`candidates`·`judge`·`candidates_retry`·`idiom_candidates`·`idiom_candidates_retry`·`idiom_select`)을 붙여 시작·끝·결과(`ok`/`error`/`cancelled`)를 남긴다.
  - 실행기는 stderr를 읽는 중에 첫 모델 출력 줄을 찾는다. 조각 경계를 이어 보고, 64바이트를 넘는 줄은 표식으로 보지 않는다.
- **로그**: 기존 지표 줄 바로 뒤에 `yoyackbot.timing` 로거로 `request_timing` JSON 한 줄을 남긴다. 지표와 같은 `request_id`를 쓴다. 단계·호출 이름은 허용 목록뿐이고 나머지는 숫자·결과 범주다.
- **`scripts/show_timings.py`**: 서비스 로그에서 `request_timing` 줄을 골라 단계별 누적 ms·직전 단계와의 차이·호출 시간을 표로 보여 준다.
