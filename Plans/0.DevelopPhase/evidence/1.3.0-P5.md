## 구현

- **트리거**
  - 앞뒤 공백을 뺀 메시지 전체가 `!!말하자면`일 때만 실행한다.
  - 뒤에 말이 붙거나, 반복되거나, `!!요약좀`과 섞이면 고정 사용 안내만 보낸다. 문장·인용 안의 토큰은 일반 대화로 둔다.
  - 명령 메시지는 Gateway·백필에서 저장하지 않는다. 1.2.0이나 편집으로 캐시에 들어간 명령 행은 `recent`/`latest` SQL의 WHERE에서 LIMIT보다 먼저 뺀다(삭제가 아닌 필터라서 다시 일반 대화로 편집하면 다시 보인다).
- **입력**
  - 기존 캐시 개수형 경로로 최신 유효 메시지 최대 30개를 시간순으로 읽는다. 준비·검증 세대·보존기간·권한 확인은 요약과 같다.
  - 답장으로 보내도 범위가 바뀌지 않고, History·답글 대상을 따로 조회하지 않는다. F10 참조는 30개 안에서만 만든다.
  - 0개면 모델 호출 없이 안내하고, `max_messages`가 30 미만이면 사용 불가로 안내한다.
- **엔진**: 일반 요약과 같은 모델 동시성 슬롯을 쓴다. 입력 JSONL 바이트 한도도 같다.
  1. 후보 호출: `{"candidates": [{term, kind}×4]}` 형식으로 받는다. 서로 다른 4개, NFC 정규화 뒤 한글 음절 4개, kind는 idiom/word여야 한다. 이름·비하어가 있으면 무효다. 무효면 오류 원문을 붙이지 않은 재생성 노트로 1회만 다시 요청한다.
  2. 선택 호출: `{"selected_index", "emoji"}` 형식으로 받는다. 번호가 틀리면 실패 처리한다. 이모지가 허용 목록(🤔 🙃 😅 😏 🤝 🧩 💡 🎯)에 없으면 🤔를 쓴다.
  - 코드가 `말하자면 {표현}? {이모지}` 한 줄을 조립한다.
  - 호출은 정상 2회, 최대 3회다. 실패하면 고정 안내만 보내고, 임의 후보를 게시하지 않는다.
- **workflow**
  - 일반 요약과 채널 작업 슬롯·대기열·성공 쿨타임을 공유한다. 진행 중이면 BUSY, 쿨타임이면 남은 초를 안내한다.
  - 시작 안내 "🔎 최근 대화를 살펴보는 중이야."를 보낸 뒤 결과를 게시한다. 게시 직전에 권한·주시·검증 세대를 다시 확인한다.
  - 성공한 게시에만 쿨타임을 건다.
- **말투**: 하오체·서버 말투·추가 요청·평가 후보·최근 평가를 쓰지 않는다. 고정 반말 안내 13종(시작·사용법·빈 입력·실패·작업 중·준비 중·비주시·확인 불가·한도·입력 초과·권한 변경·대기열·쿨타임)을 쓴다.
- **로그**: `idiom_request_parsed`와 `idiom_request` JSON(결과 분류·선택 건수·호출 수·후보 종류 수·선택 종류·소요 시간)만 남긴다. 후보·결과 문장·원문은 남기지 않는다.
- 새 DB 테이블·이력·설정은 없다.
