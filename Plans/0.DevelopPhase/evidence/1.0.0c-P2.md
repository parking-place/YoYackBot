- 대기열은 메시지 수와 서버를 힌트로 짧은 작업·다른 서버를 앞세우되, 먼저 기다리던 요청은 최대 두 번만 추월당한다. 힌트가 없는 기존 호출은 FIFO다. 큐 용량 4와 대기 제한 180초는 유지한다.
- 제어된 시험에서 같은 서버의 `긴 작업 → 짧은 작업 두 개`는 `짧은 작업 둘 → 긴 작업` 순서로 실행됐고, 다른 서버의 짧은 작업도 앞서 진행했다. 짧은 작업 세 개가 도착해도 오래된 긴 작업은 두 번 뒤 반드시 실행됐다. 기존 포화·취소·종료·모델 실패·동일 채널 중복·쿨타임 회귀가 통과했다.
- P1과 같은 1/1000 축척 합성 부하에서 같은 서버 4채널은 **3/4 → 4/4**, 8채널은 **3/8 → 4/8** 성공했다. 다른 서버 4/8채널은 이 단일 실행에서 각각 **3/4, 3/8**로 기준선과 같았다. 8채널에서 3건의 즉시 포화는 그대로이며, 대기 만료도 1~2건 남는다. 단일 실행의 작은 지연 차이는 성능 개선으로 주장하지 않는다. 게시 결과는 모든 실행에서 채널·서버가 분리됐고 같은 채널 요청은 `busy`, 성공 직후 요청은 `cooldown`이었다.

`C3/C4`는 **LXC 합성·시간 제어 범위에서 PASS**다. 남은 포화와 만료는 P4의 용량·실행 정책에서 수치로 다룬다. 실제 Discord 동시 게시와 계정 한도는 이 단계에서 시험하지 않았다. E 원격·CI와 D는 [상태](../1.0.0c/STATUS.md)에 기록한다.
