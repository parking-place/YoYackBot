## 사전 확인 (구현 전, 운영 LXC의 봇 계정)

서버 Codex CLI `codex-cli 0.158.0`의 모델 목록 캐시에서 `gpt-6-luna`는 `service_tiers: [{id: "priority", name: "Fast", description: "1.5x speed"}]`를 내놓는다. 임시 `CODEX_HOME`으로 짧은 합성 질문을 보내 다음을 확인했다(대화 원문 없음, 임시 폴더 삭제).
- `--config service_tier="priority"`, `"fast"`: 경고 없이 정상 종료(rc 0)
- `--config service_tier="bogus"`: “지원하지 않는 등급이라 요청에서 뺀다”는 경고 뒤 보통 등급으로 정상 종료

그래서 catalog의 id인 `priority`를 쓴다. 지원하지 않는 CLI라도 요청이 실패하지 않는다.

## 구현

- **선택 테이블 `guild_fast_mode`**(서버, 켠 시각; schema 5 유지): 행이 있으면 켜짐이다. `SQLiteSpeedStore.set`은 켜기·끄기를 그대로 덮어쓴다. 서버 탈퇴 때 지운다. 설정 백업·복원에 `fast_mode`로 포함되며, 이 키가 없는 1.3.0 백업도 복원된다.
- **요청 단위 등급**:
  - `CodexContract.service_tier`가 있으면 `--config service_tier="priority"` 한 쌍만 더한다.
  - 엔진의 `summarize(..., fast=)`·`idiom(..., fast=)`는 `async with fast_tier(fast)` 안에서 모든 호출을 하고, `SandboxedCodex.command`가 그 요청의 값을 읽는다(ContextVar, 요청 task마다 분리).
  - 모델·추론 강도·격리 옵션은 그대로다. `사용량` 조회는 이 경로를 쓰지 않는다.
- **workflow**: 요약은 말투와 함께, `!!말하자면`은 모델 호출 직전에 서버 설정을 읽는다. 읽기 실패면 `speed_read_failed` 경고 뒤 보통 등급이다. 지표에 `speed=fast|standard`를 넣었다.
- **`/속도 설정` 화면**:
  - 1.1.3 판정으로 실행하는 `속도` 그룹 아래 `설정`이다.
  - 연 사람에게만 상태(“⚡ 빠른 모드: 켜짐” / “🐢 빠른 모드: 꺼짐(기본)”)와 사용량 설명, 켜기·끄기·닫기 버튼을 보여 준다.
  - 누를 때마다 연 사람·서버·120초·권한을 확인한다. 저장 뒤 “⚡✅ 빠른 모드를 켰소.” / “🐢✅ 빠른 모드를 껐소.”로 닫는다.
  - 로그는 `speed_saved fast=true|false`뿐이다.
- **도움말**: 바꾸지 않았다(P2 시험에서 `속도` 미표시 확인).
