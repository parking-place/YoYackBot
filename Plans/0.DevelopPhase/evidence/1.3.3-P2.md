## 사전 확인 — CLI의 프롬프트 되찍기 (운영 LXC 봇 계정, 합성 프롬프트)

0.158.0은 stderr에 머리말 뒤 `user` 줄을 찍고 **보낸 프롬프트를 줄 그대로** 되찍는다(빈 줄·들여쓰기 포함). 그 뒤에 자기 줄(`warning:`, `ERROR: …`, `codex`, `tokens used`)이 나온다. 가짜 인증으로 실패시킨 실행에서는 되찍힌 프롬프트 뒤에 `ERROR: unexpected status 401 Unauthorized …` 줄이 나왔다. 되찍힌 프롬프트 안에 넣은 “quota exceeded” 문장이 지금의 실패 분류에 그대로 노출된다는 것도 확인했다.

## 구현

- **자료 블록**(`input_files.with_data`, 결정 D11):
  - 고정 지시문 뒤에 `<<<자료 {nonce}>>>` … `<<<자료 {nonce} 끝>>>`로 JSONL 자료를 붙인다. nonce는 호출마다 새로 만드는 16자리 16진수다.
  - JSONL은 한 줄에 JSON 값 하나라서, 대화 속 줄바꿈이나 구분자 흉내가 블록을 닫지 못한다.
- **`!!말하자면` 두 호출 모두 대화를 프롬프트로 받는다.**
  - 지시문의 “`/work/conversation.jsonl` 한 파일만 읽으시오”를 “맨 끝 자료 블록 … 파일을 읽거나 명령을 실행하지 말고”로 바꿨다.
  - 호출 구조(후보 → 선택, 최대 3회)와 최종 한 줄 조립은 그대로다(사용자 결정 5).
- **대화 파일 마운트 제거**: `InputWorkspace.create(..., inline=True)`이면 bwrap 명령에서 `/work/conversation.jsonl` 바인드를 뺀다. 파일은 봇 전용 임시 폴더에만 잠깐 쓰이고 지금처럼 호출 뒤 지운다. 다른 격리 옵션은 그대로다. 요약 경로는 아직 파일 방식이다(P3).
- **되찍힌 프롬프트 건너뛰기**: stderr 감시기가 첫 `user` 줄 뒤로 보낸 프롬프트의 줄 수만큼 건너뛴다.
  - 그래서 첫 출력·도구 수·토큰 계산과 실패 분류용으로 남기는 진단(앞뒤 최대 8KiB)은 CLI 자신의 줄만 본다.
  - 보낸 프롬프트 끝의 줄바꿈은 잘라 줄 수를 맞춘다. P1의 표식 줄 무력화는 이중 방어로 남긴다.
- **프롬프트 상한**: 실행기 상한을 `입력 상한 + 65,536바이트`로 올렸다(지금 기본 1,065,536바이트, P3에서 입력 상한 재설정).
- **기존 테스트**:
  - 사자성어 프롬프트 비교 2곳을 “고정 지시문 + 자료 블록”에 맞췄다.
  - `test_codex_lifecycle`의 `/proc` 읽기 도우미가 읽는 도중 프로세스가 사라지는 경우(`ProcessLookupError`)를 “없음”으로 보게 고쳤다. 이 경합은 기존부터 있었고, 이번 작업 중 전체 실행 1회에서 드러났다. 이후 단독 5회·전체 3회 모두 통과했다.
