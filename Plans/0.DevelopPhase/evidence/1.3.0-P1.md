## 구현

- **프롬프트 `1.3.0-p1-v1`**
  - 요약 프롬프트의 떡밥 한줄 평가 단락에 다음 규칙을 넣었다.
    - 금지: 화제 전환·어수선함(튄다·왔다갔다·오락가락·정신없다·부산하다·요란하다·한 상 가득·뒤엉켰다)
    - 허용: 떡밥 주제어
    - 그대로 금지: 사람 이름·숫자·시간
  - 후보 프롬프트를 새로 만들었다. 번호를 붙인 정확히 10줄이고, `recent_rating` 줄은 자료로만 주며 같은 소재·틀을 피하게 한다. 금지 소재(어수선함 + 미결·미룸)와 각도 예시를 넣었다. 추가 요청 인용은 그대로 붙고, 다시 만들 때는 금지를 더 강하게 적은 노트가 붙는다.
  - 심사 프롬프트를 새로 만들었다. 첫 기준은 '주제가 바뀌어 정신없다'와 비슷한지이고, 답은 `비슷함: …` / `선택: …` 두 줄로 고정했다.
- **`rating_pool`**
  - 후보 파싱: `1.`·`2)`·`3 -`·`-` 같은 여러 번호 형식과 굵게 표시 여부를 받는다. 머리말이 없는 줄은 버리고 중복을 없애며 최대 10개까지만 쓴다.
  - 거르기: 다음이 하나라도 있으면 버린다.
    - 금지 소재 정규식(도시 이름 '부산'과 '튀김'은 허용)
    - 화자 이름(2글자 이상)과 숫자
    - 비하어, 미결 조롱
    - 핵심 출력 검사 문제(도구 표식, P/M 키, 한글 없음)
    - 160자 초과나 줄바꿈
  - 심사 답 파싱: 비슷하다고 표시된 번호를 고르거나 범위를 벗어난 답, 형식 오류는 무효로 처리한다.
- **선택 테이블 `recent_ratings`**: schema 5는 그대로다.
  - 채널마다 보존기간 안의 최신 20개만 둔다.
  - 주시 해제·채널 삭제·서버 탈퇴 때 지우고, DB를 열 때 주시하지 않는 채널의 행을 정리한다(구버전 대비).
  - 저장 대상은 주시 중인 채널뿐이다. 설정 백업에는 넣지 않는다.
- 엔진 연결(후보 → 심사 → 게시 뒤 저장)은 P2에서 한다. 이 C에서는 기존 평가만 다시 만들기 경로를 그대로 뒀다.
