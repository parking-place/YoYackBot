## 구현

- **안내 문구 목록**(`notices.py`, 170개): 도움말 전체, 요약 시작·대기·실패·쿨타임·범위 머리줄, 답장 범위, 수집 안내·단계, 상태·사용량·채널 목록, 설정 화면(`/채널 설정`·`/관리권한 설정`·`/말투`·`/속도 설정`·`/처형설정`), 처형 로그, `/처형` 답이다.
  - 문구마다 키와 기본 문구가 있고, 보낼 때 채워지는 값은 `{count}` 같은 자리표시자다. 다른 문구 안에 끼는 짧은 값(“3분 전이오.”, “확인할 수 없소.” 등)도 따로 둔다.
  - `!!말하자면`·`/말하자면`의 안내는 넣지 않았다(사용자 결정). 요약 본문·평가 같은 모델 출력은 거치지 않는다.
  - 버튼 이름·명령 설명은 Discord 전체에 하나뿐이라 대상이 아니다.
- **치환**: 보내는 곳마다 `localize(서버, 문구)`를 거친다. 도움말은 통째로, 나머지는 줄마다 목록과 맞춰 서버 문구로 바꾸고 값은 그대로 다시 채운다. 목록에 없는 줄(인용한 말투, 채널 이름 등)은 그대로다. 바꾼 결과가 2,000자를 넘으면 기본 문구를 쓴다. 서버 문구는 메모리에 두고, 보낼 때 DB를 읽지 않는다.
- **생성**(`notice_writer.py`): 말투를 저장하면 그 서버 문구를 즉시 기본으로 돌리고, 백그라운드에서 `gpt-6-luna`·추론 강도 **high**로 다시 쓴다.
  - 도움말 1번, 나머지는 24개씩 나눠 부른다. 모델은 서버 말투와 기본 문구만 받고 대화는 받지 않는다.
  - high는 이 호출에만 쓰고 운영 설정값으로는 고를 수 없다(`CALL_EFFORTS`).
  - 같은 서버에서 더 새 말투가 저장되면 진행 중인 생성을 취소한다.
- **검증**: 생성 문구는 다음을 모두 지켜야 하고, 아니면 그 문구만 기본 문구를 쓴다.
  - 자리표시자가 같다. 다른 중괄호가 없다. 백틱 구간과 `/명령`·`!!명령` 표기가 같다. 숫자가 같다.
  - 줄 수가 같다(도움말 제외). 길이는 기본의 3배(최소 60자) 이하이고 도움말은 2,000자 이하다.
  - 멘션·링크 모양 글이 늘지 않는다. 비하어가 없다. 맨 앞 이모지를 지킨다.
  - 호출이 실패한 묶음도 기본 문구다.
- **저장**: `guild_notices`(서버, 키, 문구, 말투 버전) 선택 테이블이다.
  - 저장할 때 서버 말투 버전이 그대로인지 한 트랜잭션에서 확인하고, 버전이 다른 행은 읽지 않는다.
  - 기본값으로 되돌리면 행을 지운다.
  - 시작할 때 읽어 들이고, 1.4.0 전에 저장된 서버 말투처럼 문구가 없는 서버는 시작 뒤 한 번 생성한다.
  - 서버를 나가면 지우고, 접속 때 없는 서버의 행을 정리한다. 설정 백업·복원에 넣었다(복원 때 다시 검증하고, 모르는 키는 버리고, 1.3.4 백업도 받는다).
- **알림·로그**: `/말투`를 연 사람에게 결과를 본인만 보이게 알린다(“바꾼 개수”·“기본으로 남은 개수”·실패). 서비스 로그는 `guild_notices_written written= kept= failed_calls= not_stored= reasons=`처럼 개수와 사유 분류만 남기고, 문구·말투는 남기지 않는다.
- 기존 시험 2개를 고쳤다. 강도 시험은 `high`가 이제 호출별로 허용되므로 모르는 값 `xhigh`로 거부를 확인한다. `/처형` 시험 대역 상호작용에 `guild_id`를 넣었다.
