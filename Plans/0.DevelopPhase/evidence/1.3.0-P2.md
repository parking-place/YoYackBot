## 구현

- **엔진 흐름**
  1. 요약 본문(필요하면 전체 재생성 1회)을 만든다.
  2. 후보 호출 1회로 10줄을 받고 코드로 거른다.
  3. 남은 후보가 있으면 심사 호출 1회를 한다. 입력은 `candidate` 줄(새 번호)·`summary`·`recent_rating`이다.
  4. `선택` 번호를 쓴다. 모두 비슷하거나 유효 후보가 0개면 후보를 1회 다시 만들어 첫 후보를 쓴다.
  - 대체 순서: 심사 실패·잘못된 답 → 비슷하지 않은 첫 후보 → 첫 후보. 후보 호출 실패나 재생성까지 0개 → 요약 본문의 평가 줄(코드 거르기를 통과할 때) → 평가 없음.
  - `평가 빼줘`면 후보·심사 호출이 없다. 요약당 호출은 최대 5회다.
- **최근 평가 기억**: 게시에 성공한 뒤에만 고른 평가 줄(이모지 제거 반영)을 채널별로 저장한다. 다음 요약의 후보·심사 호출에 자료로 넣는다. 읽기·쓰기 실패는 고정 경고만 남기고 요약은 계속한다.
- **지표**: `rating=picked/regenerated/fallback_summary/fallback_first/missing/skipped`, `rating_candidates`(0~10), `rating_similar`(0~10). 문장은 로그에 남기지 않는다.
- **제거**: 1.1.0a의 평가만 다시 만들기(`RATING_PROMPT`·`rating_prompt`·미결 조롱 평가 재시도 노트)는 후보 생성으로 대체해 지웠다.
- **기존 테스트 정리**: 평가와 무관한 엔진 테스트는 공통 도우미(`tests/rating_fakes.py`)로 후보 호출을 '사용 불가'로 처리한다. 그래서 요약 본문의 평가 줄이 `fallback_summary`로 유지된다. 평가 흐름 테스트는 새 흐름으로 바꿨다(P4 출력 계약 포함).
