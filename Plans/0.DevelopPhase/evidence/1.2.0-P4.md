## 정책과 구현

- **B10 화자 위치 정규화**: 줄 머리의 제목/목록 표식과 이모지·기호 하나를 지나서 판정한다. 대상은 `**`·`__`·`*`·`_`·`~`의 임의 중첩으로 감싼 `P숫자` 뒤에 `:`·대시나 기존 조사(은·는·이·가)가 오는 경우다. 인용(`>`), 코드 블록, 인라인 코드(`` ` ``)는 검사하지 않는다. 조사 집합은 기존 그대로 두어 우선순위 표기 같은 정상 문장의 오탐을 늘리지 않았다.
- **B11 실제 본문 확인**: 평가 줄을 떼고 거절 고지(굵게 포함)·장식 줄을 빼면 한글 본문이 남아야 한다. 남지 않으면 `NO_BODY`로 보고 같은 입력으로 한 번 다시 요청한다. 그래도 없으면 `OUTPUT_INVALID`다. 빈 응답·한글 없음·입력 불가 표식은 기존처럼 재요청 없이 실패한다.
- **B12 공통 검증**
  - 전체 응답이 핵심 검사에 걸리면 본문만 따로 검사한다. 평가만 문제면 본문을 살리고 평가를 다시 만든다. 본문이 문제면 평가가 정상이어도 게시하지 않는다.
  - 처음 받은 평가와 평가 전용 재생성 결과는 `rating_issue`로 검사한다. 내용은 `inspect_output`과 같고, 평가에는 사람을 쓰지 않으므로 어느 위치든 내부 키가 있으면 거절한다.
  - 마지막으로 거절 고지·이모지 제거까지 반영한 최종 문자열을 다시 검사한다. 평가 때문에 실패하면 평가만 빼고, 그래도 실패하면 `OUTPUT_INVALID`다.
  - 호출 수: 본문 재시도 1회와 평가 재생성 1회를 합쳐 요청당 최대 3회로 유지했다.
- **B13 실행 경로 고정**
  - `YOYACK_CODEX_EXECUTABLE`이 PATH 이름이면 프로그램 시작(`__main__`)에서 한 번만 `shutil.which`로 절대 경로를 찾아 Settings에 고정한다. 준비 검사·엔진·sandbox runner·사용량 조회가 모두 이 값을 쓴다. 이후 PATH가 바뀌어도 다른 파일을 실행하지 않는다.
  - 경로 오류: 상대 경로(`bin/codex`)는 `config`, PATH에서 못 찾은 이름은 `executable_missing`로 거절한다.
  - 준비 검사 판정 순서는 `executable_missing`/`executable_not_runnable`(정규 파일·실행 권한) → `version_mismatch` → `auth_file`이다. `auth_file`은 인증 파일 형태 검사일 뿐 실제 로그인 성공이 아니다.
  - `check-ready`는 고정된 사유 이름만 출력하고 경로는 출력하지 않는다. `.env.example`과 서비스 운영 문서도 이 동작에 맞췄다.
