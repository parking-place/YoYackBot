## 구현

- **동시 시작**(사용자 결정 4):
  - `평가 빼줘`가 아니고 자리를 빌릴 수 있으면, 요약 호출과 같은 시점에 평가 후보 호출을 별도 task로 시작한다.
  - 후보는 대화·최근 평가·추가 요청·서버 말투로 10개를 만들고 요약 본문은 받지 않는다.
  - 후보 지시문의 “summary 줄은 방금 쓴 요약”을 “요약은 따로 쓰고 있으니 대화를 직접 읽고 평가하시오”로 바꿨다. 프롬프트 버전은 `1.3.3-p4-v1`이다.
  - 자리를 빌리지 못하면 지금처럼 요약 뒤에 같은 입력으로 순서대로 실행한다.
- **심사는 따로, 게시는 함께**(사용자 결정 6·7): 요약(재작성 포함)과 후보가 모두 끝난 뒤, 최종 요약 본문·후보·최근 평가로 심사한다. 본문과 평가 줄은 지금처럼 한 번에 게시한다. 후보 재생성(`candidates_retry`)도 후보와 같은 입력이다.
- **자리 빌리기**(`ModelSlots`):
  - 엔진의 동시 실행 자리(설정 `YOYACK_CODEX_CONCURRENCY`, 기본 4) 중 **빌린 뒤에도 한 자리가 남을 때만**, 기다리지 않고 한 자리를 빌린다. 후보 호출이 끝나거나 취소되면 바로 돌려준다.
  - 그래서 동시 실행이 1~2면 빌리지 않는다.
  - 다른 요청은 남겨 둔 한 자리를 바로 얻는다. 같은 순간에 두 요청 이상이 몰리면, 두 번째 요청은 빌린 후보 호출이 끝날 때까지(후보 1회 길이) 기다릴 수 있다.
- **취소**: 요약이 실패하거나(모델 오류·재작성 뒤 검사 실패), 요청이 취소되거나(권한 회수·종료), 예외가 나면 후보 task를 취소하고 끝날 때까지 기다린다. CLI 프로세스 그룹 종료·작업 폴더 삭제는 기존 실행기가 한다.
- 호출 상한 5회와 결과 범주(`picked`/`regenerated`/`fallback_summary`/`fallback_first`/`missing`/`skipped`)는 그대로다.
- **기존 테스트 3곳 갱신**: 후보 입력에 요약 줄이 없다는 것, 1.3.2 시간 순서 시험의 호출 순서(후보가 요약과 겹침), P3 시험의 후보 자료 종류를 새 동작에 맞췄다.
