## 왜 하는가

1.3.2의 단계별 시간 기록과 실제 모델 실측(합성 대화)에서 두 가지를 확인했다.

1. **시간은 거의 전부 Codex 호출에서 쓴다.** 조회·대기열·게시는 수십 ms다. 호출마다 모델이 `/work/conversation.jsonl`을 읽기로 정하고 읽는 도구 턴을 먼저 거친다. 큰 입력에서는 읽기를 3~6번 반복하기도 한다.
2. **긴 대화는 가운데가 빠진 채 요약된다(D10 위반).** Codex는 도구 출력을 약 1만 토큰에서 자른다. 800개 대화의 앞·가운데·뒤에 서로 다른 주제를 심자, 파일 방식은 2회 모두 가운데 주제를 빠뜨렸다. 대화를 프롬프트에 직접 넣은 방식은 2회 모두 세 주제를 다뤘다. 운영 로그의 성공 요약 55건 중 40건(73%)이 입력 약 26KB(≈1만 토큰)를 넘었다.
