# 1.1.3a-P2 — 요약 흐름·실패·명령 해석·슬래시 화면·요약 머리말

- 상태: **IN_PROGRESS** · 검사: `T113a-P2-A/B` · 환경: 개발 LXC, 합성(Discord·모델 호출 없음)

## 선행 조건·작업

[P1](01-command-replies.md)의 원격 완료 뒤 [계약](CONTRACT.md)의 묶음 4~13에 이모지 규칙을 적용한다: 시작·진행 중·쿨타임, 빈 범위, 수집 시작·완료·준비 안 됨, 주시 안내, 실패·대기열·종료·입력 과다·미리보기, 명령 해석·추가 요청 200자·범위 한도, `/채널 설정`·`/관리권한 설정` 화면의 안내·요약 줄·선택 안내(버튼은 그대로), 요약 머리말. 화면별 거절 문구를 나눠 `/관리권한 설정` 화면은 그 명령을 안내하게 고치고, `errors.USER_MESSAGES`의 쓰이지 않는 중복 문구를 실제 상수를 가리키게 정리한다.

## 검증·완료 기준

- `T113a-P2-A`: 묶음 4~13의 모든 문구가 계약 규칙대로(줄마다 앞 이모지, 뜻·하오체 유지) 글자 단위로 고정되고, 시작·진행 중 안내의 범위·길이 문구 조합(분·시간·일·주·오늘·개수 × 짧게·길게·자세히), 쿨타임 분·초, 요약 머리말(오늘·이전 날짜·연도·기준 시각 꼬리)이 기대대로다. `/관리권한 설정` 화면의 거절 문구가 그 명령을 안내한다.
- `T113a-P2-B`: 문구 목록 시험이 묶음 1~13 전체를 덮고, 중복 문구가 실제 상수와 같으며, 요약 메시지 나눔·평가 줄 위치·멘션 차단이 그대로다. 전체 회귀 통과.

같은 SHA의 결과를 [증거 양식](../EVIDENCE_TEMPLATE.md)에 남기고 구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 각각 commit·GitHub push·원격 확인한다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
