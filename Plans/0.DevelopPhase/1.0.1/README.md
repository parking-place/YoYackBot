# 1.0.1 — 사용량·요약 밀도·운영 상태 명령

- 상태: **IN_PROGRESS** (P1~P3 완료, P4 진행 중)
- 단계 수: **6단계**
- 선행: [1.0.0a~d 패치 계획](../README.md)의 실제 완료·원격 증거. 현재 출시된 `v1.0.0`의 명령·주시 채널·5분 성공 쿨타임을 후속 버전까지 유지한다.

## 목표와 명령

| 명령 | 의도한 동작 |
|---|---|
| `!!요약좀 사용량` | 봇 전용 계정의 Codex app-server JSON을 읽어 5시간·주간 **남은 비율**과 경고 문구를 표시한다. |
| `!!요약좀 [범위] 자세히` | 앞의 범위(생략 시 기본 1시간)에서 화자별 의견·결정·미해결점을 더 촘촘히 요약한다. 예: `!!요약좀 오늘 자세히` |
| `!!요약좀 [범위] 짧게` | 앞의 범위(생략 시 기본 1시간)의 대화를 본문 5줄 안팎으로 압축한다. 예: `!!요약좀 5시간 짧게` |
| `!!요약좀 상태` | 현재 서버의 주시 채널·캐시 건수와 DB 크기·실제 모델 설정·마지막 요약 시각·봇 상태를 표시한다. |
| `!!요약좀 도움` | 기존 범위 옵션과 네 가지 새 명령을 함께 설명한다. |

요약 시도에서 **실제 계정 사용량 한도 초과가 확인되면** `요약봇 사용량이 정상화되었소.\n초기화의 가호가 함께하길...`를 표시한다. 이 표현은 사용자 확인에 따라 한도 초과 **직후**에 쓰며, 문구의 의미를 임의로 바꾸지 않는다. 일시적 혼잡·인증 오류·시간 초과에는 이 문구를 사용하지 않는다. 자세한 응답·데이터 계약은 [명령 계약](COMMAND_CONTRACT.md)에 있다.

## 공통 완료 규칙

각 P단계는 순서대로 구현·검증하고, **해당 단계의 독립 commit → GitHub push → 원격 반영 및 필요한 CI 확인**을 마쳐야 DONE이다. 제품 검증은 기존 원칙대로 개발 LXC와 합성·시험 Discord에서 수행한다. 로컬 문서 작성이나 계획 게시를 제품 검사 PASS로 세지 않는다. 실계정 한도 소진을 유도하지 않고 합성 JSON·분류 대역으로 경계를 검증한다. 실제 서비스를 건드리는 검사는 단계별로 대상과 영향 범위를 확인한 뒤 진행한다. 8시간·24시간 연속 시험은 앞서 사용자가 생략했으므로 1.0.1 완료 조건에 넣지 않는다.

마지막 단계에서는 앞선 P1~P5의 원격 커밋과 증거, 1.0.1 통합 SHA, 짧은 기능 회귀, 배포·롤백 결과를 남긴다. 공개 태그나 Release는 이 게이트 통과 뒤에만 만든다. 자세한 C/E/D 기록 방식은 [Git 완료 규칙](../GIT_WORKFLOW.md)을 따른다.
