# 1.0.1-P6 — 도움말·통합 회귀·출시

- 상태: **PLANNED** · 검사: `T101-P6-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건과 작업

[P1~P5](STATUS.md)가 각각 별도 원격 커밋·증거와 함께 DONE이어야 한다. `!!요약좀 도움`에 기존 범위 옵션과 `사용량`·`자세히`·`짧게`·`상태`를 설명하고, `자세히`·`짧게`가 기존 범위 뒤에 붙는 모드이며 생략 시 1시간이라는 점과 사용량·상태의 비요약 성격을 분명히 적는다. 설치/운영 문서·변경 기록·버전 값과 저장소 검증기의 1.0.1 집계를 갱신한다. 한도 초과 안내의 사용자 확정 문구 및 `DB 크기`가 공용 파일 크기라는 점을 문서화한다.

운영으로 승격하기 전 정확한 후보 SHA의 테스트·짧은 실제 Discord 확인·업데이트/롤백 리허설을 수행한다. 과거 사용자가 생략한 8시간·24시간 연속 시험은 이 버전의 필수 게이트가 아니다. 실제 시험 채널 게시·한도 소진이 미실행이면 `NOT_RUN` 또는 명시적 생략으로 남기고 합성 결과를 실환경 PASS로 바꾸지 않는다. 1.0.1 태그·Release는 최종 게이트를 통과한 **배포 코드 SHA**에만 만든다.

## 산출물·통과 기준

- `T101-P6-A`: 도움말의 전 명령 예시와 각 명령의 라우팅·주시 경계·오류·쿨타임 회귀가 정확하며, 문서·버전·패키지·증거의 SHA가 대응한다. 실제 모델 품질 검토 결과와 합성 단위 검사를 분리한다.
- `T101-P6-B`: 개발 LXC에서 같은 SHA의 자동 검사와 짧은 운영 점검을 통과하고, 시험 Discord에서 가능한 새 명령 흐름을 확인한다. 배포·복구·제약을 기록하고 P1~P5의 원격 증거를 대조한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

검증 증거와 코드 SHA를 기록하고 이 단계의 독립 commit → GitHub push → 원격 커밋·필요 CI 확인 → STATUS DONE 종료 commit 재push를 마친다. 기본 브랜치 통합 SHA를 기록하고 출시 게이트를 다시 확인한다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
