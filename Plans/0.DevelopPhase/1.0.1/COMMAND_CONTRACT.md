# 1.0.1 명령·데이터 계약

작성 시점의 설계 계약이며 실제 응답·배포 확인은 [검증 목록](TEST_MATRIX.md)에 기록한다.

## 공통 라우팅

- 새 명령은 기존 텍스트 채널의 일반 사용자 메시지만 인식한다. `도움`은 기존처럼 어디서나 읽을 수 있다. `사용량`·`상태`는 주시 채널에서만 응답하고, 미주시 채널은 기존 미주시 안내를 따른다. 자세히·짧게는 기존 요약과 동일한 주시 채널·권한·수집 경계를 따른다.
- `사용량`, `상태`는 **정확한 한 단어 옵션**으로만 인식한다. `자세히`, `짧게`는 **요약 모드 접미사**로, 기존 범위 옵션 **뒤에 한 번만** 붙는다(`[범위] 자세히`/`[범위] 짧게`, 범위 생략 가능). `자세히 2시간`처럼 범위보다 앞에 오거나, 두 모드를 함께 쓰거나, 같은 모드를 반복한 입력은 임의 해석 없이 사용법을 안내한다. 기존 공손 어미(`부탁하오` 등)는 모드 뒤에서도 허용한다. 복수 트리거·도움 우선순위는 기존 계약을 보존한다.
- 사용량·상태·도움은 메시지 수집, 모델 요약, 요약 대기열, **성공 쿨타임**을 사용하거나 갱신하지 않는다. 자세히·짧게는 일반 요약과 같은 채널별 중복 차단·성공 후 5분 쿨타임을 따른다. 모든 전송은 멘션을 비활성화한다.

## Codex 사용량 JSON

공식 [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)의 `account/rateLimits/read`를 사용한다. 봇 전용 계정과 같은 인증으로 app-server를 시작하고 `initialize` → `initialized`를 마친 뒤 JSON-RPC 응답의 **요청 ID에 맞는 `result`**만 읽는다. 다른 알림이나 오류를 사용량으로 오인하지 않는다. app-server의 `stdio`는 줄 단위 JSON이며, WebSocket 전송은 공식 문서상 실험적이다. 현재 서비스의 CLI 고정 버전에서 해당 메서드·응답을 P1에서 실제로 확인한다. `rateLimitResetCredit/consume` 같은 쓰기 메서드는 호출하지 않는다.

`result.rateLimits`의 봇이 사용하는 `codex` 버킷을 기준으로 하되, 응답 형태가 다르면 `rateLimitsByLimitId`에서 **명시적으로 일치하는 버킷**만 선택한다. `primary`/`secondary`의 순서만으로 기간을 추정하지 않고 `windowDurationMins`가 300(5시간)·10080(7일)인 창을 찾는다. 창의 `usedPercent`가 유효한 0~100 숫자일 때 `남은 비율 = 100 - usedPercent`를 **내림**한 정수 %로 표시한다(과대 표시 방지). **응답에 있는 창만 표시한다.** P1-B에서 실제 봇 계정은 주간 창 하나만 반환했으므로(`secondary`=`null`), 사용자 결정(2026-09-29)에 따라 두 창을 모두 요구하지 않는다. 표시할 창이 하나도 없거나, 300·10080이 아닌 길이의 창·같은 길이의 중복 창이 있거나, 값·JSON이 잘못됐으면 라벨을 추측하거나 샘플 숫자를 재사용하지 않고 `Codex 사용량을 지금 확인할 수 없소. 잠시 후 다시 시도하시오.`를 보낸다. 타임아웃·출력 크기 상한·자식 프로세스 정리·인증 파일 권한 검사를 둔다. 원본 JSON, 토큰, 계정 ID와 오류 원문은 Discord나 journal에 남기지 않는다.

경고 경계는 **표시한 창 중 어느 하나라도 남은 비율이 10% 이하**일 때다. 표시한 모든 창이 10% 초과일 때만 넉넉하다는 문구를 쓴다. 정확히 10%는 경고에 포함한다.

```text
Codex의 기운을 살펴보았소.

5시간 한도는 74% 남았소.
주간 한도는 82% 남았소.

아직 요약을 정상화하기엔 넉넉하오.
```

```text
Codex의 기운을 살펴보았소.

5시간 한도는 74% 남았소.
주간 한도는 9% 남았소.

요약 정상화가 버겁기 시작했소.
```

주간 창만 있는 계정의 표시:

```text
Codex의 기운을 살펴보았소.

주간 한도는 82% 남았소.

아직 요약을 정상화하기엔 넉넉하오.
```

`74`, `82`, `9`는 **표시 예시**이며 실시간 값이 아니다. 한도 초과를 확정할 때는 사용량 조회값만 추측하지 않고 모델 시도의 안전하게 분류된 실제 오류를 사용한다. 한도 초과로 요약이 실패한 경우에만 다음 문구를 보낸다. 사용자 원문의 `샤용량`은 오탈자로 보고 `사용량`으로 표기한다. 실패한 요청에는 성공 쿨타임을 걸지 않는다.

```text
요약봇 사용량이 정상화되었소.
초기화의 가호가 함께하길...
```

## 요약 밀도

`자세히`·`짧게`는 앞에 적힌 범위 옵션과 **동일한 범위**를 수집한다(`!!요약좀 3일 자세히`, `!!요약좀 1주 짧게`, `!!요약좀 100개 짧게`). 범위를 생략하면 기본 요약과 같은 최근 1시간이다. 범위 상한·오류 안내, 일반 사용자 대화 선택과 현재 명령 제외 규칙도 기본 요약과 같다. 모드는 수집 범위를 바꾸지 않고 신뢰된 프롬프트 밀도만 바꾼다. 여러 모델 호출로 나누는 긴 범위에서는 최종 통합 출력에 밀도를 적용한다. 빈 대화는 기존 빈 대화 안내를 사용한다.

- `자세히`: 화자별 주된 주장·찬반·정정, 확인된 결정, 실제 미해결 질문을 구분한다. 발언하지 않은 사람에게 의견을 귀속하거나 제안을 결정으로 바꾸지 않는다. 내용이 없으면 빈 항목을 만들지 않는다.
- `짧게`: 모바일 본문 4~6줄을 목표로 하며, 핵심 화자·결정·미해결점 중 실제로 있는 내용만 남긴다. 문장 분리·머리말·Discord 메시지 분할이 발생하면 시각적 총 줄 수는 늘 수 있으므로 검사에서는 **본문 밀도**와 사실성을 함께 평가한다.
- 두 모드는 버전 지정된 신뢰 가능한 프롬프트 선택값이다. Discord 원문 안의 지시로 모드·범위·도구 권한을 변경하지 않는다. 기존 하오체·화자 귀속·출력 분할·보안 경계를 유지한다.

## 상태 표시

```text
📜 현재 형편을 살펴보았소.

상태: 평온하오.
주시 채널: 4곳이오.
캐시된 대화: 12,481건이오.
DB 크기: 18.4 MB이오.
Codex: GPT-6 Luna / Low
마지막 요약: 23분 전이오.
```

수치는 전부 **예시**다. 현재 서버(Guild)의 주시 채널 수와 보존 중인 일반 사용자 캐시 건수를 별도 집계한다. DB 크기는 서비스 SQLite 주 파일과 존재하는 WAL 파일의 바이트 합계를 MB(10진수, 소수 첫째 자리)로 표시한다. 일시적 SHM 파일은 제외한다. `Codex`는 실행 설정의 실제 모델 ID·reasoning 수준을 표시한다. 현재 고정 계약은 `gpt-6-luna / low`이며 사용자 예시의 `GPT-5.6 Luna / Low`를 하드코딩하지 않는다. 마지막 요약은 현재 서버의 주시 채널 가운데 **가장 최근 전체 게시 성공 시각**으로 정의하고, 성공 기록이 없으면 `기록이 없소.`라고 쓴다. 부팅 후 경과 시간이 아니라 지속된 기록을 사용한다.

`평온하오`는 Gateway 준비·DB 읽기·모델 인증 준비가 모두 정상일 때만 쓴다. 한 항목이라도 확인 불가면 `점검이 필요하오.`와 해당 값의 `확인할 수 없소.`를 표시하며 정상 수치를 지어내지 않는다. 상태 조회 실패를 요약 실패나 쿨타임으로 연결하지 않는다. 상태 화면에 다른 서버의 채널 수·대화 건수·원문·식별자·토큰·경로는 노출하지 않는다. DB 크기는 서버 공용 파일 크기라는 점을 도움말과 운영 문서에 밝힌다.
