# 1.0.1-P2 — 사용량 명령·한도 초과 안내

- 상태: **IN_PROGRESS** · 검사: `T101-P2-A/B` · 환경: 개발 LXC, 합성 Discord·실제 시험 채널

## 선행 조건과 작업

[P1](01-app-server-contract.md)의 종료 커밋이 원격에 있어야 한다. `!!요약좀 사용량`을 정확히 라우팅하고 주시 채널에서 app-server 어댑터의 남은 비율을 [명령 계약](COMMAND_CONTRACT.md)의 두 형식으로 표시한다. 한 창이라도 **10% 이하**면 경고, 두 창 모두 **10% 초과**면 넉넉하다는 문구를 쓴다. 조회 실패에는 별도 안내를 사용한다. 사용량 조회는 요약 대기열·모델 실행·성공 쿨타임에 영향을 주지 않는다.

요약 시도(`!!요약좀 5분` 등)에서 **확인된 계정 사용량 한도 초과**를 기존 일반 모델 오류와 분리하고, 사용자 확인을 받은 `요약봇 사용량이 정상화되었소.\n초기화의 가호가 함께하길...`를 초과 직후 보낸다. 일시적 429/서비스 과부하·인증 만료·timeout·모델 부재에는 이 문구를 내지 않는다. 실패 시 성공 쿨타임을 기록하지 않고 채널 잠금을 해제한다.

## 산출물·통과 기준

- `T101-P2-A`: 74/82, 74/9, 10/100, 0/100, 값 누락·오류의 정확한 사용자 문구와 라우팅 우선순위를 합성 응답으로 검증한다. 미주시 채널에서 JSON 조회·모델 호출은 0회다.
- `T101-P2-B`: 합성 한도 초과/일시 429/인증 실패/timeout/정상 성공을 구분하고, 실패 후 재시도 가능·성공 쿨타임 불변·비밀 로그 없음·실제 시험 채널 사용량 명령의 표시를 확인한다. 실제 한도를 소진시키는 시험은 하지 않는다.

검증 증거와 코드 SHA를 기록하고 이 단계만의 commit → GitHub push → 원격 커밋·필요 CI 확인 → STATUS DONE 종료 commit 재push까지 마친다. push가 실패하면 PUSH_PENDING이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
