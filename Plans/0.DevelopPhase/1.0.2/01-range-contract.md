# 1.0.2-P1 — 30일 상한 상속·표시 범위 계약

- 상태: **PLANNED** · 검사: `T102-P1-A/B` · 환경: 개발 LXC, 합성 명령·격리 DB

## 선행 조건·작업

[1.0.0a-P5](../1.0.0a/05-release.md)와 [1.0.1-P6](../1.0.1/06-help-release.md)의 원격 완료를 확인한다. 출시된 1.0.0의 7일 상한은 역사적 기준선이다. [안내 계약](NOTICE_CONTRACT.md)에 따라 선행 1.0.0a의 **30일 SQLite 보존·요청 상한**과 운영의 실효 30일 설정을 검증한다. `10일`·`30일`은 허용하고 `31일`은 수집 전 거부한다. 30일 안의 캐시 공백은 기존 임시 History 보충 경로를 따른다.

파싱한 옵션·기본 범위·1.0.1 요약 모드에서 검증된 표시 범위를 만들고 요청 수명 동안 고정한다. 원문 명령을 표시문에 복사하거나 경과 시간에서 단위를 역산하지 않는다.

## 검증·완료 기준

- `T102-P1-A`: 기본/숫자/분/시간/오늘/일/주/개수와 자세히·짧게의 표시값이 결정적이며 `10일`·`30일` 허용, `31일`·실효 관리자 상한 초과 거부를 확인한다.
- `T102-P1-B`: 격리 DB와 합성 History에서 10일·30일 범위의 캐시 자료와 캐시 공백 보충이 요약 입력에 정확히 들어가고, 30일 이전 자료와 페이지·입력 바이트 상한 초과가 제외되는지 확인한다. 실제 개인 대화는 사용하지 않는다.

같은 SHA의 검사 결과·제약을 [증거 양식](../EVIDENCE_TEMPLATE.md)에 남긴다. 이 단계만의 구현 C, 증거 E, 종료 D를 차례로 commit·GitHub push하고 원격·필요 CI를 확인해야 DONE이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
