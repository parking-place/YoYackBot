# 1.0.2-P1 — 10일 허용·표시 범위 계약

- 상태: **PLANNED** · 검사: `T102-P1-A/B` · 환경: 개발 LXC, 합성 명령·격리 DB

## 선행 조건·작업

[1.0.1-P6](../1.0.1/06-help-release.md)의 원격 완료를 확인한다. 현재 일 단위 기본 상한 7일 때문에 `!!요약좀 10일`이 거부되는 것을 기준선으로 남긴다. [안내 계약](NOTICE_CONTRACT.md)에 따라 일 단위 기본 상한을 28일 범위까지 넓히고 운영 설정에서 실효 상한이 최소 10일인지 확인한다. 상한을 넘는 요청은 기존처럼 수집 전 거부한다. **7일 SQLite 보존 정책은 유지**하며 10일 요청의 오래된 부분은 기존 일시적 History 보충 경로를 따른다.

파싱한 옵션·기본 범위·1.0.1 요약 모드에서 검증된 표시 범위를 만들고 요청 수명 동안 고정한다. 원문 명령을 표시문에 복사하거나 경과 시간에서 단위를 역산하지 않는다.

## 검증·완료 기준

- `T102-P1-A`: 기본/숫자/분/시간/오늘/일/주/개수와 자세히·짧게의 표시값이 결정적이며, `10일` 허용·`28일` 경계 허용·`29일` 거부 및 관리자 상한 7일의 거부를 확인한다.
- `T102-P1-B`: 격리 DB와 합성 History에서 10일 범위의 7일 초과 자료가 요약 입력에는 들어가고 영속 캐시에는 남지 않으며 기존 최대 4주/페이지·입력 바이트 상한을 넘지 않는다. 실제 10일 자료나 개인 대화는 사용하지 않는다.

같은 SHA의 검사 결과·제약을 [증거 양식](../EVIDENCE_TEMPLATE.md)에 남긴다. 이 단계만의 구현 C, 증거 E, 종료 D를 차례로 commit·GitHub push하고 원격·필요 CI를 확인해야 DONE이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
