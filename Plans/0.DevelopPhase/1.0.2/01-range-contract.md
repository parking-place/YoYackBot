# 1.0.2-P1 — 표시 범위·준비 상태 경계 계약

- 상태: **DONE** · 검사: `T102-P1-A/B` · 환경: 개발 LXC, 합성 명령·격리 DB

## 선행 조건·작업

[1.0.1-P6](../1.0.1/06-help-release.md)의 원격 완료(`v1.0.1`)를 확인한다. 30일 상한은 1.0.0a에서 출시·검증됐으므로 새로 구현하지 않고, 운영 설정의 실효값(최대 30일·기본 60분)과 `10일`·`30일` 허용, `31일` 거부를 회귀로만 확인한다.

[안내 계약](NOTICE_CONTRACT.md)의 표에 따라 파싱한 옵션·기본 범위·1.0.1 요약 모드에서 **검증된 표시값**(예: `10일`, `30분`, `오늘`, `최근 100개`, `1시간` + `자세히`)을 만드는 함수를 추가하고 요청 수명 동안 고정한다. 원문 명령을 복사하거나 경과 시간에서 단위를 역산하지 않는다. 시작 안내·진행 중 안내 문장을 만드는 함수도 함께 고정한다.

준비 상태 경계를 코드와 시험으로 고정한다: 초기 수집(`history`/`overlap`), 재시작·연결 끊김 뒤 누락 재확인, 첫 주시 완료 안내 미게시 상태는 모두 **준비 중**이며 요약 시작 안내 대상이 아니다. 준비 완료 판정은 기존 `BackfillState.ready`와 첫 주시 완료 안내 조건을 그대로 쓴다.

## 검증·완료 기준

- `T102-P1-A`: 기본/숫자/분/시간/오늘/일/주/개수 × 모드 없음·자세히·짧게의 표시값과 두 안내 문장이 계약 표와 정확히 일치한다. 기본 범위가 60의 배수가 아닐 때는 분으로 표시한다. `10일`·`30일` 허용, `31일`·낮춘 관리자 상한 초과 거부를 확인한다.
- `T102-P1-B`: 격리 DB의 백필 상태(초기 수집, 누락 재확인, 첫 주시 완료 안내 미게시, 준비 완료)별로 요약 요청이 준비 중 안내 또는 작업 입장 경로로 정확히 나뉜다. 운영 LXC 설정의 실효 최대 일수·기본 범위를 비밀값 없이 기록한다.

같은 SHA의 검사 결과·제약을 [증거 양식](../EVIDENCE_TEMPLATE.md)에 남긴다. 이 단계만의 구현 C, 증거 E, 종료 D를 차례로 commit·GitHub push하고 원격·필요 CI를 확인해야 DONE이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
