# 1.0.2-P3 — 실제 수집 시작 안내

- 상태: **PLANNED** · 검사: `T102-P3-A/B` · 환경: 개발 LXC, 합성 Discord 전송

## 선행 조건·작업

[P2](02-active-scope.md)의 원격 완료 뒤 요약 요청이 주시·권한·옵션·채널 상태 검사를 통과하면, 첫 `collect` 호출 직전에 한 번 안내한다. `!!요약좀 10일`의 문구는 정확히 `10일 채팅을 요약해보겠소.`이다. 전송 성공 후 수집을 시작하며, 전송 실패에는 수집·모델 호출 없이 활성 상태를 해제한다. 사용자에게 안내만 보인 뒤 수집이 실패했다면 기존 안전한 실패 안내를 별도로 보낸다.

미주시/접근 불가·잘못된 옵션·기존 진행 작업·성공 쿨타임·서비스 종료에는 시작 안내를 내지 않는다. 빈 대화의 경우에는 수집 시작 안내 후 기존 빈 대화 안내가 따라올 수 있다. 안내는 요약 게시나 성공 쿨타임으로 세지 않는다. 모든 전송에서 멘션을 비활성화한다.

## 검증·완료 기준

- `T102-P3-A`: 승인된 10일 요청에서 시작 안내가 수집 전에 정확히 한 번 나오고, 빈 범위·수집 실패에서도 순서와 기존 후속 안내가 맞다. 다른 단위·기본 범위·1.0.1 요약 모드의 문구도 검증된 범위를 사용한다.
- `T102-P3-B`: 미주시·권한 변경·잘못된 옵션·쿨타임·종료·전송 실패에서 허위 시작 안내 또는 History/모델 실행이 없고, 실패 뒤 재시도가 가능하다. 안내문에 원문·멘션·식별자가 섞이지 않는다.

같은 SHA의 검사·제약을 기록하고 이 단계의 구현 C → 증거 E → 종료 D를 독립 commit·GitHub push·원격/필요 CI 확인까지 마쳐야 DONE이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
