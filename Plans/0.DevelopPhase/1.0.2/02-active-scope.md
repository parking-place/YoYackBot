# 1.0.2-P2 — 진행 중 요청 범위의 원자적 보관

- 상태: **PLANNED** · 검사: `T102-P2-A/B` · 환경: 개발 LXC, 합성 동시 요청

## 선행 조건·작업

[P1](01-range-contract.md)의 종료 D가 원격에 있어야 한다. 현재 `ChannelStates`는 활성 Guild·채널 **집합만** 보관하므로 중복 요청에 원래 범위를 알려줄 수 없다. 입장 시 검증된 표시 범위와 요약 모드를 함께 원자적으로 저장하고, BUSY 응답에는 활성 작업의 불변 스냅샷을 돌려준다. 중복 요청의 옵션은 활성 범위를 바꾸지 못한다. 시작 안내가 전송 중인 상태도 구분해 같은 채널의 응답 순서를 지킬 수 있게 한다.

성공 게시·빈 결과·수집/모델/게시 실패·취소·권한 해제·서비스 종료에서 작업과 범위를 함께 제거한다. 기존 성공 쿨타임은 성공 게시 뒤에만 기록한다. DB에 진행 중 범위나 Discord 원문을 영속화하지 않는다.

## 검증·완료 기준

- `T102-P2-A`: 동일 Guild·채널 동시 20건 중 한 건만 ACCEPTED이고 나머지 BUSY는 **첫 요청의** 범위를 받는다. 다른 채널·Guild는 서로의 범위를 보지 않으며 잠금 경쟁에서 빈/옛 범위가 나오지 않는다.
- `T102-P2-B`: 정상·빈 결과·각 단계 실패·취소·재시작·주시 해제 뒤 활성 범위가 남지 않는다. 성공 쿨타임·전역 대기열·다른 채널 동시 실행의 기존 계약을 유지한다.

같은 SHA의 검사 결과를 기록하고 구현 C → 증거 E → 종료 D의 각 commit·GitHub push·원격/필요 CI 확인을 끝내야 DONE이다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
