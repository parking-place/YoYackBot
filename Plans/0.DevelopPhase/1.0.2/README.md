# 1.0.2 — 요약 시작·진행 중 범위 안내

- 상태: **IN_PROGRESS** (P1~P3 완료, P4 재개)
- 단계 수: **5단계**
- 선행 버전: 출시된 [1.0.0a~d](../README.md)와 [1.0.1](../1.0.1/README.md)(`v1.0.1`, 2026-09-29). 1.0.0a~d는 이 계획이 처음 작성된 뒤 추가됐으므로 2026-09-29에 현재 코드 기준으로 다시 검토했다.

## 목표

준비 완료된 주시 채널에서 요약 작업에 들어간 **모든** `!!요약좀` 요청에 요청 범위를 한 번 안내한다. 초기 수집이나 누락 재확인 중인 채널에는 지금처럼 준비 중 안내만 보낸다. 같은 채널에 요약이 진행 중일 때 들어온 요약 요청에는 새 요청의 범위가 아니라 **이미 진행 중인 작업의 범위**를 알려준다.

```text
!!요약좀 10일
10일 채팅을 요약해보겠소.
```

```text
현재 10일 분 채팅을 요약중이오.
참을성을 가져보시오.
```

## 재검토로 바뀐 점

- **선행 조건**: 1.0.0a의 30일 상한과 1.0.1은 이미 출시됐다. 운영 실효값(최대 30일, 기본 60분)도 확인했으므로 P1은 “30일 상한 상속”이 아니라 **표시 범위와 준비 상태 경계를 고정하는 단계**로 바꿨다.
- **‘수집’의 의미**: 1.0.0b-1 이후 요약은 요청마다 Discord History를 조회하지 않고 캐시만 읽는다. 옛 계획의 “수집 시작 안내·캐시 공백 History 보충”은 “요약 시작 안내·준비 완료 채널의 캐시 조회”로 바꿨다. 채널 단위의 **초기 수집·누락 재확인**은 기존 준비 중 안내가 담당한다.
- **1.0.1 모드**: `자세히`·`짧게`를 표시값과 안내 문구에 포함한다. `사용량`·`상태`·`도움`은 안내 대상이 아니다.
- **문구 정리**: 단위별 진행 중 문구를 표로 확정했다([안내 계약](NOTICE_CONTRACT.md)).

[응답·상태 계약](NOTICE_CONTRACT.md)에 요청 상태별 응답표, 문구, 예외, 중복 요청 경계를 적었다.

## 검증 방침

- 안내 문구·상태 전이는 모델 없이 합성 대역으로 검증한다. 이 버전은 프롬프트를 바꾸지 않으므로 실제 모델 평가를 요구하지 않는다(봇 계정 한도 절약).
- 실제 시험 Discord 확인은 1.0.1과 같이 **P5 배포 뒤 사용자가 직접 입력**한다. 확인하지 못하면 `NOT_RUN`으로 남긴다.
- 사용자가 앞서 생략한 8시간·24시간 연속 시험은 필수 게이트가 아니다. 제품 태그·Release는 배포 코드가 최종 게이트를 통과한 뒤에만 만든다.
