# 1.0.2 안내 문구·진행 상태 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 2026-09-29에 출시된 `v1.0.1`(1.0.0a~d 포함) 코드 기준으로 다시 검토했다.

## 현재 기준선

- **수집 방식**: 1.0.0b-1부터 요약은 요청마다 Discord History를 조회하지 않는다. 채널을 처음 주시하면 최근 30일을 한 번 **초기 수집**하고, 재시작·연결 끊김 뒤에는 준비된 채널의 누락 구간을 **재확인**한다. 이 두 작업이 끝난 채널(`준비 완료`)의 요약은 SQLite 캐시만 읽는다.
- **준비 중 안내**: 초기 수집 또는 누락 재확인 중인 채널의 요약 요청에는 이미 `참을성을 기르시오 아직 준비가 되지 않았소.`를 보내고 요약 작업을 시작하지 않는다.
- **범위 상한**: 1.0.0a의 30일 보존·요청 상한은 출시돼 있고 운영 LXC의 실효값도 `YOYACK_MAX_DAYS` 기본 30, `YOYACK_DEFAULT_MINUTES` 기본 60이다(설정 파일에서 덮어쓰지 않음, 2026-09-29 확인). `10일`·`30일`은 허용되고 `31일`은 거부된다.
- **1.0.1 명령**: `[범위] 자세히`/`[범위] 짧게`는 요약 모드, `사용량`·`상태`·`도움`은 요약이 아닌 명령이다.
- **현재 진행 중 응답**: 같은 채널에 요약이 진행 중이면 범위 없이 `요약중이오. 좀 기다리시오.`만 보낸다. `ChannelStates`는 활성 Guild·채널 집합만 보관한다.

## 요청 상태별 응답 (핵심 규칙)

**준비 완료 채널에서 요약 작업에 들어간 모든 `!!요약좀` 요청은 요약 시작 안내를 받는다.** 초기 수집·재확인 중인 채널에서만 시작 안내 대신 기존 준비 중 안내를 쓴다.

| 요청 시점의 채널 상태 | 응답 | 시작 안내 |
|---|---|---|
| 미주시·설정 확인 실패 | 기존 미주시/설정 확인 실패 안내 | 없음 |
| 초기 수집 또는 누락 재확인 중 | 기존 `참을성을 기르시오 아직 준비가 되지 않았소.` | 없음 |
| 준비 완료, 옵션 오류·상한 초과 | 기존 사용법/상한 안내 | 없음 |
| 준비 완료, 같은 채널 요약 진행 중 | [진행 중 안내](#진행-중-안내) | 없음 |
| 준비 완료, 성공 쿨타임 중 | 기존 쿨타임 안내 | 없음 |
| 준비 완료, 서비스 종료 중 | 기존 종료 안내 | 없음 |
| **준비 완료, 요약 작업 입장 성공** | **시작 안내** → 요약 게시 / 빈 대화 / 실패 안내 | **1회** |

판정 순서는 현재 코드와 같다: 주시 확인 → 준비 상태 확인 → 옵션 해석 → 채널 입장(진행 중·쿨타임) → 시작 안내 → DB 조회. 진행 중인 작업이 있는 채널이 재확인 상태로 바뀌면 다음 요청은 준비 중 안내를 받는다(준비 상태 확인이 먼저다).

## 요약 시작 안내

채널 입장이 성공하고 **준비 완료를 다시 확인한 직후, 캐시 조회 직전**에 한 번 게시한다. 게시 전 재확인에서 준비 완료가 아니면 시작 안내 없이 준비 중 안내를 보내고 입장을 해제한다. 안내 전송이 실패하면 조회·모델 호출·게시를 시작하지 않고 입장을 해제한다(쿨타임 없음, 즉시 재시도 가능). 안내는 요약 성공이나 5분 쿨타임으로 계산하지 않는다.

```text
!!요약좀 10일
10일 채팅을 요약해보겠소.
```

시작 안내 뒤에는 기존 결과가 이어진다: 요약 게시, `요약할 만한 대화가 없소.` 같은 빈 대화 안내, 모델 대기열 포화·대기 시간 초과, 입력 과다, 모델 실패, 확인된 한도 초과(`요약봇 사용량이 정상화되었소.`), 권한·주시 변경 중단. 조회 중에 준비 상태가 바뀌어 기존 경로가 준비 중 안내를 보내는 경우도 시작 안내 뒤에 올 수 있다.

## 진행 중 안내

같은 Guild·채널에 이미 입장한 **첫 요청**이 시작 안내 전송, 캐시 조회, 모델 대기, 모델 실행, 게시 중 어느 단계에 있든 다음 요약 요청에는 아래 두 줄을 보낸다. 새 요청의 범위·모드는 보여주지 않는다. 중복 요청은 조회·모델·게시·쿨타임 갱신을 하지 않는다.

```text
현재 10일 분 채팅을 요약중이오.
참을성을 가져보시오.
```

활성 범위는 **검증된 옵션에서 만든 표시값과 모드**를 입장과 동시에 원자적으로 저장한다(메모리, DB 비영속). Discord 원문을 다시 출력하지 않고 다른 Guild·채널의 범위를 누설하지 않는다. 성공·빈 대화·실패·취소·종료·권한/주시 해제에서 함께 지우며, 재시작 뒤 유령 작업으로 남지 않는다. 첫 요청의 시작 안내가 아직 전송 중이면 중복 안내는 그 전송이 끝난 뒤에 보낸다. 시작 안내 전송이 실패해 입장이 해제됐다면 기다리던 중복 요청은 진행 중 안내 대신 일반 요청으로 다시 판정한다.

## 범위 표시 기준

표시값은 요청이 확정된 순간의 파싱 결과·설정에서 만들고 작업 종료까지 유지한다. 자정/DST/설정 변경 뒤 시간 차이로 단위를 역산하거나(`10일`→`240시간`), 뒤에 온 요청의 옵션으로 덮어쓰지 않는다. 숫자·단위·모드는 검증된 값만 조합한다. 모든 안내는 멘션을 비활성화한다.

| 요청 예 | 표시 범위 | 시작 안내 | 진행 중 안내 첫 줄 |
|---|---|---|---|
| `!!요약좀` | 기본 범위(현행 60분 → `1시간`) | `1시간 채팅을 요약해보겠소.` | `현재 1시간 분 채팅을 요약중이오.` |
| `!!요약좀 3` | `3시간` | `3시간 채팅을 요약해보겠소.` | `현재 3시간 분 채팅을 요약중이오.` |
| `!!요약좀 30분` | `30분` | `30분 채팅을 요약해보겠소.` | `현재 30분간의 채팅을 요약중이오.` |
| `!!요약좀 10일` | `10일` | `10일 채팅을 요약해보겠소.` | `현재 10일 분 채팅을 요약중이오.` |
| `!!요약좀 1주` | `1주` | `1주 채팅을 요약해보겠소.` | `현재 1주 분 채팅을 요약중이오.` |
| `!!요약좀 오늘` | `오늘` | `오늘 채팅을 요약해보겠소.` | `현재 오늘 채팅을 요약중이오.` |
| `!!요약좀 100개` | `최근 100개` | `최근 100개 채팅을 요약해보겠소.` | `현재 최근 100개 채팅을 요약중이오.` |
| `!!요약좀 자세히` | `1시간` + 자세히 | `1시간 채팅을 자세히 요약해보겠소.` | `현재 1시간 분 채팅을 자세히 요약중이오.` |
| `!!요약좀 5시간 짧게` | `5시간` + 짧게 | `5시간 채팅을 짧게 요약해보겠소.` | `현재 5시간 분 채팅을 짧게 요약중이오.` |

규칙: 시간·일·주는 `N단위 분`, 분은 `N분간의`, 오늘은 `오늘`, 개수는 `최근 N개`를 쓴다. 기본 범위는 `YOYACK_DEFAULT_MINUTES`가 60의 배수면 시간, 아니면 분으로 표시한다. 모드는 `요약` 앞에 `자세히 `/`짧게 `를 넣는다. 진행 중 안내의 둘째 줄은 항상 `참을성을 가져보시오.`다.

## 유지할 동작

동일 채널 단일 작업, 다른 채널 독립 처리, 전역 모델 대기열(동시 4·대기 8·600초), 성공 후 5분 쿨타임, 빈 대화·실패 안내, 명령 제외 규칙, 초기 수집 시작·완료 안내(1.0.0b-1)를 유지한다. `사용량`·`상태`·`도움`은 진행 중에도 바로 응답하며 시작·진행 중 안내 대상이 아니다.
