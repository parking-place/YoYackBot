# 1.0.2 안내 문구·진행 상태 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다.

## 수집 시작 안내

같은 Guild·채널의 주시 및 권한 확인, 옵션 검증, 채널별 요약 작업 입장을 모두 통과한 뒤 **첫 수집 호출 직전**에 한 번만 게시한다. 안내 전송이 실패하면 수집·모델 호출·게시를 시작하지 않고 작업 점유를 해제한다. 이미 진행 중인 요청, 성공 쿨타임, 잘못된 옵션, 미주시/접근 불가 채널, 종료 중인 서비스에는 시작 안내를 보내지 않는다. 빈 범위도 수집을 시도한 경우에는 시작 안내 후 기존 빈 대화 안내를 보낼 수 있다. 안내는 요약 성공이나 5분 쿨타임으로 계산하지 않는다.

```text
10일 채팅을 요약해보겠소.
```

`!!요약좀 10일`은 실제 설정에서 허용되어야 위 안내까지 도달한다. 선행 1.0.0a에서 설정한 기본·최대 30일 상한과 30일 영속 캐시를 1.0.2가 상속한다. 운영 설정이 더 낮다면 기존 범위 제한 안내를 보내고 범위를 거짓으로 말하지 않는다. P1에서 실효 30일 상한과 `30일` 허용·`31일` 거부를 확인한다.

## 진행 중 안내

같은 Guild·채널에 이미 입장한 **첫 요청**이 수집, 모델 대기, 모델 실행, 게시 중이면 두 번째 요약 요청에는 아래 두 줄을 보낸다. 두 번째 요청의 `5분` 옵션을 보여주지 않는다. 중복 요청은 History·DB 수집·모델·요약 게시·쿨타임 갱신을 하지 않는다.

```text
현재 10일 분 채팅을 요약중이오.
참을성을 가져보시오.
```

활성 범위는 **검증된 옵션에서 생성한 짧은 표시값**(`10일`)을 입장과 동시에 원자적으로 저장한다. Discord 원문 전체를 다시 출력하지 않는다. 다른 Guild나 채널의 범위를 누설하지 않는다. 진행 상태와 범위는 성공·빈 대화·실패·취소·종료·권한/주시 해제에서 함께 지우며, 재시작 뒤 유령 작업으로 남기지 않는다. 첫 시작 안내가 아직 전송 중이어도 중복 안내가 이를 추월하지 않도록 같은 채널의 안내 순서를 보장한다. 첫 안내 실패 시 중복 요청을 실제 진행 중으로 잘못 답하지 않게 상태를 재확인한다.

## 범위 표시 기준

| 요청 예 | 표시 범위 | 시작 안내 예 |
|---|---|---|
| `!!요약좀` | 설정상 기본 범위(현행 1시간) | `1시간 채팅을 요약해보겠소.` |
| `!!요약좀 3` | `3시간` | `3시간 채팅을 요약해보겠소.` |
| `!!요약좀 30분` | `30분` | `30분 채팅을 요약해보겠소.` |
| `!!요약좀 10일` | `10일` | `10일 채팅을 요약해보겠소.` |
| `!!요약좀 1주` | `1주` | `1주 채팅을 요약해보겠소.` |
| `!!요약좀 오늘` | `오늘` | `오늘 채팅을 요약해보겠소.` |
| `!!요약좀 100개` | `최근 100개` | `최근 100개 채팅을 요약해보겠소.` |
| `!!요약좀 자세히` | 기본 1시간 + 자세히 | `1시간 채팅을 자세히 요약해보겠소.` |
| `!!요약좀 짧게` | 기본 1시간 + 짧게 | `1시간 채팅을 짧게 요약해보겠소.` |

다른 단위의 중복 안내는 한국어에 맞게 `현재 30분간의 채팅을 요약중이오.`, `현재 오늘 채팅을 요약중이오.`, `현재 최근 100개 채팅을 요약중이오.`처럼 표시한다. `자세히`·`짧게`는 활성 작업의 모드도 유지해 `현재 1시간 채팅을 자세히 요약중이오.`처럼 답한다. 모든 중복 안내의 둘째 줄은 `참을성을 가져보시오.`로 고정한다.

표시값은 요청이 확정된 순간의 파싱 결과·설정에서 만들고 작업 종료까지 유지한다. 자정/DST/설정 변경 후 단순 시간 차이를 역산해 `10일`을 `240시간`으로 바꾸거나, 뒤에 온 요청의 옵션으로 표시를 덮어쓰지 않는다. 숫자·단위·모드는 검증된 값만 조합하며 사용자 입력의 멘션·Markdown을 그대로 삽입하지 않는다. 모든 Discord 안내는 멘션을 비활성화한다.

## 유지할 동작

기존 동일 채널 단일 작업, 다른 채널 독립 처리, 전역 모델 대기열, 성공 후 5분 쿨타임, 빈 대화·실패 안내, 명령 제외 수집 규칙을 유지한다. 1.0.1의 `사용량`·`상태`·`도움` 같은 비요약 명령은 진행 중에도 접근 가능하며 새 시작/중복 안내 대상이 아니다. 선행 1.0.0a의 영속 캐시 보존·요청 상한은 최대 30일이며 캐시 공백만 기존 임시 History 조회로 보충한다.
