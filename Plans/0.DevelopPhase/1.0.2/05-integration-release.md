# 1.0.2-P5 — 도움말·통합 회귀·출시 게이트

- 상태: **IN_PROGRESS** · 검사: `T102-P5-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P4](STATUS.md)의 독립 원격 완료를 확인한다. `!!요약좀 도움`과 운영 문서에 요약 시작·진행 중 안내와, 채널이 초기 수집·누락 재확인 중이면 준비 중 안내가 먼저 나온다는 점을 적는다. 1.0.1 명령 설명과 최대 30일 정책은 유지한다. 패키지·`VERSION`을 `1.0.2`로, [버전 대응표](../PATCH_VERSIONING.md)에 `1.0.2` 행을 추가하고, 저장소 검증기에 1.0.2의 5단계·10검사 집계를 넣는다. `CHANGELOG`·README·`docs/upgrade-rollback-1.0.2.md`(복귀 대상 `v1.0.1`, schema 변경 없음 확인)를 갱신한다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 1.0.1과 같은 절차(DB 온라인 백업·설정 백업·wheel 설치·checkout 일치·`check-ready`·health·DB 무결성)로 개발 LXC 서비스에 배포한다. 이전 `v1.0.1` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 주시 시험 채널에서 직접 확인한다: 준비 완료 채널의 `!!요약좀 10일`(시작 안내 → 요약), 진행 중 `!!요약좀 5분`(진행 중 안내 두 줄), `자세히`/`짧게` 시작 안내, 쿨타임 중 요청(시작 안내 없음). 봇 계정 한도를 아끼도록 실제 요약은 최소 건수로 한다. 확인하지 못한 항목은 `NOT_RUN`으로 기록하고 합성 시험으로 대체해 PASS라 부르지 않는다. 8시간·24시간 연속 시험은 요구하지 않는다.

## 검증·완료 기준

- `T102-P5-A`: 범위 옵션·1.0.1 명령·준비 상태 경계·주시 경계·명령 제외·빈 결과·중복·전역 대기열·성공 쿨타임·장문 분할의 회귀와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T102-P5-B`: 개발 LXC 후보 SHA와 실제 서비스 SHA를 대조하고, 시험 Discord에서 시작/진행 중 문구·순서를 사용자 확인과 서비스 로그로 대조하며, 배포·복귀·비밀정보 비노출·P1~P4 원격 증거를 기록한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

이 단계의 구현 C → 증거 E → 종료 D를 독립 commit·GitHub push·원격/필요 CI 확인까지 마친 뒤, `main`으로 PR·리뷰·병합하고 통합 SHA를 기록한다. 제품 태그 `v1.0.2`와 Release는 **배포 코드 SHA의** 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
