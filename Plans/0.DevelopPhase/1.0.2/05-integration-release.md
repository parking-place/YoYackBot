# 1.0.2-P5 — 도움말·통합 회귀·출시 게이트

- 상태: **PLANNED** · 검사: `T102-P5-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P4](STATUS.md)의 독립 원격 완료를 확인한다. `!!요약좀 도움`과 운영 문서에 수집 시작·진행 중 안내, `10일` 예시와 **최대 30일** 정책, 30일 캐시와 캐시 공백의 History 임시 조회를 적는다. 1.0.1의 새 명령 설명도 유지한다. 버전·패키지·검증기와 업데이트/롤백 절차를 1.0.2에 맞추고, 운영 설정에서 실효 `YOYACK_MAX_DAYS = 30`을 확인한다.

정확한 후보 SHA로 LXC 자동 회귀와 짧은 시험 Discord 점검을 진행한다. 주시 시험 채널의 합성 대화만 사용해 `10일` 시작 안내와 진행 중 중복 안내의 게시 순서를 관찰한다. 실제 게시를 확인하지 못하면 그 항목은 `NOT_RUN`으로 기록하고 합성 시험으로 대체해 PASS라 부르지 않는다. 기존 사용자가 생략한 8시간·24시간 연속 시험은 요구하지 않는다.

## 검증·완료 기준

- `T102-P5-A`: 범위 옵션·1.0.1 명령·주시 경계·명령 제외·빈 결과·중복·전역 대기열·성공 쿨타임·장문 분할의 회귀와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T102-P5-B`: 개발 LXC 후보 SHA와 실제 서비스 SHA를 대조하고, 시험 Discord에서 시작/중복 문구·순서를 확인하며, 배포·롤백·비밀정보 비노출·P1~P4 원격 증거를 기록한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

이 단계의 구현 C → 증거 E → 종료 D를 독립 commit·GitHub push·원격/필요 CI 확인까지 마친 뒤 기본 브랜치 통합 SHA를 기록한다. 제품 태그와 Release는 **배포 코드 SHA의** 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
