## 실행 환경

- 제공 환경: OpenJevLXC, 4 vCPU / 8 GB RAM / 32 GB 디스크. 제공값이며 남은 자원·OS·설치 상태는 미검증이다.
- 봇 런타임, SQLite, Codex CLI의 실제 검증 대상은 해당 Linux LXC다. 공유 서비스 유무와 자원 사용량을 먼저 확인한다.
- 접속 주소·계정·SSH 키 위치는 로컬 비공개 자료에서만 확인한다. 원격 명령과 로그를 문서에 복사할 때 값은 제거한다.
- 로컬은 문서·코드 작성과 문서 구조 점검에 사용한다. 본 로드맵은 제품 실행 검증을 LXC에 모으는 방식을 제안한다. 이 프로젝트에 별도 사용자 지시로 확정된 로컬 테스트 금지 규칙이 있다는 뜻은 아니다.
- GitHub CI는 초기에는 비밀정보 없는 문서·정적 검사에 사용한다. Discord/Codex 실제 인증값이나 운영 DB를 공개 CI에 주입하지 않는다.
- 개발용 Discord 서버/채널과 격리된 테스트 DB를 사용한다. 기존 서비스·운영 데이터·인증 파일을 덮어쓰지 않는다.

## 구현 기준안

- Python + 비동기 Discord SDK + SQLite + Codex CLI subprocess를 우선 검토한다. 언어·SDK·런타임의 정확한 버전은 0.0.0-P2에서 호환성을 확인하고 잠금 파일로 고정한다.
- 구성요소: 설정 / Discord gateway·채널 설정 / 명령 파서 / 메시지 저장소 / 수집 범위 계산 / History 수집 / 입력 파일 / Codex 실행 / 출력 / 작업 상태 / 운영 계층.
- 봇은 전용 비특권 계정으로 실행한다. 제공된 LXC의 권한 설정과 봇 프로세스 권한은 구분한다.
- Codex subprocess에는 Discord 토큰, SSH 키, 운영 DB, 프로젝트 디렉터리 접근권을 넘기지 않는다. 요청별 입력 디렉터리와 필요한 인증 경로만 분리한다.
- 전역 Codex 동시 실행 1개를 초기 제안값으로 사용한다. 채널별 잠금과 유한 대기열을 함께 둔다. 0.8.0에서 실측해 조정한다.
- 실행 파일 버전, 구성 식별자, 테스트 대상 Git SHA, OS·CPU 아키텍처를 검증 증거에 기록한다.

## 검증되지 않은 선행 조건

LXC 접속 가능 여부, OS 지원 상태, Python/SDK/Codex 설치, 계정 인증·사용 한도, Discord 권한·Message Content 접근, 디스크 여유, systemd 사용 가능 여부는 개발 단계에서 확인한다. 이번 계획 작성으로 충족된 것으로 표시하지 않는다.

명세의 `GPT-6 Luna Light` 요구는 유지한다. [설계 결정](DECISIONS.md)의 D03에 따라 모델 ID·reasoning 설정·계정 허용 여부를 검증해야 한다.
