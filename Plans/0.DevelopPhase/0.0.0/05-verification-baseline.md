# 0.0.0-P5 — 검증 실행 기반·초기 버전 게이트

- 상태: **PUSH_PENDING**
- 명세 근거: §39, §52–53
- 검증 ID: `T000-P5-A`, `T000-P5-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.0.0-P4](../0.0.0/04-interfaces-config.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. LXC에서 lint·타입·단위 검사를 재현할 runner와 합성 fixture를 준비하고 비밀정보 없는 문서/정적 CI 범위를 정한다.
2. TEST_MATRIX와 증거 양식에 실제 실행 명령·환경·SHA를 기록하는 절차를 연결한다.
3. 0.0.0 산출물 회귀 검증, 문서 링크/비밀정보 검사, 원격 커밋 확인을 마치고 버전 브랜치를 검토·통합한다.

## 산출물

검사 실행 지침, 합성 fixture, 초기 CI 구성, 0.0.0 검증 증거.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T000-P5-A`: 새 LXC 작업 디렉터리에서 같은 SHA의 기초 검사가 재현되고 의도적인 실패가 검사 실패로 표시된다.
- [x] `T000-P5-B`: 초기 CI가 실제 Discord/Codex 비밀값 없이 동작하며, 선행 4단계의 원격 증거를 확인한다. 현재 단계 업로드와 버전 통합은 G-PUSH에서 확인한다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.1.0-P1](../0.1.0/01-gateway.md).
