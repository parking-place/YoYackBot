# 0.0.0-P4 — 설정·인터페이스·오류 계약 정의

- 상태: **PLANNED**
- 명세 근거: §4, §10–13, §30, §43, §51–52
- 검증 ID: `T000-P4-A`, `T000-P4-B`
- 검증 환경: **MOCK** — LXC의 합성 데이터·대역 기반 단위/통합 검사. 실제 Discord/모델 검증과 구분한다.

## 선행 조건

[0.0.0-P3](../0.0.0/03-environment-preflight.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. MessageRecord, RangeRequest, Coverage, SummaryRequest/Result와 어댑터 경계를 정의해 Discord·DB·CLI를 교체 가능한 구조로 만든다.
2. 명세 §51의 모든 설정을 분리하고 기본값·허용 범위·변경 시점·비밀 여부를 명시한다. 시간/주 단위 상한은 서로 독립적으로 검증한다.
3. 사용자용 하오체 오류 코드와 내부 오류 분류를 나누고 UTC 저장·KST 출력·전송 성공 계약을 정한다.

## 산출물

인터페이스/설정 명세, 값 없는 환경 예시, 오류 분류표.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T000-P4-A`: 합성 어댑터가 같은 요청/응답 계약을 따르고 잘못된 설정은 시작 전에 거부된다.
- [ ] `T000-P4-B`: Discord 사용자 응답에 경로·예외 stack·인증값이 섞이지 않는 오류 매핑을 확인한다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.
