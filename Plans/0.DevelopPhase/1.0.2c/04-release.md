# 1.0.2c-P4 — 통합·배포·출시

- 상태: **PLANNED** · 검사: `T102c-P4-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P3](STATUS.md)의 원격 완료를 확인한다. 패키지·`VERSION`을 `1.0.2.2`로, 저장소 검증기에 1.0.2c의 4단계·8검사 집계를 넣는다. `CHANGELOG`·README·`docs/upgrade-rollback-1.0.2c.md`(복귀 대상 `v1.0.2b`, schema 변경 없음, 복귀 시 쿨타임이 다시 5분이 된다는 점)를 갱신한다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤 이전과 같은 절차(DB 온라인 백업·설정 백업·wheel 설치·checkout 일치·`check-ready`·health·DB 무결성)로 배포한다. 이전 `v1.0.2b` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 채널에서 직접 확인한다: 요약 1건의 말투(천박한 몸통·하오체 말끝·사실 정확성), 성공 직후 같은 채널 재요청의 `01분 00초` 이하 안내, 1분 뒤 재요청 입장. 계정 한도를 아끼도록 실제 요약은 최소 건수로 한다. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T102c-P4-A`: 전체 회귀(범위·모드·사용량·상태·채널·시작/진행 중 안내·준비 상태·쿨타임 1분)와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T102c-P4-B`: 후보 SHA와 서비스 SHA를 대조하고, 시험 Discord 결과를 사용자 확인과 서비스 로그(성공·`cooldown` 결과)로 대조하며, 배포·복귀·비밀정보 비노출·P1~P3 원격 증거를 기록한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합하고 병합 후 `main` CI 결과를 확인해 기록한다. 태그 `v1.0.2c`와 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
