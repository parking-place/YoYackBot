# 0.3.0-P4 — 완료 구간·빈 구간·연결 공백

- 상태: **PUSH_PENDING**
- 명세 근거: §4-6–4-7, §13-5–13-9
- 검증 ID: `T030-P4-A`, `T030-P4-B`
- 검증 환경: **MOCK** — LXC의 합성 데이터·대역 기반 단위/통합 검사. 실제 Discord/모델 검증과 구분한다.

## 선행 조건

[0.3.0-P3](../0.3.0/03-edits-retention.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 겹치거나 인접한 완료 구간의 병합·조회·차집합을 구현한다. 메시지 min/max만으로 완료를 추정하지 않는다.
2. History adapter가 끝까지 조회했다는 완료 신호와 메시지 upsert를 원자적으로 적용하는 계약을 만든다.
3. 재시작·gateway 중단·주시 해제 구간을 미완료로 관리한다. 오프라인 수정/삭제에 대한 재확인 필요를 별도로 표시한다.

## 산출물

coverage 연산, 수집 완료 commit 계약, gap 추적.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T030-P4-A`: 빈 구간·다중 구간·포함·인접·부분 겹침·TTL 절단에서 정확한 미수집 구간이 나온다.
- [x] `T030-P4-B`: 중간 페이지 실패나 연결 공백은 완료 범위로 승격되지 않고 X개 존재만으로 최신성 충족으로 판정하지 않는다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.3.0-P5](../0.3.0/05-cache-acceptance.md).
