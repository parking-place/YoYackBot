# 0.3.0-P5 — 캐시 동시성·장애·버전 검증

- 상태: **DONE**
- 명세 근거: §13-1–13-13, §53 SQLite 캐시
- 검증 ID: `T030-P5-A`, `T030-P5-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.3.0-P4](../0.3.0/04-coverage.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 수집·수정·조회·정리 동시 접근에 대한 트랜잭션, busy timeout, 재시도 한도를 검증한다.
2. DB 잠금·읽기 전용·디스크 부족·손상 오류를 분류하고 0.4.0 fallback에 전달할 계약을 검증한다.
3. 설정 보존과 전체 캐시 회귀 결과를 정리하고 각 단계 push 이후 버전 통합 증거를 남긴다.

## 산출물

캐시 통합 시험, 오류 분류, DB 운영 초안.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T030-P5-A`: 격리 DB에서 동시 이벤트와 TTL 정리 후 중복·채널 혼합·잘못된 coverage가 없다.
- [x] `T030-P5-B`: 장애가 이벤트 루프를 무한 차단하지 않고 원문/인증값 없는 진단과 복구 가능한 실패를 반환한다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [x] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [x] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [x] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [x] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [x] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.
