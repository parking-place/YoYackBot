# 1.3.2-P1 — 단계별 시간 기록

- 상태: **PUSH_PENDING** · 검사: `T132-P1-A/B` **PASS** ([증거](../evidence/1.3.2-P1.md)) · 환경: 개발 LXC, 합성 대역(모델 호출 없음)

## 작업

[개요](README.md)의 단계를 기록하는 `timing` 모듈을 만든다. 명령을 받은 Discord 이벤트에서 시작한 기록을 workflow·엔진·Codex 실행기까지 요청 단위로 넘긴다(요청 task마다 분리). 엔진은 호출마다 이름을 붙이고, 실행기는 stderr에서 첫 모델 출력 줄을 찾는다. 작업이 끝나면 기존 지표 줄 뒤에 `request_timing` 한 줄을 남긴다. 표 출력 스크립트를 더한다.

## 검증·완료 기준

- `T132-P1-A`: 정상 요약(요약·후보·심사), 재시도가 섞인 요약(호출 5회), `!!말하자면`(재생성 포함 3회)의 단계 순서와 호출 이름, 시간이 줄어들지 않는 순서, 첫 출력이 시작·끝 사이에 있음, 실패·취소 호출의 `result`. 첫 출력 탐지는 조각 경계·머리말·출력 없는 실패를 다룬다. 동시 요청의 기록이 섞이지 않는다.
- `T132-P1-B`: 빈 대화·쿨타임·실패 결과에서도 한 줄을 남기고 결과 범주가 지표와 같다. 로그에 메시지·프롬프트·답 내용이 없고 이름·범주는 허용 목록뿐이다. 요약 결과·게시·지표는 바뀌지 않는다. 표 스크립트가 합성 로그를 읽는다. 전체 회귀 통과.
