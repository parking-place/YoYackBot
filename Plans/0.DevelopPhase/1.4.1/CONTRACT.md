# 1.4.1 계약 — `/사면`

이 문서는 구현 목표다. 기준 코드는 출시된 `v1.4.0`(`312e5b0`)이다. “사용자 결정”은 2026-10-07 사용자 요청과 질문 답이고, “기본안”은 그 밖의 세부를 개발자가 정한 것이다.

## 1. 명령

- 서버 전용 슬래시 명령 `/사면 대상 [사유]`다. 대상은 서버 멤버이고, 사유는 선택이며 기본값은 “내맴”이다(사용자 결정). 사유는 `/처형`처럼 공백을 정리하고 400자까지 받는다.
- **쓸 수 있는 사람**: `/처형설정 관리역할`에서 고른 처형 역할이 있는 사람, 관리자, 서버 주인이다(사용자 결정: 처형 역할과 같음). 실행할 때마다 서버 멤버 정보를 다시 읽어 확인한다.
- **거부**(Discord를 부르기 전에 확인, 본인에게만 안내):
  - 처형 중이 아닌 사람이다(타임아웃이 없거나 이미 끝남, 기본안).
  - 자기 자신, 봇이다(기본안).
  - 서버 주인·관리자다. 이들은 원래 타임아웃되지 않는다(기본안).
  - 자기와 같거나 높은 역할의 사람이다. 서버 주인은 예외다(사용자 결정: `/처형`과 같은 위계).
  - 봇에 멤버 타임아웃 권한이 없거나 봇 역할이 대상보다 낮다.
- **동작**: 타임아웃을 풀고(`timeout(None)`), 결과는 본인에게만 보인다. 예: “🕊️ <@대상>의 처형을 풀었소. 📝 사유: 내맴”.

## 2. 로그·안내 문구

- 해제는 감사 로그로 처형 로그 채널에 올라간다(1.4.0의 `kind=release`, 멘션 알림 없음). 감사 로그의 실행자는 봇이므로, `/처형`처럼 120초 안에 같은 대상을 `/사면`한 사람을 사면자로 적는다.
- 서비스 로그에는 결과 범주만 남긴다(`pardon_command outcome=…`). 이름·사유는 남기지 않는다.
- `/사면`의 새 안내 문구는 1.4.0 안내 문구 목록에 더해 서버 말투로 바뀐다. 이미 서버 문구가 있는 서버는 **빠진 문구만** 다시 써서 더한다(기본안). 시작할 때 한 번 하고, 그 전이나 실패 때는 기본 문구를 쓴다.
- 도움말 본문은 바꾸지 않는다(`/처형`도 도움말에 없음).

## 3. 호환

- DB schema·테이블·환경·프롬프트는 바뀌지 않는다. 복귀 대상은 `v1.4.0`이다. 복귀하면 `/사면`이 명령 목록에서 사라지고, 더해진 안내 문구 행은 1.4.0이 읽지 않는다(1.4.0은 자기 목록에 있는 키만 읽음).
