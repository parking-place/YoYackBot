# 0.8.0-P5 — 자원 한도·장시간 실행·운영 게이트

- 상태: **PUSH_PENDING**
- 명세 근거: §3, §28, §34, §42, §51–52
- 검증 ID: `T080-P5-A`, `T080-P5-B`
- 검증 환경: **OPS** — LXC의 서비스·장애·자원·복구 검증. 운영 변경은 그 단계 실행 시 확인된 대상과 범위에서 수행한다.

## 선행 조건

[0.8.0-P4](../0.8.0/04-security-review.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 시간/페이지/입력/큐/CLI 동시성 한도를 제공 LXC의 공유 부하에 맞춰 실측·조정한다.
2. 시작한 8시간 시험은 [사용자 결정](../DURATION_WAIVER.md)으로 중단했다. 수집한 부분 관측을 검토하고 재연결·반복 요약·TTL·큐 포화·디스크 압박·모델 timeout의 제한된 검사를 별도로 확인한다.
3. 지속 메모리 증가·디스크 증가·영구 잠금이 없는지 확인하고 운영 제한값·실측 결과·5단계 원격 증거를 기록해 통합한다.

## 산출물

자원 측정표, 확정 제한값, 부분 관측 및 장시간 시험 생략 기록, 운영 기준.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T080-P5-A`: 관측한 구간에서 CPU/RSS/디스크 예산과 종료 후 프로세스/파일/잠금 상태를 확인한다. 장시간 누수 부재는 주장하지 않는다.
- [x] `T080-P5-B`: 사전 기준·workload·실행 SHA·실제 지속 시간과 사용자 생략을 기록하며 부분 관측을 8시간 완료로 적지 않는다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.9.0-P1](../0.9.0/01-full-regression.md).
