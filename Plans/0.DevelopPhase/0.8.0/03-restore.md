# 0.8.0-P3 — 설정 백업·캐시 재생성·복구

- 상태: **DONE**
- 명세 근거: §4-5, §13-2, §13-10–13-13, §39
- 검증 ID: `T080-P3-A`, `T080-P3-B`
- 검증 환경: **OPS** — LXC의 서비스·장애·자원·복구 검증. 운영 변경은 그 단계 실행 시 확인된 대상과 범위에서 수행한다.

## 선행 조건

[0.8.0-P2](../0.8.0/02-observability.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 주시 설정·schema 버전·필요 운영 설정의 복구 절차를 작성하고 인증값은 별도 보안 저장 체계로 취급한다.
2. 메시지 DB의 장기 백업을 기본 비활성화한다. 장애 복구는 빈 캐시와 History 재수집을 기본으로 한다.
3. 필요한 단기 DB 사본이 있으면 원본 created_at 기준 만료가 사본에서도 지켜지도록 관리하고 복원 시 즉시 TTL 정리한다.

## 산출물

백업 범위/보존 정책, 빈 캐시 복구, 복원 runbook.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T080-P3-A`: 격리 DB로 복원한 뒤 주시 설정은 유지되고 메시지는 허용 범위에서 재수집되며 운영 DB를 덮어쓰지 않는다.
- [x] `T080-P3-B`: 백업·임시 사본·WAL·로그가 7일 초과 원문을 사실상 장기 보관하는 통로가 되지 않는지 확인한다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [x] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
