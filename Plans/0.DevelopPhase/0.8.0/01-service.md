# 0.8.0-P1 — 전용 계정 서비스·자동 재시작

- 상태: **PLANNED**
- 명세 근거: §3, §13-12, §39–42
- 검증 ID: `T080-P1-A`, `T080-P1-B`
- 검증 환경: **OPS** — LXC의 서비스·장애·자원·복구 검증. 운영 변경은 그 단계 실행 시 확인된 대상과 범위에서 수행한다.

## 선행 조건

[0.7.0-P5](../0.7.0/05-workflow-acceptance.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. systemd 사용 가능 여부를 확인하고 전용 사용자, 작업 경로, 비밀 설정 파일, 재시작 제한을 갖춘 서비스 정의를 작성한다.
2. runtime/DB/임시/로그 경로를 분리하며 서비스 시작 전 설정·schema·인증 준비 상태를 검사한다.
3. SIGTERM drain, 비정상 종료 후 제한된 재시작, 중복 인스턴스 거부를 배포 절차에 연결한다.

## 산출물

서비스 정의, 설치/기동/종료 절차, 운영 디렉터리 권한.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T080-P1-A`: 개발 LXC 재부팅/프로세스 종료 후 한 인스턴스만 복원되고 주시 설정·cooldown이 보존된다.
- [ ] `T080-P1-B`: 비밀 설정 누락·DB 권한 오류에서는 재시작 폭주 없이 진단하며 다른 서비스에 영향이 없다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.8.0-P2](../0.8.0/02-observability.md).
