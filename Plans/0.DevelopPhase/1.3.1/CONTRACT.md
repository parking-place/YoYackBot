# 1.3.1 계약 — `!!말하자면` 정리·`/도움말`·`/속도 설정`

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 기준 코드는 출시된 [1.3.0](../1.3.0/README.md)(`v1.3.0`, `df159cc`)이다. “사용자 결정”은 2026-10-03 사용자 1.3.1 계획의 문장이고, “기본안”은 계획에 없는 세부를 개발자가 정한 것이다. 기본안은 사용자 확인으로 바뀔 수 있다.

## 0. 호환성

- schema 5를 유지한다. 새 데이터는 선택 테이블 두 개(`idiom_cooldowns`, `guild_fast_mode`)에만 둔다. 기존 테이블의 이름·열·정리 경로는 바꾸지 않는다.
- 복귀 대상은 `v1.3.0`(`df159cc`)이다. 1.3.0은 두 테이블을 모르므로 무시한다: `!!말하자면`은 다시 요약과 쿨타임을 함께 쓰고 시작 안내를 보내며, 모든 서버가 보통 속도로 돌아간다. `/도움말`·`/속도`는 명령 목록에서 사라진다(1.3.0 기동 시 명령 동기화).
- 1.3.0이 돌던 동안 주시 해제된 채널의 `idiom_cooldowns` 행은 1.3.1이 DB를 열 때 정리한다(기존 `recent_ratings`와 같은 방식). 1.3.0이 돌던 동안 봇이 서버에서 나간 경우 `guild_fast_mode` 행이 남을 수 있다. 1.3.0 `guild_tones`와 같은 알려진 한계로 기록한다.

## 1. `!!말하자면` (P1)

- **시작 안내를 보내지 않는다**(사용자 결정). 성공하면 결과 한 줄 `말하자면 {네 글자}? {이모지}`만 올린다. 대기·실패·준비 중·사용법 안내 문구는 그대로 둔다.
- **쿨타임을 `!!요약좀`과 따로 센다**(사용자 결정). `!!말하자면`의 성공은 `!!요약좀`의 쿨타임을 만들지 않고, `!!요약좀`의 성공도 `!!말하자면`을 막지 않는다. 길이는 같은 설정값(`success_cooldown_seconds`, 기본 300초)이다(기본안).
- 채널 작업 슬롯 하나와 전역 모델 대기열은 계속 같이 쓴다(기본안). 한 채널에서 요약이 도는 동안 `!!말하자면`을 부르면 기존처럼 “다른 작업을 하고 있어” 안내를 받는다.
- 저장: `idiom_cooldowns`(서버·채널·마지막 성공·만료 시각). 요약 쿨타임과 같은 규칙으로 주시 해제·서버 탈퇴 때 지운다. 짧은 대기 기록이므로 설정 백업에는 넣지 않는다(기본안).

## 2. `/도움말` (P2)

- 새 슬래시 명령 **`/도움말`**은 기존 요약 도움말 내용을 **부른 사람에게만 보이는**(ephemeral) 답으로 보낸다(사용자 결정).
- **누구나** 부를 수 있다. 관리자·봇 관리 역할 판정(1.1.3)을 거치지 않는다(사용자 결정). 서버 안에서만 쓰며 주시하지 않는 채널에서도 답한다(기존 `!!요약좀 도움`과 같음).
- 기존 `!!요약좀 도움`(`도움말` 포함)은 도움말 전체를 채널에 올리지 않고 한 줄 안내 “📜 사용법은 `/도움말`로 보시오. 부른 사람에게만 보이오. 🙈”만 보낸다(기본안). 다른 안내 문구 속 “`!!요약좀 도움`에서 사용법을 살펴보시오”는 “`/도움말`에서 …”로 바꾼다.
- 도움말 본문은 1.3.0과 같다. `/속도 설정`은 싣지 않는다(사용자 결정).
- 로그: `help_request surface=slash|text`(내용 없음).

## 3. `/속도 설정` (P3)

### 동작
- 서버마다 luna의 **빠른 모드**를 켜고 끈다. **기본값은 끔**이며, 켜면 **그 서버에서만** 적용된다(사용자 결정).
- 빠른 모드는 Codex CLI의 `service_tier="priority"`이다. 서버 Codex CLI 0.158.0의 모델 목록에서 `gpt-6-luna`가 이 등급을 이름 “Fast”, 설명 “1.5x speed”로 내놓는다. 켠 서버의 모든 모델 호출(요약 최대 5회, `!!말하자면` 최대 3회)에 `--config service_tier="priority"`를 더하고, 끈 서버에는 아무것도 더하지 않는다. 추론 강도(현재 운영 `medium`)와 모델은 바꾸지 않는다. CLI가 등급을 지원하지 않으면 경고 뒤 보통 등급으로 처리하므로 요청이 실패하지 않는다.
- `사용량` 조회는 서버와 무관하므로 바꾸지 않는다.
- **관리자·봇 관리 역할만** 열고 바꿀 수 있다(사용자 결정, `/말투`와 같은 1.1.3 판정). 도움말에는 싣지 않는다(사용자 결정).

### 화면 흐름
1. `/속도 설정` → 본인에게만 보이는 메시지: “⚡ 빠른 모드: 꺼짐(기본)” 또는 “켜짐”, 설명 한 줄(“켜면 이 서버의 요약·`!!말하자면`이 더 빨리 나오지만 Codex 사용량이 더 들 수 있소.”), 버튼 **켜기**·**끄기**·**닫기**.
2. **켜기**/**끄기** → 저장하고 “⚡✅ 빠른 모드를 켰소.” / “🐢✅ 빠른 모드를 껐소.”로 화면을 닫는다.
- 연 사람만 조작, 누를 때마다 권한 재확인, 120초 제한. 켜기·끄기는 같은 값을 다시 써도 결과가 같으므로 동시 수정 충돌 검사는 하지 않는다(기본안).

### 저장·로그
- `guild_fast_mode`(행이 있으면 켜짐, 켠 시각). 서버 탈퇴 때 지우고 설정 백업에 포함한다(서버 설정이므로, 기본안). 읽지 못하면 보통 속도로 처리한다.
- 로그: `speed_saved fast=true|false`. 요약·사자성어 지표에 `speed=fast|standard`.

## 4. 문서·출시 (P4)

- README·`docs/channel-settings.md`·CHANGELOG·`docs/upgrade-rollback-1.3.1.md`에 세 변경을 적는다. `/속도 설정`은 운영 문서에만 적고 도움말에는 넣지 않는다.
- 실제 모델 확인: 합성 대화로 같은 요약·`!!말하자면`을 보통/빠른 모드로 실행해 둘 다 성공하고 형식 검사를 통과하는지, 소요 시간을 기록한다. 사용량 차이는 측정하지 않는다.
- 1.3.0 → 1.3.1 → 1.3.0 → 1.3.1 복귀 시험을 격리 DB로 하고, 복귀 중 주시 해제 뒤 재업그레이드에서 `idiom_cooldowns` 고아 행이 정리되는지 확인한다.
