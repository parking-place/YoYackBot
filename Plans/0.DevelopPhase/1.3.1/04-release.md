# 1.3.1-P4 — 실제 모델 확인·통합·배포·출시

- 상태: **DONE** · 검사: `T131-P4-A/B` **PASS** ([증거](../evidence/1.3.1-P4.md)) · 환경: 개발 LXC, 실제 모델(합성 대화), 시험 Discord, GitHub CI

## 작업

[P1~P3](STATUS.md)의 원격 완료를 확인한다. 패키지·`VERSION`을 `1.3.1`로 올리고 버전 대응표·저장소 검증기에 4단계·8검사를 넣는다. README·`docs/channel-settings.md`·CHANGELOG·`docs/upgrade-rollback-1.3.1.md`를 갱신한다. 복귀 대상은 `v1.3.0`(`df159cc`)이다.

실제 모델로 합성 대화의 요약과 `!!말하자면`을 보통/빠른 모드로 실행한다. 정확한 후보 SHA로 LXC 전체 회귀를 돌린 뒤 진행 중 요약이 없을 때 배포한다. 배포 뒤 사용자가 시험 채널에서 확인한다: 시작 안내 없는 `!!말하자면`, 요약과 따로 도는 쿨타임, 부른 사람에게만 보이는 `/도움말`(일반 사용자 포함), `!!요약좀 도움`의 한 줄 안내, `/속도 설정` 켜기·끄기와 켠 뒤의 요약.

## 검증·완료 기준

- `T131-P4-A`: 실제 모델에서 보통/빠른 모드의 요약·`!!말하자면`이 모두 성공하고 형식 검사를 통과하며 소요 시간을 기록한다. 같은 SHA에서 전체 회귀·버전·문서 링크·4단계/8검사 집계를 확인한다.
- `T131-P4-B`: 후보·서비스 SHA 대조, 격리 DB로 1.3.0 → 1.3.1 → 1.3.0 → 1.3.1 복귀·재업그레이드와 고아 정리, 사용자 시험 Discord 확인과 비식별 로그 대조, 비밀정보 비노출, P1~P3 원격 증거, 병합 후 `main` CI를 기록한다.

출시 순서는 [1.3.0-P7](../1.3.0/07-release.md)과 같다: 배포·사용자 확인 → 사전 증거 → `main` PR·리뷰·병합 → main CI → 태그 `v1.3.1`·Release → 최종 증거 E → 종료 D.
