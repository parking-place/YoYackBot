# 1.0.0-P5 — GitHub 정식 릴리스·최종 인수

- 상태: **PUSH_PENDING**
- 명세 근거: §53–55
- 검증 ID: `T100-P5-A`, `T100-P5-B`
- 검증 환경: **DOC** — 문서 검토·추적성/링크/공개 정보 검사. 제품 실행 PASS를 뜻하지 않는다.

## 선행 조건

[1.0.0-P4](../1.0.0/04-production-validation.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 제자리 승격과 즉시 점검을 마친 구현 커밋에 v1.0.0 태그를 붙이고 해당 태그와 GitHub Release/변경 기록을 게시한다. 새 배포의 실제 게시 결과는 [사용자 결정](POSTING_WAIVER.md)으로 미검증임을 Release에 명시한다.
2. 운영 담당에게 시작/중지/장애/인증 갱신/보존/롤백 지침과 알려진 제한을 인수하고 후속 과제를 정리한다.
3. 전체 55단계의 STATUS·검증 링크·단계별 원격 커밋을 점검하고 마지막 문서 커밋까지 push하여 1.0.0을 종료한다.

## 산출물

v1.0.0 태그, GitHub Release, 운영 인수 기록, 최종 STATUS.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T100-P5-A`: 원격 태그가 운영에 배포하고 즉시 상태를 확인한 코드 SHA를 가리키고 Release에서 문서·배포 산출물·실게시 검증 공백을 확인할 수 있다.
- [ ] `T100-P5-B`: 선행 54단계의 원격 증거와 운영 인수 기록에 누락이 없다. 현재 단계 종료 커밋까지 원격 확인하는 G-PUSH를 마치면 55단계 완료다.
- [x] 선행 회귀와 새 배포의 실게시 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: 1.0.0 운영 인수 완료 및 별도 후속 계획.
