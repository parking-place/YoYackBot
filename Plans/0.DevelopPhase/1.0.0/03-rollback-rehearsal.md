- 명세 근거: §4-5, §13-12–13-13, §39
- 검증 ID: `T100-P3-A`, `T100-P3-B`
- 검증 환경: **OPS** — LXC의 서비스·장애·자원·복구 검증. 운영 변경은 그 단계 실행 시 확인된 대상과 범위에서 수행한다.

## 선행 조건

[1.0.0-P2](../1.0.0/02-release-package.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 베타 설정에서 1.0.0으로 업데이트하고 schema 전환·주시 목록·성공 cooldown 보존을 검증한다.
2. 이전 정상 코드 복귀와 호환 schema 복원, 캐시 재생성을 격리 환경에서 리허설한다. 운영 DB를 시험 대상으로 사용하지 않는다.
3. 실패 판정·복귀 조건·복귀 순서·예상 복구 시간을 실측해 runbook에 확정한다.

## 산출물

업데이트/롤백 결과, 복구 시간, 호환성 표.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T100-P3-A`: 업데이트와 복귀 후 주시 설정·권한 격리가 유지되고 오래된 원문이 복원되어 보존 정책을 넘지 않는다.
- [x] `T100-P3-B`: 실패한 migration은 부분 성공 상태로 서비스가 뜨지 않으며 검증된 복구 순서로 정상 기동한다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.
