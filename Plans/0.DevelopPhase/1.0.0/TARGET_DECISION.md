# 1.0.0 운영 대상 결정

- 결정: 현재 개발 LXC와 봇 계정을 1.0.0 운영 환경으로 **제자리 승격**한다.
- 근거: 2026-09-29 사용자 확인. 별도의 운영 서버나 봇 계정은 이 릴리스의 필수 조건이 아니다.
- 상태: 기존 LXC에 1.0.0 후보를 배포했다. 24시간 관측은 [사용자 결정](../DURATION_WAIVER.md)에 따라 생략했고, 새 배포의 실제 게시 결과도 [후속 사용자 결정](POSTING_WAIVER.md)에 따라 확인하지 않고 진행한다. 출시 여부는 P4·P5의 다른 검사와 원격 반영으로 확정한다.

## 전환 조건

1. [1.0.0-P1](01-release-review.md)에서 이전 50단계의 원격 증거와 출시 후보 SHA, 운영 전환 범위를 확정한다.
2. [1.0.0-P3](03-rollback-rehearsal.md)에서 같은 LXC의 격리 경로로 업데이트·복구 절차를 검증한다. 운영 DB를 리허설 대상으로 쓰지 않는다.
3. [1.0.0-P4](04-production-validation.md)에서 기존 봇 프로세스를 정지한 뒤 검증된 SHA로 **단일 Gateway 세션**만 기동하고, 설정·인증·DB 준비 상태를 확인한다. 새 배포의 게시 결과는 [사용자 결정](POSTING_WAIVER.md)에 따라 `SKIPPED_BY_USER`로 기록한다.
4. 전환 시각, 이전/신규 SHA, 설정 백업 위치, 복구 절차, 즉시 점검 시각을 비밀값 없이 증거에 남긴다. 상태·보존·자원 검사를 마치고 새 배포의 실게시 공백을 명시하기 전에는 P4를 완료로 표시하지 않는다.
5. 전환이 실패하거나 출시 차단 결함이 생기면 검증된 이전 SHA와 설정으로 복구하고, 실패·복구 시간을 기록한다.

개발 LXC와 봇 계정의 계속 사용은 사용자가 승인한 대상 선택이다. 실제 승격과 GitHub Release는 해당 단계의 선행 조건·검증·원격 업로드를 완료할 때 수행한다.
