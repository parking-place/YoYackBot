# 1.0.0-P1 — 정식 출시 범위·증거 최종 검토

- 상태: **PLANNED**
- 명세 근거: §53–55
- 검증 ID: `T100-P1-A`, `T100-P1-B`
- 검증 환경: **DOC** — 문서 검토·추적성/링크/공개 정보 검사. 제품 실행 PASS를 뜻하지 않는다.

## 선행 조건

[0.9.0-P5](../0.9.0/05-rc-freeze.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 0.0.0~0.9.0의 50단계가 원격 증거와 함께 DONE인지 검토하고 배포 대상 후보 SHA를 명시한다.
2. 필수 기능·보존·보안·품질·운영 기준과 알려진 제한을 릴리스 체크리스트로 대조한다.
3. 이 단계 실행 시 운영 반영 대상·실행 권한·복구 담당·점검 시점을 확인한다. 이번 계획 작성은 배포 수행을 뜻하지 않는다.

## 산출물

출시 검토표, 대상 후보, 운영 전환 범위 기록.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T100-P1-A`: 필수 게이트 누락·미해결 치명/높음 결함·미확인 모델 설정이 없고 전체 증거가 원격에서 열람된다.
- [ ] `T100-P1-B`: 공개 안내에 지원 범위와 제한이 정확하며 민감 정보·실제 대화가 포함되지 않는다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [1.0.0-P2](../1.0.0/02-release-package.md).
