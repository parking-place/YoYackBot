# 0.1.0-P4 — 주시 추가·해제·미주시 차단

- 상태: **PLANNED**
- 명세 근거: §4-6–4-8, §8
- 검증 ID: `T010-P4-A`, `T010-P4-B`
- 검증 환경: **MOCK** — LXC의 합성 데이터·대역 기반 단위/통합 검사. 실제 Discord/모델 검증과 구분한다.

## 선행 조건

[0.1.0-P3](../0.1.0/03-settings-store.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 일반 메시지 수신과 요약 진입점 모두에 주시 검사를 연결한다. 아직 없는 cache/history/CLI는 spy 어댑터로 호출 여부를 검증한다.
2. 주시 추가 이후 이벤트부터 처리하고 과거 범위 보충 필요를 표시한다. 해제 시 즉시 신규 처리를 차단한다.
3. 미주시 채널의 요약 요청은 명세 안내만 출력하며 도움말은 언제든 허용한다. 처리 중 해제 신호 전달 계약을 만든다.

## 산출물

주시 검사 공통 계층, 설정 변경 이벤트, 미주시 응답.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T010-P4-A`: 미주시 채널에서 DB 메시지 저장·History 조회·CLI 실행·성공 쿨타임 호출이 모두 0회다.
- [ ] `T010-P4-B`: 추가/해제 직후 이벤트와 재시작 복원 상태를 확인하며, 해제된 채널은 기존 데이터 유무와 관계없이 차단된다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.
