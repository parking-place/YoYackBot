# 0.1.0-P1 — Discord 연결·이벤트 경계 구현

- 상태: **PUSH_PENDING**
- 명세 근거: §3–4, §8–9
- 검증 ID: `T010-P1-A`, `T010-P1-B`
- 검증 환경: **LIVE** — 개발 Discord 서버/채널에서 실제 이벤트·권한·출력을 확인한다. 실제 Codex 사용 여부도 구분한다.

## 선행 조건

[0.0.0-P5](../0.0.0/05-verification-baseline.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. Discord gateway 연결·재연결·정상 종료와 Guild 메시지 이벤트 진입점을 구현한다.
2. 봇·웹훅·시스템 메시지, DM과 비지원 채널을 입구에서 구분한다. 메시지 캐시 구현 전에는 원문 저장을 하지 않는다.
3. 권한이나 Message Content 접근이 부족할 때 준비 상태를 실패로 표시하고 무응답 원인을 운영 로그로 분류한다.

## 산출물

Discord 어댑터, 연결 상태·이벤트 필터, 최소 권한 안내.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T010-P1-A`: 개발 Guild에서 일반 사용자와 봇/웹훅 이벤트가 분리되며 다른 Guild나 DM 메시지가 처리 대상에 섞이지 않는다.
- [x] `T010-P1-B`: 네트워크 단절 후 재연결과 권한 부족을 시험하고 자동 재연결이 중복 핸들러를 만들지 않는다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.1.0-P2](../0.1.0/02-channel-selector.md).
