# 0.0.0 → 1.0.0 개발 계획

작성일: 2026-09-28 · 기준: [기능 명세 v1.5](../shinchangseop_discord_summary_bot_spec_v1.5.md)

**11개 버전 × 버전별 5단계 = 총 55단계. 모든 단계는 검증 후 commit·GitHub push·원격 반영 확인까지 끝나야 완료한다.**

버전 범위는 `0.0.0 → 0.1.0 → … → 0.9.0 → 1.0.0`의 11개 개발 마일스톤으로 구성했다. 중간 패치 버전은 결함 수정 필요 시 별도로 추가한다.

1.0.0 이후 패치 실행 순서는 [1.0.0a — 30일 캐시](1.0.0a/README.md) → [1.0.0b-1 — 대량 요약 복구와 첫 30일 전체 수집](1.0.0b-1/README.md) → [1.0.0c — 여러 채널 동시 요청](1.0.0c/README.md) → [1.0.0d — 실제 닉네임](1.0.0d/README.md)이다. [옛 1.0.0b 계획](1.0.0b/README.md)은 폐기·대체됐고 P1 완료/P2 중단 이력만 보존한다. 1.0.0a는 출시됐으며 1.0.0b-1(6단계)·1.0.0c(5단계)·1.0.0d(5단계)는 새 계획의 [상태](1.0.0b-1/STATUS.md)를 각각 확인해야 한다. [버전 대응표](PATCH_VERSIONING.md)에 태그와 패키지 버전을 나누어 기록했다. 아래 역사적 55단계 완료 집계에는 포함하지 않는다.

그 뒤의 새 명령은 [1.0.1 후속 계획](1.0.1/README.md)에 6단계로 따로 정리했고, 6단계 모두 완료해 `v1.0.1`로 출시했다.

준비 완료 채널의 요약 시작 안내와 같은 채널 중복 요청의 범위 안내는 [1.0.2 후속 계획](1.0.2/README.md)에 5단계로 정리했다. 1.0.2는 출시된 `v1.0.1` 기준으로 다시 검토한 뒤 5단계 모두 완료해 `v1.0.2`로 출시했다.

`!!요약좀 채널`로 현재 서버의 주시 채널을 알려주는 명령은 [1.0.2b 계획](1.0.2b/README.md)에 3단계로 정리했고, 모두 완료해 `v1.0.2b`로 출시했다.

성공 쿨타임을 1분으로 줄이고 요약 말투를 천박하지만 말끝은 하오체로 바꾸는 작업은 [1.0.2c 계획](1.0.2c/README.md)에 4단계로 정리했고, 모두 완료해 `v1.0.2c`로 출시했다.

기본 요약을 짧게로 바꾸고(`길게`·아주 긴 `자세히`), 옵션 뒤 문장을 추가 요청으로 넘기며, 말투를 더 비꼬는 쪽으로 바꾸는 작업은 [1.1.0 계획](1.1.0/README.md)에 5단계로 정리했고, 모두 완료해 `v1.1.0`으로 출시했다.

요약을 주제·화자별로 읽기 쉽게 나누고 모든 요약 끝에 요약창섭의 떡밥 한줄 평가를 붙이는 작업은 [1.1.0a 계획](1.1.0a/README.md)에 4단계로 정리했고, 모두 완료해 `v1.1.0a`로 출시했다.

옵션 뒤 추가 요청을 기본 형식·길이·말투 지시보다 우선하게 하고 떡밥 한줄 평가를 한줄 비평으로 바꾸는 작업은 [1.1.1 계획](1.1.1/README.md)에 4단계로 정리했고, 모두 완료해 `v1.1.1`로 출시했다.

결론이 안 난 이야기를 흠으로 비꼬지 않고 진행 중으로 다루는 작업은 [1.1.1a 계획](1.1.1a/README.md)에 4단계로 정리했고, 모두 완료해 `v1.1.1a`로 출시했다.

이모지를 적극적으로 쓰고, 주제마다 한줄 비평을 붙이며, 기본(짧게) 요약을 주제별 1~2줄로 줄이는 작업은 [1.1.2 계획](1.1.2/README.md)에 4단계로 정리했고, 모두 완료해 `v1.1.2`로 출시했다.

도움말을 짧게 바꾸고, 요약문에 마크다운(제목·밑줄 닉네임·인용 비평)을 적극 쓰고, 모든 슬래시 명령어를 `애플리케이션 명령어 사용` 권한이 있는 누구나 쓰게 하는 작업은 [1.1.2a 계획](1.1.2a/README.md)에 5단계로 정리했고, 모두 완료해 `v1.1.2a`로 출시했다.

슬래시 명령어를 기본적으로 관리자만 쓰게 되돌리고, `/관리권한 설정`으로 고른 봇 관리 역할도 쓰게 하는 작업은 [1.1.3 계획](1.1.3/README.md)에 3단계로 정리했고, 모두 완료해 `v1.1.3`으로 출시했다.

사용량·상태 등 요약 본문 밖의 안내 문구에도 이모지를 적극 쓰는 작업은 [1.1.3a 계획](1.1.3a/README.md)에 3단계로 정리했고, 모두 완료해 `v1.1.3a`로 출시했다.

서버별 `/말투`, 답장으로 범위 지정, 떡밥 한줄 평가 다양화(후보 10개 + luna 심사)는 [1.2.0 계획](1.2.0/README.md)에 6단계로 정리했다. 계획 상태이며 제품 검증을 뜻하지 않는다.

이 문서는 개발 계획이다. 단계별 실제 완료·미실행 검사는 [STATUS](STATUS.md)와 증거를 따른다. 문서 게시만으로 기능 구현·LXC 검증·Discord/Codex 실행 성공·정식 출시를 선언하지 않는다.

## 읽는 순서

1. [환경과 자료 검토](ENVIRONMENT.md), [명세 해석과 결정](DECISIONS.md)을 읽는다.
2. [요구사항 추적표](REQUIREMENTS.md)에서 원본 명세와 단계의 연결을 확인한다.
3. [Git 완료 규칙](GIT_WORKFLOW.md)과 [증거 양식](EVIDENCE_TEMPLATE.md)을 적용한다.
4. 버전/단계 파일을 순서대로 실행하고 [검증 목록](TEST_MATRIX.md), [STATUS](STATUS.md)에 실제 결과를 기록한다.
5. [출시 기준](RELEASE_CRITERIA.md)을 충족한 후보만 정식 배포한다.

## 공통 개발 원칙

- 주시 대상으로 명시한 현재 Guild 텍스트 채널의 일반 사용자 대화만 처리한다.
- 출시된 1.0.0a의 SQLite 캐시는 최대 30일이다. 후속 1.0.0b-1은 첫 주시 시 조회 가능 범위 전체를 수집하고 이후 실시간 DB 수집으로 전환할 계획이다.
- 요약은 한국어 하오체와 화자 귀속을 유지하고 대화 밖의 사실·외부 URL 내용을 보충하지 않는다.
- 동일 채널 중복 작업을 차단하고 결과 전체 게시 성공 시점부터 5분 쿨타임을 적용한다.
- 실제 인증값·원문·운영 DB는 공개 GitHub에 올리지 않는다.
- 모델·CLI·SDK 버전과 환경을 실제 검증해 고정한다. 계획만으로 설치·사용 가능을 확정하지 않는다.
- 각 버전의 P1~P5를 순서대로 마친다. 미구현 후속 모듈의 초기 검사는 명시한 대역/계약으로 한정한다.

## 계획 범위 밖

음성 녹음, OCR, 첨부 내용 분석, 외부 URL 탐색, 여러 채널 통합, 장기 아카이브, 개인 요약, 정기 자동 요약, 웹 대시보드, 대화 검색, 대화 외부 공개는 1.0.0 필수 범위에 넣지 않는다.

## 개발 착수

실행은 [0.0.0-P1 요구사항 확정](0.0.0/01-requirements.md)부터 순서대로 진행한다. 각 단계의 완료 여부는 실행 증거와 원격 커밋으로 판단한다.
