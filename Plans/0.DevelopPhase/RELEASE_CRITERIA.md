# 버전 및 정식 출시 기준

아래 항목은 각 버전과 정식 출시를 판단하는 기준이다. 이미 수행한 검사와 앞으로 필요한 검사는 [STATUS](STATUS.md)와 증거 파일에서 구분한다.

## 공통 단계 게이트

1. 선행 단계의 작업·검증·종료 문서가 원격에 존재한다.
2. 해당 단계의 고유 검사 A/B와 관련 회귀 검사가 통과했다.
3. 검증 대상 구현 SHA·환경·결과·제한을 기록했다.
4. 비밀정보·Discord 원문·DB·임시 파일을 제외한 산출물을 commit·push했다.
5. 증거 commit과 DONE 종료 문서 commit의 GitHub 반영·필수 CI를 확인했다.

문서 계획의 구조 검사와 제품 검사는 분리한다. 대역 검사는 실제 Discord 권한·전송 또는 실제 Codex 모델 성공의 대체 증거가 아니다.

## 품질 및 운영 수치

다음 값은 명세 외에 이 로드맵에서 제안한 검증 기준이다. 실제 측정이 아니며 변경 시 이유와 영향받는 검사를 문서화한다.

- 요약 평가: 최소 20개 합성 대화, 중대한 날조/화자 오귀속 0건, 주요 결정·미해결 포인트 포함률 90% 이상, 한국어 하오체 적합 90% 이상. 수동 검토를 포함하며 자동 문자열 검사만으로 사실성을 판정하지 않는다.
- 동시성: 동일 채널 20개 동시 요청에서 실행 1개; 전역 Codex 실행은 설정값 이하; 대기열과 대기시간은 유한하다.
- 쿨타임: 마지막 조각 게시 성공 + 300초; 299초 거부, 300초 허용; 실패/빈 대화/도움말/미주시 요청은 생성하지 않는다.
- 보존: 영속 캐시의 7일 경계, 4주 요청의 비영속 처리, 수정·삭제, 임시 파일·CLI 기록·DB 사본 정책을 확인한다.
- soak: 0.8.0 최소 8시간, 0.9.0 최소 24시간, 1.0.0 운영 검증 최소 24시간. 실행 SHA·workload·관측 시작/끝·오류를 남긴다.
- 자원: 0.8.0-P5 시험 시작 전에 실제 여유 자원을 바탕으로 CPU/RSS/디스크·큐·시간 제한을 확정한다. 지속적으로 증가하는 메모리/파일/프로세스/잠금 누수는 허용하지 않는다.
- 실제 운영 장애와 제품 결함을 분리해서 기록하되 외부 장애라는 이유로 복구 실패·데이터 노출·영구 잠금을 허용하지 않는다.

## 출시 차단 조건

- 필수 기능의 FAIL/NOT_RUN 또는 검증 후보 SHA 불일치.
- 비밀정보·원문·다른 Guild/요청 데이터 노출, 불필요한 파일/네트워크 접근.
- 캐시를 오래된 원문의 장기 보관 수단으로 사용하거나 4주 입력을 조용히 축소함.
- 중대한 날조·화자 오귀속, 중복 게시, 성공 전 cooldown, 영구 잠금.
- 지정 모델과 Light 설정 조합 미확인, 실제 Discord/Codex 검증 부재.
- 복구/롤백 불가, 미해결 치명적 또는 높은 심각도의 결함.
- 단계별 GitHub 업로드 또는 마지막 종료 문서 원격 확인 미완료.

## 1.0.0 진행 순서

0.9.0까지 50단계를 완료한 뒤 1.0.0-P1에서 증거를 검토한다. P2에서 배포 산출물, P3에서 롤백 리허설, P4에서 운영 배포·관측을 마친다. P5는 그 운영 검증 코드 SHA에 태그와 Release를 게시하고 인수를 마친 뒤 자체 종료 커밋까지 push한다. 이 마지막 확인이 끝나야 55 / 55 완료다.

운영 전환은 해당 단계를 실제 수행할 때 확인한 대상과 실행 범위에서 한다. 이번 요청의 산출물은 계획 문서와 GitHub 게시이며, 실제 운영 배포·모델 실행·제품 태그 생성은 수행하지 않는다.
