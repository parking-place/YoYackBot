# 0.9.0-P2 — 개발 Discord 사용자 흐름·품질 베타

- 상태: **PLANNED**
- 명세 근거: §4-1–4-8, §5, §15–22, §44–49
- 검증 ID: `T090-P2-A`, `T090-P2-B`
- 검증 환경: **LIVE** — 개발 Discord 서버/채널에서 실제 이벤트·권한·출력을 확인한다. 실제 Codex 사용 여부도 구분한다.

## 선행 조건

[0.9.0-P1](../0.9.0/01-full-regression.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 개발 Guild에서 관리자 설정부터 일반 사용자 8개 옵션·도움말·오류 안내까지 실제 흐름을 점검한다.
2. 실제 모델로 화자 귀속·하오체·결정/미해결 정리 품질을 검토하고 중복 알림·장문 가독성·부분 실패 안내를 확인한다.
3. 베타 피드백을 결함 심각도와 재현 절차로 분류한다. 공개 GitHub에는 합성/익명 결과만 기록한다.

## 산출물

사용자 흐름 베타 기록, 품질 결과, 수정 backlog.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T090-P2-A`: 관리자/일반 사용자 관점의 성공·실패 경로 모두에서 오해 없는 안내와 권한 경계가 유지된다.
- [ ] `T090-P2-B`: 중대한 날조·화자 오귀속·권한 누수·원문 노출은 출시 차단으로 처리하고 품질 기준을 재확인한다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.9.0-P3](../0.9.0/03-fault-drills.md).
