# 0.9.0-P4 — 베타 부하·보존 경계 검증

- 상태: **DONE**
- 명세 근거: §3, §13-2, §28, §42, §52
- 검증 ID: `T090-P4-A`, `T090-P4-B`
- 검증 환경: **OPS** — LXC의 서비스·장애·자원·복구 검증. 운영 변경은 그 단계 실행 시 확인된 대상과 범위에서 수행한다.

## 선행 조건

[0.9.0-P3](../0.9.0/03-fault-drills.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. [사용자 결정](../DURATION_WAIVER.md)에 따라 24시간 시험을 생략하고, 제한된 베타 workload에서 메모리·디스크·성공률·지연·큐를 측정한다.
2. 7일 보존 경계는 별도의 과거 timestamp fixture로 검증한다. 짧은 관측을 장시간 운영 증거라고 표현하지 않는다.
3. 실행 중 재연결·TTL·CLI timeout 이후에도 회복하는지 확인하고 실패를 숨기지 않은 보고서를 작성한다.

## 산출물

짧은 부하 시험 기록, 자원 결과, 보존 경계 별도 결과, 장시간 신뢰성 미검증 기록.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T090-P4-A`: 제한된 workload에서 0.8.0 자원 한도를 확인하고 모델/Discord 외부 장애와 제품 결함을 구분한다. 24시간 누수 부재는 미검증이다.
- [x] `T090-P4-B`: 합성 과거 메시지의 TTL·coverage 절단과 실제 관측 시간 모두 재현 가능한 증거가 있다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [x] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [x] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [x] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [x] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [x] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계
