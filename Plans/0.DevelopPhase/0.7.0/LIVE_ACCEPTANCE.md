# 0.7.0 실제 명령 인수 결과

- 검증 대상: `develop/0.7.0`의 `23cdd18c19c7a195d9eab43bfc94d49b14c0ad92` 소스. 이 보고서와 추가 회귀 검사는 후속 검증 커밋에 포함된다.
- 환경: 개발 LXC의 봇 전용 계정, 개발 Discord의 주시 채널, 인증된 Codex CLI의 고정 모델. 대화 입력은 사용자가 보낸 합성 문장뿐이다.
- 데이터 변경: 기동 전 개발 DB의 제한된 백업을 만들고, 원본 설정을 보존하며 schema 4→5로 전환했다. 장기 백업 보존 정책은 0.8.0-P3에서 처리한다.

| 확인 항목 | 결과 | 증거 경계 |
|---|---|---|
| 실제 명령 전체 경로 | 합성 일반 사용자 메시지 → Discord 이벤트/수집 → 실제 모델 → 같은 채널 요약 게시가 성공했다. 시험 화자와 회의·시간 핵심 단서가 출력에 있었고 멘션은 없었다. | 실제 Discord와 실제 모델 |
| 처리 중 중복 | 사용자가 첫 채널에 같은 명령을 즉시 다시 보냈을 때 `요약중이오` 안내를 확인했다. 최근 기록에는 처리 중 안내 2건이 있다. | 실제 Discord |
| 다른 채널 | 주시 채널 2곳에 최근 요약이 각각 게시됐다. 두 채널의 성공 시각과 만료 시각이 독립된 DB 행에 기록됐다. | 실제 Discord와 SQLite |
| 성공 후 대기 | 즉시 재호출에 남은 시간 안내가 나왔다. 각 DB 행의 만료 시각은 마지막 게시 성공 시각의 정확히 300초 뒤이며, Discord 게시 시각과 저장 성공 시각 차이는 3초 미만이다. | 실제 Discord와 SQLite |
| 도움말 | 성공 대기 중 실제 도움말이 나왔다. 처리 중과 대기 중 모두 도움말이 모델·수집을 우회하는 회귀 검사도 추가했다. | 실제 Discord + 합성 회귀 |
| 출력 및 정리 | 최근 게시 조각 3건은 모두 Discord 메시지 길이 제한 이내이고 멘션이 중립화됐다. 요청 임시 디렉터리 0개, 봇 프로세스 1개, DB 무결성 정상이다. | 실제 개발 LXC |
| 실패·취소·대기열 | 모델/부분 게시 실패 후 성공 대기 미적용, 취소 후 상태 복구, FIFO·동시 1개 제한, 포화 거부와 종료 복구를 개발 LXC의 합성 장애 주입으로 검사했다. | MOCK/LXC; 실제 Discord 장애 주입은 미실행 |

실제 5분 명령의 출력은 한 조각이었다. 여러 조각의 실제 Discord 게시·부분 실패는 [0.6.0-P4](../evidence/0.6.0-P4.md)에서 합성 출력을 사용해 별도로 확인했다. 실제 서비스의 권한 회수, 모델 인증 만료, 부분 게시 실패를 의도적으로 만들지는 않았다. 이 경계를 0.9.0 장애 훈련에서도 유지한다.

메시지 본문, 요약 원문, Discord 식별자, 인증값 및 백업 DB는 이 보고서에 넣지 않았다.
