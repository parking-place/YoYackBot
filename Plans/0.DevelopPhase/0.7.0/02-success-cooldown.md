# 0.7.0-P2 — 게시 성공 기준 300초·남은 시간

- 상태: **PLANNED**
- 명세 근거: §25–27, §29, §43, §49; D02/D09
- 검증 ID: `T070-P2-A`, `T070-P2-B`
- 검증 환경: **MOCK** — LXC의 합성 데이터·대역 기반 단위/통합 검사. 실제 Discord/모델 검증과 구분한다.

## 선행 조건

[0.7.0-P1](../0.7.0/01-channel-state.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 마지막 분할 게시 성공을 받은 시각부터 300초 만료를 기록하고 실패 경로에는 적용하지 않는다.
2. 성공 쿨타임 중 `아직은 때가 아니오. 00분 00초 뒤에 오시오.`를 분·초 형식으로 표시한다.
3. 만료 timestamp를 영속화하고 runtime clock·재시작·시계 변동 시 음수/영구 잠금이 생기지 않게 한다.

## 산출물

성공 cooldown 저장소, 남은 시간 formatter, 복원 규칙.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T070-P2-A`: 299초에는 거부하고 300초부터 허용하며 1분 35초 후에는 03분 25초 안내가 나온다.
- [ ] `T070-P2-B`: CLI 성공 후 게시 실패에는 cooldown이 없고 재시작 후에는 기존 성공 cooldown의 남은 시간만 적용된다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.7.0-P3](../0.7.0/03-failure-recovery.md).
