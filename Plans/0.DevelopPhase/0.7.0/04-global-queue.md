# 0.7.0-P4 — 전역 실행 제한·대기열·재시작

- 상태: **PUSH_PENDING**
- 명세 근거: §27–28, §42–43; D09
- 검증 ID: `T070-P4-A`, `T070-P4-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.7.0-P3](../0.7.0/03-failure-recovery.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. Codex 실행 semaphore 기본 1개와 유한 FIFO 대기열, 대기 timeout을 설정으로 제공한다.
2. 수락된 대기 작업은 해당 채널에서 SUMMARIZING으로 유지하고 큐 포화 요청은 잠금 없이 거부한다.
3. 정상 종료 시 신규 수락 중단·진행 작업 정리, 비정상 재시작 시 stale 작업 실패 복구, 프로세스 중복 기동 방지를 구현한다.

## 산출물

작업 queue, backpressure, shutdown/startup 복원.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T070-P4-A`: 여러 채널 burst에서 CLI 동시 수가 설정을 넘지 않고 큐 크기·대기 timeout·해제 순서가 지켜진다.
- [x] `T070-P4-B`: 실행/대기 중 재시작 후 orphan·영구 잠금·요약 자동 중복 게시가 없으며 성공 cooldown은 보존된다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.7.0-P5](../0.7.0/05-workflow-acceptance.md).
