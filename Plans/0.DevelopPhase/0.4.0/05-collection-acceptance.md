# 0.4.0-P5 — 캐시 fallback·빈 대화·수집 통합 게이트

- 상태: **IN_PROGRESS**
- 명세 근거: §13-13, §29–31, §53 로그 필터/캐시
- 검증 ID: `T040-P5-A`, `T040-P5-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.4.0-P4](../0.4.0/04-recent-count.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 설정/권한을 신뢰할 수 있을 때만 DB 장애를 History 직접 수집으로 대체한다. 설정 불명확 시 수집을 중단한다.
2. 일반 사용자 메시지가 0개면 Codex 호출 없이 빈 대화 결과를 반환하며 입력 크기 초과를 조용히 절단하지 않는다.
3. 시간형·오늘·개수형·4주·재연결·장애의 회귀 결과를 모으고 실제 History smoke를 포함해 0.4.0을 검토·통합한다.

## 산출물

fallback 오케스트레이션, 빈 결과 계약, 수집 통합 증거.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T040-P5-A`: 캐시 읽기/쓰기 실패에도 허용된 fallback은 같은 입력을 만들고 설정 DB 실패에서는 History/CLI가 0회다.
- [ ] `T040-P5-B`: 완전/부분 캐시, 빈 범위, 최대 상한, 장애 주입 사례가 통과하고 선행 4단계의 원격 증거가 존재한다. 현재 증거 업로드는 G-PUSH에서 확인한다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.
