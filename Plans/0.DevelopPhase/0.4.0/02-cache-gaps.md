# 0.4.0-P2 — 시간 범위 차집합 조회·완료 확정

- 상태: **IN_PROGRESS**
- 명세 근거: §13-5–13-7, §13-9
- 검증 ID: `T040-P2-A`, `T040-P2-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.4.0-P1](../0.4.0/01-history-pages.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 요청 범위에서 유효 coverage를 빼고 누락된 구간만 조회하도록 cache/history를 연결한다.
2. 17:00~18:00 캐시와 16:20~18:20 요청 사례를 구현하고 빈 구간도 정상 조회 완료 후 기록한다.
3. 페이지 수집 실패 시 완료된 부분만 확정하거나 현재 구간을 미완료로 남긴다. 재접속 후 수정/삭제 신선도 재확인 경로를 적용한다.

## 산출물

범위 수집 서비스, gap별 원자적 저장, 캐시 효율 계측.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T040-P2-A`: 명세의 겹침 사례에서 16:20~17:00과 18:00~18:20만 조회하고 완전한 재요청에서는 0회 조회한다.
- [ ] `T040-P2-B`: 실패·빈 응답·연결 공백 후 요청에서 누락이 은폐되지 않고 DB 직접 결과와 합성 원본이 일치한다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.4.0-P3](../0.4.0/03-older-than-retention.md).
