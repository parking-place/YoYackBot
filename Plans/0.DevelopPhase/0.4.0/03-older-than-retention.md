# 0.4.0-P3 — 7일 초과·최대 4주 요청 처리

- 상태: **PUSH_PENDING**
- 명세 근거: §13-2, §34, §39, §55; D01
- 검증 ID: `T040-P3-A`, `T040-P3-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.4.0-P2](../0.4.0/02-cache-gaps.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. 요청을 7일 이내 캐시 구간과 그 이전 비영속 구간으로 나누어 수집한다.
2. 오래된 메시지는 요청별 제한 메모리/임시 파일에만 두고 최신 캐시 데이터와 ID 기준으로 병합한다.
3. 기간·페이지·바이트·시간 상한을 넘으면 설명 가능한 실패를 반환하고 전체 기간을 수집한 것처럼 표시하지 않는다.

## 산출물

장기 요청 분리 수집, 비영속 결과 병합, 보존 경계 처리.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [x] `T040-P3-A`: 7일 경계 양쪽을 걸치는 2주/4주 요청에서 결과는 연결되지만 영속 DB에는 7일 초과 본문이 없다.
- [x] `T040-P3-B`: 메모리 수집 경로는 성공·실패·취소 모두에서 요청 파일을 만들지 않고 4주 초과는 History 호출 전에 거부된다. 실제 모델 입력 파일의 생성·정리는 0.5.0-P2에서 검증한다.
- [x] 영향받는 검사를 수행하고 미실행·실환경 미확인 항목을 증거에서 분리했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.
