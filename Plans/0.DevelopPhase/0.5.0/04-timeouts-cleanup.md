# 0.5.0-P4 — 시간·입력 제한·취소·잔여 파일 정리

- 상태: **IN_PROGRESS**
- 명세 근거: §13, §28–31, §39–42, §51; D08/D10
- 검증 ID: `T050-P4-A`, `T050-P4-B`
- 검증 환경: **LXC** — 제공 LXC의 격리된 개발 경로/DB에서 실행한다. 실제 서비스 사용 여부는 각 검사에 따로 기록한다.

## 선행 조건

[0.5.0-P3](../0.5.0/03-subprocess-isolation.md)가 검증과 GitHub push 확인까지 끝나 DONE이어야 한다.

## 수행 작업

1. CLI 실행시간·출력 바이트·입력 예산을 제한하고 timeout/취소 시 자식 프로세스 그룹까지 종료한다.
2. 성공·비정상 종료·빈 결과·오류·전송 실패의 모든 종료 경로를 finally 정리로 연결한다.
3. 재시작 시 본 서비스 소유의 오래된 요청 폴더만 정리하며 active 작업은 건드리지 않는다. CLI 세션·stderr 잔여 원문도 점검한다.

## 산출물

timeout/cancellation 처리, 입력 예산 검사, 정리/잔여 회수 정책.

산출물은 앞으로 구현할 대상이다. 이 계획 파일을 작성한 것만으로 산출물이 구현되었다고 판단하지 않는다.

## 검증과 통과 기준

- [ ] `T050-P4-A`: 지연 프로세스·종료 무시 자식·큰 출력·빈 출력·취소를 주입해 orphan과 남은 요청 파일이 없음을 확인한다.
- [ ] `T050-P4-B`: 입력 상한 초과는 명시적으로 실패하며 다른 서비스 파일과 진행 중 요청 폴더를 삭제하지 않는다.
- [ ] 영향받는 선행 기능의 회귀 검사가 통과하고 실패·미실행·실환경 미확인 항목을 구분했다.

## 단계 완료 — GitHub 업로드 필수

- [ ] 위 작업·검증을 완료하고 [증거 양식](../EVIDENCE_TEMPLATE.md)에 대상 SHA·환경·결과·제한을 기록했다.
- [ ] 실제 비밀값·`.private`·DB·Discord 원문·임시 파일이 커밋에 없음을 확인했다.
- [ ] 구현과 증거를 단계별로 commit하고 대상 브랜치에 **GitHub push**했다.
- [ ] 원격에서 증거 커밋 존재와 구현 SHA 포함, 필요한 CI 결과를 확인했다.
- [ ] [STATUS](../STATUS.md)를 DONE으로 갱신한 종료 커밋도 push하고 마지막 원격 반영을 확인했다.

**push 실패 또는 원격 확인 미완료는 PUSH_PENDING이며 단계 완료가 아니다.** 상세 절차와 SHA 기록 방식은 [GIT_WORKFLOW](../GIT_WORKFLOW.md)를 따른다.

## 실패 및 다음 단계

검사 실패 시 실패 사례·환경·복구 방법을 증거에 남기고 IN_PROGRESS/BLOCKED로 유지한다. 수정 후 영향 검사를 다시 수행하며 완료 전에 의존 단계로 넘어가지 않는다.

이 단계의 마지막 원격 반영까지 확인한 뒤 다음으로 진행한다: [0.5.0-P5](../0.5.0/05-engine-acceptance.md).
