# 0.5.0 Codex 실행 계약

개발 서버의 봇 전용 계정에서 고정된 `codex-cli 0.158.0`과 같은 버전의
`codex-code-mode-host`, `bubblewrap`을 사용한다. 모델은 `gpt-6-luna`, reasoning은
`low`로 고정한다. 버전이나 인증 상태가 맞지 않으면 모델을 바꾸지 않고 시작을 거부한다.

## 인증과 비밀정보

전용 계정에서 기기 로그인한 뒤 인증 파일만 해당 계정 소유의 별도 `model-auth` 디렉터리에
복사한다. 디렉터리 권한은 `0700`, `auth.json`은 `0600`이어야 한다. 이 파일은 Git에
올리지 않는다. `YOYACK_CODEX_AUTH_DIRECTORY`는 이 별도 디렉터리를 가리킨다.
CLI의 토큰 갱신을 위해 격리된 실행 안에서는 이 디렉터리를 쓸 수 있으나, 모델이
호출하는 도구에는 `/auth` 읽기·쓰기를 금지한다. 실제 봇 계정의 홈, SSH, DB,
프로젝트 경로는 격리 공간에 노출하지 않는다.

## 실행

- `YOYACK_CODEX_EXECUTABLE`은 검증된 절대 경로의 CLI 바이너리다.
- `YOYACK_INPUT_DIRECTORY`는 봇 전용 계정의 개인 디렉터리다.
- 입력은 요청별 `0700` 디렉터리 안의 `0600` 파일로 만든다. 대화 본문은 프로세스
  인자가 아니라 이 파일에만 기록하고, CLI 프롬프트는 표준입력으로 보낸다.
- CLI에는 현재 요청 입력 파일과 출력 경로만 보인다. 웹 검색, 브라우저, 앱,
  플러그인, 하위 에이전트는 끈다. OS와 CLI의 두 격리 계층을 적용한다.
- 성공과 실패 모두에서 요청 폴더를 삭제한다. 시작 시에는 오래된 서비스 소유
  요청 폴더만 복구 정리하며 진행 중인 요청은 제외한다.
- 결과는 `--output-last-message` 파일에서만 읽는다. stdout, stderr, 이벤트,
  인증 진단은 사용자 요약으로 전달하지 않는다.

인증 만료, 모델 지원 변경, 한도 소진은 각각 실패로 기록한다. 실제 값이나 Discord
원문은 로그·증거 문서에 남기지 않는다. 0.5.0의 검증은 합성 대화의 모델 호출까지이며,
실제 Discord 명령과 결과 게시의 연결은 0.7.0에서 검증한다.
