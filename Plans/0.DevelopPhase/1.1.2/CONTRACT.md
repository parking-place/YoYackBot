# 1.1.2 이모지·주제별 한줄 비평·짧은 기본 요약 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 출시된 `v1.1.1a`(2026-10-01) 코드를 기준으로 작성했다.

## 문제 (사용자 요청, 2026-10-01)

1. 요약이 글자만 빽빽해 훑어보기 어렵고 재미가 덜하다. 이모지를 적극적으로 써서 **가독성과 재미**를 높인다.
2. `v1.1.1a`의 주제별 비아냥 줄(`↳ *…*`)은 “주제마다 **최대** 한 줄”이라 실제로는 빠지는 주제가 많다. 1.1.1a 실제 평가(합성 대화 12건)에서 주제 묶음 가운데 상당수가 비아냥 줄 없이 끝났다. 주제마다 짧은 한줄 비평을 **다시 꼭** 붙인다.
3. 기본(짧게) 요약이 화자별 불릿(`- **가람**: …`)이라 짧게라도 길다. 짧게는 **주제마다 내용만 1~2줄**로 줄인다. `길게`·`자세히`는 지금 형식(주제 묶음 + 화자별 불릿)을 유지한다.
4. 도움말을 새 형식에 맞게 고친다.

## 1. 이모지

| 위치 | 규칙 |
|---|---|
| 주제 소제목 | **앞에 이모지 1개 필수**(지금은 “1개까지” 허용). 주제와 어울리는 것으로 고른다(예: 🚀 배포, 🧯 장애, 🏖️ 여행, 💸 돈) |
| 결정·진행 중 표시 | 짧게 `✅ **결정**:` / `⏳ **진행 중**:`, 길게·자세히 묶음 소제목 `**✅ 결정 난 거**` / `**⏳ 진행 중인 거**` |
| 본문 줄 | **개수·위치 제한 없이 마음껏**(사용자 결정). 문장 앞뒤·낱말 옆 어디든 여러 개 써도 된다 |
| 주제 한줄 비평 | 마음껏(예: `↳ *요일 하나에 판이 뒤집혔구려.* 🙄🤦‍♂️`) |
| 떡밥 한줄 평가 | 머리말 `**요약창섭의 떡밥 한줄 평가** : ` 뒤 평가 문장에 마음껏. 머리말 글자는 그대로 |

- 제한은 다음뿐이다: 화자 이름·숫자·시간·금액 글자 **사이**에 끼워 넣어 글자를 깨뜨리지 않는다(앞뒤는 괜찮음). 이모지로 사실을 대신하지 않는다(👍로 찬성을 표현하는 식 금지 — 찬성은 글로 쓴다). 이모지가 사람·집단을 비하하는 뜻으로 쓰이면 안 된다.
- 추가 요청(1.1.1)이 `이모지 빼고`처럼 말하면 그쪽을 따른다(형식 규칙이므로 추가 요청이 이김).

## 2. 주제별 한줄 비평

- **모든 길이**에서 주제 묶음마다 **정확히 한 줄** `↳ *…*`을 그 묶음 끝에 붙인다. 이름을 “비아냥 줄”에서 “주제 한줄 비평”으로 바꾼다.
- 짧고 신랄한 한 문장(대략 40자 이내), 하오체, 비속어 허용. 그 주제에서 **실제로 한 말과 행동**(말바꿈·헛짚음·딴소리·호들갑)을 비꼰다. 1.1.1a 규칙대로 결론 없음·미룸·지연은 소재로 쓰지 않고, 새 사실을 보태지 않으며, 금지선(집단 비하·인신공격·성적 묘사)을 지킨다.
- `결정 난 거`/`진행 중인 거` 묶음(길게·자세히)은 주제가 아니므로 비평 줄을 붙이지 않는다.
- 맨 끝 **떡밥 한줄 평가**(대화 전체 비평)는 그대로 둔다. `평가 빼줘`는 떡밥 한줄 평가만 빼고, 주제 한줄 비평은 `비평 빼줘`/`비아냥 빼줘`처럼 따로 요청하면 뺀다(추가 요청 우선).

## 3. 짧게(기본) 형식

```text
**🚀 배포 날짜**
금요일 오후 2시 안이 주말 대응 인력 문제로 막히자, 가람이 목요일 오후 2시로 바로잡았소. ✅ **결정**: 목요일 오후 2시 배포.
↳ *요일 하나 헷갈려서 판을 한 바퀴 돌렸구려.* 🙄

**🧯 롤백 담당**
라온이 롤백 담당을 물었고 가람은 다음 회의에서 정하자고 했소. ⏳ **진행 중**: 롤백 담당.
↳ *롤백 소리만 나와도 다들 등골이 서늘한 모양이오.*

**요약창섭의 떡밥 한줄 평가** : 달력 한 장 두고 이렇게 요란 떨 일이오? 🔥
```

(합성 예시. 실제 대화나 사용자 보고 내용이 아니다.)

- 주제 2~4개. 주제마다 **소제목 1줄 + 내용 1~2줄 + 주제 한줄 비평 1줄**. 내용 줄은 불릿 없이 문장으로 쓰고, 화자별로 나누지 않는다.
- 이름은 누가 했는지가 중요한 곳(결정·담당·정정·제안자)에만 쓴다. 서로 다른 사람의 의견을 한 사람 말처럼 합치지 않고, 이름을 쓰지 않을 때는 “찬반이 갈렸소”처럼 귀속 없이 적는다(1순위 화자 귀속 규칙은 그대로).
- 결정·진행 중은 내용 줄 안에 `✅ **결정**:` / `⏳ **진행 중**:`으로 짧게 표시한다. 결정·진행 중이 없으면 표시하지 않는다.
- 1.1.0a의 “불릿 최대 8개” 규칙은 짧게에서 없어지고, 대신 “주제당 내용 2줄 이하”가 목표다(넘쳐도 실패로 보지 않고 평가에서 센다).
- 추가 요청이 형식을 정하면 그쪽이 이긴다(예: 짧게 + `시간순으로 해줘`는 1.1.1 규칙대로 소제목 없는 순서 목록).

## 4. 길게·자세히

- 지금 형식(주제 묶음 + `- **화자**: …` 불릿, 결정·진행 중 묶음)을 유지한다. 바뀌는 것은 이모지 규칙(1절)과 주제마다 한줄 비평 필수(2절)뿐이다.

## 5. 코드 검사 (보조)

- 출력 형식 지표 `topic_critique`: 주제 소제목 수와 그 아래 `↳` 줄 수를 세어 `all`(모든 주제에 1줄)·`partial`·`none`·`na`(소제목 없음, 예: 시간순 요청)를 지표 로그에 남긴다. 재생성은 하지 않는다(사용자 결정 기본안). 원문은 로그에 남기지 않는다.
- 1.1.1a의 미결 조롱 검사는 주제 한줄 비평에도 그대로 적용된다(비평 줄이 늘어 재생성이 늘 수 있으므로 P3에서 `ongoing_jab` 빈도를 본다).
- 메시지 분할(Discord 2,000자)·평가 줄 분리 규칙은 이모지가 섞여도 그대로 동작해야 한다(UTF-16 길이 기준).

## 6. 도움말

- 기본 설명을 “최근 1시간의 대화를 주제별로 1~2줄씩 짧게 요약하오(주제마다 한줄 비평).”로, `길게`는 “주제별로 화자별 흐름과 결정·진행 중인 이야기까지”로 고친다. 추가 요청 예에 `이모지 빼고`를 한 번 넣는다. 2,000자 미만 유지.
