# 1.0.0b — 100건 초과 요약 실패 수정

> **폐기·대체(SUPERSEDED)** — 이 계획의 남은 단계는 실행하지 않는다. 현행 계획은 [1.0.0b-1](../1.0.0b-1/README.md)이다. 아래 내용은 당시 계획과 P1 완료·P2 중단 이력을 보존한 것이다. `v1.0.0b` 태그/출시는 만들지 않는다.

선행: [1.0.0a](../1.0.0a/README.md). P1만 원격 완료했고 P2는 코드 후보만 push한 뒤 새 계획으로 이관했다. 이 버전의 제품 검증·배포는 완료되지 않았다.

100건 초과 대화 요약의 실패를 수집·입력·모델·대기열로 분리해 원인을 찾고 수정한다. 운영의 원문 없는 집계에서는 100건 초과 요청 6건 중 모델 오류 3건(선택 298/858/574건), **수집 후 모델 대기열** 시간 초과 3건(300/200/150건, 약 60초)이었다. 이전 모델 오류의 상세 원인은 기록되지 않았고, 합성 대량 입력에서는 CLI 진단 출력의 작은 버퍼가 별도 실패 원인으로 재현됐다.

사용자의 추가 요청에 따라 **새 주시 채널은 조회 가능한 최근 30일 이내의 과거 기록을 백그라운드로 최대한 초기 수집**한다. 그 사이와 이후의 새 대화는 기존 Gateway 경로로 즉시 DB에 저장하고, 30일이 지난 기록만 정리한다. 이 버전은 5단계에서 **6단계**로 확대한다. 실제 고부하 채널의 조회 시간은 1시간 2.1초, 1일 55.5초, 7일 160.2초, 조회 가능한 전체 218.8초여서 현행 30초·100페이지 제한을 초기 수집에 그대로 적용할 수 없다. 상세한 개인정보 없는 수치는 [P3](03-backfill.md)에 기록한다.

새 주시 채널에는 시작 시 `안녕하시오. 요약을 위해 데이터 수집중이오.`, 완료 시 `이제부터 요약을 해줄 수 있을 것 같소.`를 각각 한 번 보낸다. 초기 수집 중 `!!요약좀` 요청에는 `참을성을 기르시오 아직 준비가 되지 않았소.`라고 답한다. 부분 수집을 완료로 속이지 않고 시작·완료 알림의 중복을 막는다.
