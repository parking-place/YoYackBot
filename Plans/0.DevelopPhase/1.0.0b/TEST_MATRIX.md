# 1.0.0b 검증 목록

계획 게시 시 모두 **NOT_RUN**이다. 운영의 원문 없는 집계는 원인 진단의 입력일 뿐 제품 검증 PASS가 아니다.

| ID | 단계 | 합격 조건 | 결과 |
|---|---|---|---|
| B1 | [P1](01-diagnose.md) | 각 건수의 실패 지점이 수집·입력·모델·대기열 중 어디인지 같은 SHA의 로그와 시험에서 구분된다. | NOT_RUN |
| B2 | [P1](01-diagnose.md) | 원문·닉네임·사용자/채널 ID·토큰이 새 지표에 포함되지 않는지 확인한다. | NOT_RUN |
| B3 | [P2](02-input.md) | 101~1000건 합성 자료의 선택 건수·실제 포함 건수·입력 바이트·출력을 대조해 100건 초과 성공을 확인한다. | NOT_RUN |
| B4 | [P2](02-input.md) | 긴 본문·Unicode·삭제/편집 메시지에서 중간 처리의 누락·중복, 시간순 붕괴, 원문 로그 유출이 없는지 확인한다. | NOT_RUN |
| B5 | [P3](03-queue.md) | 120초 모델 실행 뒤 두 번째 요청이 60초에서 만료되던 시나리오와 새 정책의 성공/명시적 만료를 시간 제어 시험으로 비교한다. | NOT_RUN |
| B6 | [P3](03-queue.md) | 포화·취소·서비스 종료·채널 교차 요청에서 무한 대기나 슬롯 누수가 없는지 확인한다. | NOT_RUN |
| B7 | [P4](04-recovery.md) | 각 실패를 주입한 뒤 잠금 해제·파일 정리·쿨타임 미적용·다음 요청 성공을 확인한다. | NOT_RUN |
| B8 | [P4](04-recovery.md) | 동일 채널 중복·다른 채널 독립 작업·1.0.2의 계획된 시작 안내와 응답 상태가 충돌하지 않는지 확인한다. | NOT_RUN |
| B9 | [P5](05-release.md) | 100건 초과 여러 크기의 게시 성공과 상한 초과의 정확한 실패 안내를 확인한다. | NOT_RUN |
| B10 | [P5](05-release.md) | 배포 후보·서비스 SHA, 실제 시험 게시 여부, 롤백과 단계별 C/E/D·필요 CI를 확인한다. | NOT_RUN |

각 단계의 두 검사와 C/E/D 원격 반영·필요 CI 확인 뒤에만 [상태](STATUS.md)를 DONE으로 바꾼다.
