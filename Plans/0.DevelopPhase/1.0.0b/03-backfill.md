# 1.0.0b-P3 — 최초 주시 채널 30일 초기 수집

> 이 계획은 [1.0.0b-1](../1.0.0b-1/README.md)로 **폐기·대체**됐다. 아래는 구현되지 않은 당시 요구 기록이다.

상태: **SUPERSEDED**. 검사: `B5/B6`는 이 버전에서 미실행이다.

## 작업

관리자가 채널을 새로 주시 목록에 저장하거나, 주시 채널의 기록 조회 권한이 다시 생기면 그 시점부터 **조회 가능한 최근 30일 이내 기록**을 백그라운드로 수집한다. 주시 설정의 저장 응답을 오래 기다리게 하지 않는다. 초기 수집 중 도착하는 새 일반 사용자 메시지는 기존 실시간 경로로 즉시 DB에 upsert하고, 과거 페이지와 메시지 ID로 중복 제거한다. 수집의 목표 컷오프는 시작 시각 기준 30일이며, 정기 정리도 계속 30일 이전 자료만 삭제한다.

새로 주시를 시작한 채널에는 수집 시작 시 `안녕하시오. 요약을 위해 데이터 수집중이오.`를 한 번 게시한다. 수집이 완전히 끝나고 누락 여부를 확인한 뒤 `이제부터 요약을 해줄 수 있을 것 같소.`를 한 번 게시한다. 그전의 `!!요약좀` 요약 요청에는 `참을성을 기르시오 아직 준비가 되지 않았소.`로 답하고 모델 작업을 시작하지 않는다. `!!요약좀 도움`은 계속 사용할 수 있다. 시작·완료 게시 상태를 영속 저장해 재시작·재시도 후 같은 안내를 중복 게시하지 않는다. 주시 해제·권한 거부·부분 수집 상태에서는 완료 안내를 보내지 않는다. 기존에 이미 주시 중인 채널의 배포 후 보충은 새 주시 알림과 구별한다. 이 일회성 안내는 1.0.2의 요청별 수집 안내와 별개다.

현재 고부하 시험 채널의 기록 조회는 1시간 5페이지/2.1초, 1일 53페이지/55.5초, 7일 153페이지/160.2초, 조회 가능한 전체(14·30일) 207페이지/218.8초였다. 초기 수집에는 요청별 30초·100페이지 상한을 그대로 적용할 수 없다. 페이지 묶음 단위로 진행 상태를 영속 저장하고 잠시 양보하면서 끝까지 이어간다. 재시작 후 미완료 채널을 재개하되, Discord의 페이지 순서·권한·주시 revision을 다시 확인한다. 동시 초기 수집 수와 디스크 사용량은 유한하게 제한하고, 한도에 닿으면 완료로 속이지 않고 부분/실패 상태를 남긴다. 새 상태 테이블은 기존 schema 5의 선택적 확장으로 두어 1.0.0a 코드가 읽을 수 있게 한다.

## 통과 기준

- `B5`: 첫 주시 저장 뒤 시작 안내가 한 번 게시되고 최근 30일의 조회 가능한 일반 사용자 기록이 페이지를 넘어 중복·누락 없이 쌓이며, 수집 중 새 메시지가 즉시 저장된다. 완료 후에만 종료 안내를 한 번 게시한다. 30일보다 오래된 기록과 봇·웹훅·명령 메시지는 제외한다.
- `B6`: 초기 수집 중 모든 요약 요청에 정확한 대기 안내를 보내고 모델을 실행하지 않는다. 200페이지 이상 합성 History, 중간 재시작·권한 회수/복구·주시 해제·429/네트워크 재시도·용량 한도에서 재개/중지/부분 상태와 안내의 한 번만 게시를 확인한다. 완료하지 못한 범위를 `30일 전체 확보`로 표시하지 않는다.

결과·동일 구현 SHA를 [검증 목록](TEST_MATRIX.md)에 남긴다. **이 단계만의 C(구현) → E(증거) → D(종료)를 각각 commit·GitHub push하고 원격 포함 관계·필요 CI를 확인해야 DONE**이다. 실패·미실행은 PASS로 세지 않는다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
