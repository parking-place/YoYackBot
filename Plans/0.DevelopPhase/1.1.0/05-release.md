# 1.1.0-P5 — 도움말·통합·배포·출시

- 상태: **PUSH_PENDING** · 검사: `T110-P5-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P4](STATUS.md)의 원격 완료를 확인한다. [계약](CONTRACT.md) 4절대로 `!!요약좀 도움`을 고치고(2,000자 미만), README·주시 채널 안내·`CHANGELOG`·`docs/upgrade-rollback-1.1.0.md`(복귀 대상 `v1.0.2c`, schema 변경 없음, 복귀 시 기본 요약이 다시 길어지고 추가 요청 문장은 사용법 안내가 된다는 점)를 갱신한다. 패키지·`VERSION`을 `1.1.0`으로, 저장소 검증기에 1.1.0의 5단계·10검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, **진행 중 요약이 없음을 확인하고** 이전과 같은 절차(DB 온라인 백업·설정 백업·wheel 설치·checkout 일치·`check-ready`·health·DB 무결성)로 배포한다. 이전 `v1.0.2c` wheel로의 복귀 호환성은 격리 합성 DB로 확인한다.

배포 뒤 사용자가 시험 채널에서 직접 확인한다: `!!요약좀`(짧게), `!!요약좀 길게`, `!!요약좀 [범위] 자세히`, `!!요약좀 2분 길게 시간순으로 해줘`, 오인 입력 1건(`!!요약좀 자세히 2시간`), `!!요약좀 도움`. 계정 한도를 아끼도록 실제 요약은 최소 건수로 한다. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T110-P5-A`: 전체 회귀(범위·길이·추가 요청·사용량·상태·채널·시작/진행 중 안내·준비 상태·쿨타임·말투 검사)와 도움말·버전·문서 링크를 같은 SHA에서 확인한다.
- `T110-P5-B`: 후보 SHA와 서비스 SHA를 대조하고, 시험 Discord 결과를 사용자 확인과 서비스 로그(모드·추가 요청 유무·결과)로 대조하며, 배포·복귀·비밀정보 비노출·P1~P4 원격 증거를 기록한다. 필수 검사 FAIL/NOT_RUN은 DONE으로 세지 않는다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합하고 병합 후 `main` CI 결과를 확인해 기록한다. 태그 `v1.1.0`과 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
