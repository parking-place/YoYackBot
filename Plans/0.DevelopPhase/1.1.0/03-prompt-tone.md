# 1.1.0-P3 — 길이별 프롬프트·싸가지 말투

- 상태: **IN_PROGRESS** · 검사: `T110-P3-A/B` · 환경: 개발 LXC, 합성 대역(모델 호출 없음)

## 선행 조건·작업

[P2](02-request-note.md)의 원격 완료 뒤, 신뢰 프롬프트를 새 길이 규칙에 맞춘다: 기본·`짧게`는 본문 4~6줄, `길게`는 현행 기본 구성(화자별 흐름 + 결정·남은 점), `자세히`는 아주 긴 버전(화자별 주장·근거·반론·정정, 시간 순서, 결정·남은 점을 빠짐없이). [계약](CONTRACT.md) 3절에 따라 말투 단락을 더 띠껍고 비꼬는 방향으로 고치고 하오체 종결과 금지선 우선을 유지한다. 프롬프트 버전을 `1.1.0-p3-v1`로 올린다. 집단 비하어 재시도는 유지한다.

## 검증·완료 기준

- `T110-P3-A`: 세 길이 × (일반·화자 재시도·비하어 재시도) 프롬프트가 각 길이 지시·말투·금지선·추가 요청 규칙을 포함하고 순서(사실·신뢰 경계 → 추가 요청 규칙 → 말투 → 길이)가 고정된다. 봇 안내 문구는 모드 표시 외에는 이전과 같다.
- `T110-P3-B`: 비하어 재시도·안전 실패, 허용 비속어 오탐 없음, 긴 `자세히` 출력의 Discord 분할(1,900자 단위·순서·멘션 비활성)과 출력 상한이 유지된다.

같은 SHA의 결과를 기록하고 구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 각각 commit·GitHub push·원격 확인한다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
