# 1.0.0c — 여러 채널 동시 요약 최적화

상태: **P1~P2 완료, P3 진행 중**. 선행: [1.0.0b-1](../1.0.0b-1/README.md)의 실제 원격 완료. 제품 구현·검증·배포는 시작하지 않았다.

여러 채팅 채널의 요약 요청이 동시에 들어와도 공정하게 DB 조회·모델 실행·게시되도록 한다. 1.0.0b-1에서 추가한 여러 채널의 첫 30일 전체 수집과 이후 실시간 DB 수집도 같은 DB·Discord rate limit을 쓰므로, 초기 수집과 일반 요약이 서로 굶기지 않는지 함께 측정한다. 동일 채널의 중복 요청 차단, 다른 채널·서버의 데이터 분리, 성공 후 채널별 5분 쿨타임, 유한한 대기열을 유지한다. 모델 병렬 수를 무조건 늘리지 않고 처리량·지연·계정 한도를 함께 측정한다.

|---|---|---|---|
| 1 | [동시 부하 기준선](01-baseline.md) | C1/C2 | DONE |

| 5 | [다중 채널 통합·출시](05-release.md) | C9/C10 | PLANNED |

각 단계의 완료는 **해당 단계 구현·개발 LXC 검증·증거 기록·독립 C/E/D 커밋의 GitHub push·원격 반영/필요 CI 확인**까지다. [Git 완료 규칙](../GIT_WORKFLOW.md)을 따른다. [검증 목록](TEST_MATRIX.md)은 모두 NOT_RUN, [상태](STATUS.md)는 모두 PLANNED이다. 실제 Discord 게시와 합성 검사는 분리 기록하고 8/24시간 연속 시험은 요구하지 않는다.

태그 `v1.0.0c`, 패키지 `1.0.0.3`은 [버전 대응표](../PATCH_VERSIONING.md)를 따른다.
