# 1.4.0 계약 — 처형 기능과 서버별 말투 확장

이 문서는 구현 목표다. 기준 코드는 출시된 `v1.3.4`(`1491025`)이다. “사용자 결정”은 2026-10-07 사용자 계획과 답변이고, “기본안”은 계획에 없는 세부를 개발자가 정한 것이다(사용자 확인으로 바뀔 수 있음).

## 1. 처형 설정 (P1)

- `/처형설정 채널관리`: 처형 로그를 올릴 텍스트 채널 **하나**를 고르거나 해제한다(기본안: 서버당 한 채널). 처음에는 없음이며, 없으면 로그를 올리지 않는다(사용자 결정). 관리자·채널 관리 권한·봇 관리 역할만 쓸 수 있다(1.1.3 판정, 사용자 결정). 봇이 그 채널을 보고 쓸 수 없으면 저장하지 않는다.
- `/처형설정 관리역할`: `/처형`을 쓸 수 있는 역할을 고른다. **서버 관리자만** 쓸 수 있다(사용자 결정). `@everyone`·연동 관리 역할은 고를 수 없다.
- 화면은 기존 설정 화면과 같다: 연 사람만, 누를 때마다 권한 재확인, 120초.
- 저장: 선택 테이블 `execution_settings`(서버, 로그 채널)와 `execution_roles`(서버, 역할). 서버 탈퇴·채널 삭제·역할 삭제 때 정리한다. 설정 백업에 포함한다.

## 2. 감사 로그 감시와 처형 로그 (P2)

- Gateway에서 서버 감사 로그 생성 이벤트를 받는다(`moderation` intent, 봇의 감사 로그 보기 권한 필요). 대상은 멤버 갱신 중 **타임아웃이 걸리거나(적용·연장) 풀린(해제)** 항목이다(사용자 결정).
- 로그 채널이 정해져 있으면 한 메시지를 올린다.
  - 처형자(감사 로그의 실행자), 처형인(대상), 적용이면 끝나는 시각과 길이, 사유(없으면 “사유 없음”)를 담는다.
  - 사람 표시는 멘션 모양이지만 알림은 보내지 않는다(`allowed_mentions` 없음, 기본안).
- `/처형`으로 봇이 실행한 타임아웃은 감사 로그의 실행자가 봇이다. 이때는 명령을 실행한 사람을 처형자로 올리고(사용자 결정), 같은 일을 두 번 올리지 않는다.
- 로그 채널 권한을 잃었거나 게시에 실패하면 경고 로그만 남기고 재시도하지 않는다(기본안). 사유 글은 서비스 로그에 남기지 않는다.

## 3. `/처형 대상 시간 사유` (P3)

- 옵션: `대상`(멤버, 필수), `시간`(선택, 기본 **30초**), `사유`(선택, 기본 **“내맴”**)(사용자 결정).
- 시간 형식(기본안): `30초`·`10분`·`2시간`·`1일`, 숫자만 쓰면 초다. 최소 1초, 최대 28일(Discord 한도)이다. 사유는 최대 400자이고 줄바꿈을 지운다.
- 쓸 수 있는 사람(기본안): `/처형설정 관리역할`로 정한 역할이 있는 사람, 그리고 서버 관리자.
- **권한 상승 방지**(기본안):
  - 대상이 자기 자신·봇·서버 주인·관리자 권한 보유자면 거절한다.
  - 대상의 최상위 역할이 실행자의 최상위 역할보다 같거나 높으면 거절한다(서버 주인이 실행하는 경우는 예외).
  - 봇의 역할 순서·권한으로 불가능하면 거절한다.
- 실행 결과와 거절 안내는 **실행자에게만** 보인다. 공개 기록은 처형 로그 채널에만 남는다(기본안).
- 이미 타임아웃 중이면 새 시간으로 덮어쓴다(Discord 동작).

## 4. 말투 프롬프트 분리 (P4)

- 요약·평가 후보·심사 프롬프트를 **고정 규칙**과 **서버 말투**로 나눈다.
  - 고정 규칙(고칠 수 없음, `/말투`에 보이지 않음): 사실·화자 귀속, 신뢰 경계, 진행 중 이야기를 비꼬지 말 것, 형식(소제목·비평 줄·평가 줄 위치), 금지선(비하·성적 표현·이름·숫자), 추가 요청 우선.
  - 서버 말투(고칠 수 있음): 어미(하오체), 입담, 비꼬기·빈정거림, 깔보는 태도, 비속어 정도, 성격, 소제목·비평·평가의 말맛.
- 지금 프롬프트 곳곳의 “하오체로 끝내시오” 같은 말투 지시는 말투 단락이 정하도록 옮긴다. 기본 말투 단락은 지금 동작과 같은 결과를 내야 한다.
- `/말투` 화면·수정 창·기본값은 말투 단락만 보인다. 이미 저장된 서버 말투는 그대로 말투 단락으로 쓴다.

## 5. 서버 말투 안내 문구 (P5)

- 봇이 서버에 보내는 고정 안내 문구를 목록(키·기본 문구·자리표시자)으로 모은다. 대상은 도움말, 요약 시작·대기·실패·쿨타임, 상태·사용량·채널 목록 안내, 설정 화면 문구, 처형 로그·`/처형` 안내 등이다. `!!말하자면`·`/말하자면`의 결과·안내는 제외한다(사용자 결정).
- 서버 말투를 저장하면 그 서버의 안내 문구 전체를 `gpt-6-luna`·추론 강도 **high**로 그 말투에 맞게 다시 쓴다(사용자 결정). 백그라운드에서 한 번 생성하고 서버별 DB 표 `guild_notices`(서버, 키, 문구, 말투 버전)에 저장한다(사용자 결정: DB).
- **검증**(기본안): 생성 문구는 다음을 지켜야 한다. 그렇지 않은 항목은 기본 문구를 쓴다.
  - 자리표시자(숫자·시간·채널·명령 이름)를 그대로 유지한다.
  - `/명령`·`!!명령` 표기를 바꾸지 않는다.
  - 길이는 기본 문구의 3배 이하, 도움말은 2,000자 이하다.
  - 비하어가 없고, 멘션 모양 글이 없다.
- 기본 말투로 되돌리면 저장한 문구를 지우고 기본 문구를 쓴다. 생성이 끝나기 전·실패하면 기본 문구를 쓴다. 생성 결과(성공 개수·실패)를 `/말투` 연 사람에게 알리고, 서비스 로그에는 개수만 남긴다.
- 안내 문구를 보내는 모든 곳이 서버별 문구를 찾아 쓴다(없으면 기본 문구).

## 6. 평가 (P6)

- 말투 분리 뒤 기본 말투로 1.3.0 평가 세트(요약 16건)·품질 세트를 돌려 1.3.4와 같은 수준(금지 소재·비하어·키 노출 0, 하오체 유지)인지 본다.
- 서버 말투 2종(점잖은 보고서체·일부러 위험한 문구)으로 안내 문구를 생성한다. 검증 통과율, 자리표시자 유지, 금지선을 확인하고 예시를 사용자가 확인한다.
- 처형 로그·`/처형`은 시험 서버에서 사용자 확인(P7)으로 실제 동작을 본다.

## 7. 호환·복귀

- schema 5를 유지하고 선택 테이블만 더한다. 복귀 대상은 `v1.3.4`이며, 복귀하면 처형 기능·서버별 안내 문구가 사라진다. 저장한 말투는 1.3.4의 말투 단락으로 그대로 쓰인다.
- 1.3.4로 복귀한 동안 봇이 서버를 나가면 새 표의 행이 남을 수 있다. 1.4.0이 다시 접속하면 봇이 들어가 있지 않은 서버의 처형 설정·안내 문구 행을 정리한다(기본안).
