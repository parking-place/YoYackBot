# 1.3.0-P6 — 도움말·통합·배포·출시

- 상태: **PLANNED** · 검사: `T130-P6-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P5](STATUS.md)의 원격 완료를 확인한다. 도움말은 그대로 둔다([계약](CONTRACT.md) 4절). `docs/channel-settings.md`에 `/말투`와 답장 범위를, README·`CHANGELOG`·`docs/upgrade-rollback-1.3.0.md`를 갱신한다. 복귀 대상은 선행 출시 1.2.0이며 태그·wheel·정확한 checkout SHA를 P1 증거와 대조해 적는다(계획 작성 시점 미정). schema 5를 유지하고 복귀하면 서버 말투·최근 평가 표는 무시되어 기본 말투·이전 평가 방식으로 돌아가되, 1.2.0의 B01~B14 수정·F02·F10은 유지한다. `v1.1.3a`/wheel `1.1.3.1`/`d51c72a`는 이전 계획의 역사적 복귀 근거일 뿐 이 버전의 복귀 대상으로 사용하지 않는다. 패키지·`VERSION`을 `1.3.0`으로, 버전 대응표와 저장소 검증기에 1.3.0의 6단계·12검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 진행 중 요약이 없음을 확인하고 이전과 같은 절차로 배포한다. 확정된 1.2.0 wheel로의 복귀 호환성은 F02·F10·서버 말투·최근 평가 표가 함께 있는 격리 합성 DB로 확인한다. 1.2.0 → 1.3.0 → 1.2.0 → 1.3.0 순서로 기동하고, 복귀 중 메시지 수정·삭제·retention 정리·주시 해제·서버 탈퇴 뒤 고아 참조나 삭제 데이터 부활이 없는지 확인한다. FK 설정이나 구버전 정리 경로가 선택 테이블을 처리하지 못하면 정리 방법을 먼저 확정하고 검증한다. 테이블 무시만 확인한 상태로 복귀 PASS를 선언하지 않는다.

배포 뒤 사용자가 시험 채널에서 확인한다: `/말투` 보기·수정·기본값으로, 바뀐 말투의 `!!요약좀`, 메시지에 답장으로 `!!요약좀`, 떡밥 한줄 평가(여러 번 요약해 겹치지 않는지). 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T130-P6-A`: 전체 회귀와 도움말·버전·문서 링크를 같은 SHA에서 확인한다. 선행 B01~B14·F02·F10의 회귀 및 선택 테이블 공존 시 삭제·정리·백업 경계를 포함한다.
- `T130-P6-B`: 후보·서비스 SHA 대조, 시험 Discord 사용자 확인과 서비스 로그(`tone_saved`·`tone`·`rating`·`rating_candidates`) 대조, 배포·확정된 1.2.0으로의 복귀 및 재업그레이드·비밀정보 비노출·P1~P5 원격 증거, 병합 후 `main` CI를 기록한다.

구현 C → 증거 E → (E CI 성공 확인) → 종료 D를 마친 뒤 `main`으로 PR·리뷰·병합한다. 태그 `v1.3.0`과 Release는 배포 코드 SHA의 최종 게이트 통과 뒤에만 만든다. [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다.
