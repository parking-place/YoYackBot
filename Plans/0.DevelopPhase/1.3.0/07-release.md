# 1.3.0-P7 — 도움말·통합·배포·출시

- 상태: **IN_PROGRESS** · 검사: `T130-P7-A/B` · 환경: 개발 LXC, 시험 Discord, GitHub CI

## 선행 조건·작업

[P1~P6](STATUS.md)의 원격 완료를 확인한다. 도움말은 그대로 둔다([계약](CONTRACT.md) 4절). `docs/channel-settings.md`에 `/말투`와 답장 범위를, README·`CHANGELOG`·`docs/upgrade-rollback-1.3.0.md`를 갱신한다. 복귀 대상은 선행 출시 1.2.0이며 태그·wheel·정확한 checkout SHA를 P1 증거와 대조해 적는다(계획 작성 시점 미정). schema 5를 유지하고 복귀하면 서버 말투·최근 평가 표는 무시되어 기본 말투·이전 평가 방식으로 돌아가되, 1.2.0의 B01~B14 수정·F02·F10은 유지한다. `v1.1.3a`/wheel `1.1.3.1`/`d51c72a`는 이전 계획의 역사적 복귀 근거일 뿐 이 버전의 복귀 대상으로 사용하지 않는다. 패키지·`VERSION`을 `1.3.0`으로, 버전 대응표와 저장소 검증기에 1.3.0의 7단계·16검사 집계를 넣는다.

정확한 후보 SHA로 LXC 자동 회귀를 돌린 뒤, 진행 중 요약이 없음을 확인하고 이전과 같은 절차로 배포한다. 확정된 1.2.0 wheel로의 복귀 호환성은 F02·F10·서버 말투·최근 평가 표가 함께 있는 격리 합성 DB로 확인한다. 1.2.0 → 1.3.0 → 1.2.0 → 1.3.0 순서로 기동하고, 복귀 중 메시지 수정·삭제·retention 정리·주시 해제·서버 탈퇴 뒤 고아 참조나 삭제 데이터 부활이 없는지 확인한다. FK 설정이나 구버전 정리 경로가 선택 테이블을 처리하지 못하면 정리 방법을 먼저 확정하고 검증한다. 테이블 무시만 확인한 상태로 복귀 PASS를 선언하지 않는다.

사자성어 명령의 고정 최신 30개·후보 4개·일반 단어 대체·고정 비하오체 한 줄·공통 쿨타임은 README·`docs/channel-settings.md`·변경 기록에 설명한다. 전용 명령은 기존 요약 도움말 불변 결정과 별개로 해당 문서에서 안내한다. 1.2.0으로 복귀하면 새 명령은 사라지되 추가 저장 상태가 없으므로 사자성어 데이터 이관은 필요하지 않다. 재업그레이드 후 전용 라우트가 다시 정상 동작하는지 확인한다.

배포 뒤 사용자가 시험 채널에서 확인한다: `/말투` 보기·수정·기본값으로, 바뀐 말투의 `!!요약좀`, 메시지에 답장으로 `!!요약좀`, 떡밥 한줄 평가(여러 번 요약해 겹치지 않는지), `!!말하자면`의 최근 대화에 맞는 한 줄·이모지와 서버 말투 미적용·일반 요약과의 공통 쿨타임. 확인하지 못한 항목은 `NOT_RUN`으로 남긴다.

## 검증·완료 기준

- `T130-P7-A`: 전체 회귀와 도움말·버전·문서 링크·7단계/16검사 집계를 같은 SHA에서 확인한다. 선행 B01~B14·F02·F10, 신규 사자성어 라우트·입력 30개·후보 4개·고정 말투·최대 3회·일반 요약과 자원 공유, 선택 테이블 공존 시 삭제·정리·백업 경계를 포함한다.
- `T130-P7-B`: 후보·서비스 SHA 대조, 기존 명령과 사자성어의 시험 Discord 사용자 확인 및 비식별 수치/상태 로그 대조, 배포·확정된 1.2.0으로의 복귀 및 재업그레이드·비밀정보 비노출·P1~P6 원격 증거, 병합 후 `main` CI를 기록한다. 운영 후보·선택 문구·원문은 로그나 공개 증거로 옮기지 않는다.

마지막 단계의 순서는 다음과 같다. P7-A와 P7-B의 배포·복귀·사용자 확인 등 출시 전 검증 및 P1~P6 원격 증거를 먼저 확인한다. 구현 C와 사전 증거 E_pre를 push하고 원격·CI를 확인하며 P7은 PUSH_PENDING으로 유지한다. 이후 `main`으로 PR·리뷰·병합하고 main CI와 검증·배포 코드의 일치를 확인한다. 코드가 달라지면 영향 검증을 다시 한다. 이 출시 전 게이트를 통과한 코드에만 태그 `v1.3.0`과 Release를 만든다.

병합 후 CI·태그·서비스 SHA까지 기록한 최종 증거 E를 main에 반영하고 CI 성공을 확인한 뒤, STATUS에 DONE을 기록하는 종료 D를 반영한다. D의 원격·필요 CI를 확인해야 단계 완료다. 보호 규칙과 [공통 Git 규칙](../GIT_WORKFLOW.md)을 따른다. 병합 후 결과를 요구하는 검사를 병합 이전의 종료 조건으로 사용하지 않는다.
