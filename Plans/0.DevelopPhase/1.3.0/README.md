# 1.3.0 — `/말투`·답장 범위·평가 다양화·사자성어 한마디

- 상태: **IN_PROGRESS** (`develop/1.3.0`, 1.2.0 후보 `613856e` 기준)
- 단계 수: **7단계·16검사**
- 선행 버전: 새 [1.2.0](../1.2.0/README.md)의 7단계 완료·출시·`main` 통합. 실행 기준 태그·정확한 SHA는 아직 미정이며 P1 착수 전에 확정한다.
- 계획 이력: 기존 1.2.0 계획을 먼저 `main`에 병합한 뒤 이 디렉터리로 이관했다. 최초 설계의 코드 근거는 출시된 [1.1.3a](../1.1.3a/README.md)(`v1.1.3a`, 2026-10-01)이며, 앞으로의 개발·배포·복귀 기준을 뜻하지 않는다.

## 목표

1. **`/말투`**: 관리자·봇 관리 역할이 서버별 말투·성격 프롬프트를 보고(기본값이 채워져 있음) 고쳐 저장한다(1,500자). 사실·신뢰 경계·금지선·형식은 고칠 수 없다.
2. **답장으로 범위 지정**: 메시지에 답장으로 `!!요약좀`을 쓰면 그 메시지부터 지금까지 요약한다(기간·개수를 함께 써도 답장 우선).
3. **떡밥 한줄 평가 다양화**: “화제가 튀어 정신없다”류를 금지하고, 후보 10개를 한 번에 만든 뒤 luna가 “정신없다류와 비슷한지”부터 심사해 1개를 고른다(호출 상한 5번). 채널별 최근 평가 20개를 기억해 겹침을 피한다.
4. **최근 30개 대화의 사자성어 한마디**: 최근 유효 메시지 최대 30개로 서로 다른 후보 4개를 만들고, 상황에 맞는 하나를 선택해 이모지를 붙인다. 적절한 사자성어가 없으면 일반 네 글자 단어를 사용한다. **`말하자면 안하무인? 🤔`**처럼 고정된 비하오체 한 줄로 말하며 서버 `/말투`는 적용하지 않는다. 사용자 확정 전용 명령은 `!!말하자면`이다.

방식·화면 흐름·검사·호출 수·실패 대체·사용자 결정은 [계약](CONTRACT.md)에 있다. 선행 1.2.0은 Improvements의 B01~B14와 추가 기능 F02·F10만 처리한다. F10은 이미 선택한 범위 안 메시지의 답글 관계를 연결하는 기능이고, 이 버전의 답장 범위는 명령의 답장 대상을 시작 경계로 정하는 기능이다.

선행 1.2.0의 버그 수정·F02 수집 상태·F10 범위 안 익명 참조를 유지한다. schema 5의 선택 테이블이 함께 존재하는 DB에서 삭제·정리·백업 경계와 **1.2.0으로의 복귀 후 재업그레이드**를 검증한다. 이관 당시 6단계·12검사였으며, 2026-10-02 사자성어 추가 요청으로 P5를 신설하고 평가·출시를 P6·P7로 옮겨 **7단계·16검사**로 확장했다. 기존 요약의 사용자 결정·실제 모델 16건·도움말 불변은 유지하고 새 기능 평가 4건을 추가한다(합계 20건).

## 검증 방침

- 평가 줄: 실제 모델 12건에서 금지 소재 0건, 서로 다른 소재(같은 틀 반복 2건 이하, 최근 평가 기억과 겹치지 않음), 심사가 고른 번호가 유효, 사실·화자 오류 0, 요약 소요 시간 증가 기록.
- `/말투`: 서버 말투 2종(점잖은 보고서체, 그리고 일부러 위험한 문구를 섞은 합성 말투)으로 실제 모델 4건에서 말투 반영과 금지선 유지를 확인한다. 저장은 글자 수만 검사하므로, 위험한 문구가 프롬프트에서 1순위 규칙·금지 단락 아래에 머리말과 함께 들어가는지 합성 시험으로도 확인한다.
- 답장 범위: 합성 시험으로 경계(같은 채널·최대 기간·최대 개수·삭제된 대상·범위 옵션을 함께 쓰면 답장 우선)를 확인하고 시험 Discord에서 사용자가 확인한다.
- 사자성어: 합성 시험으로 최신 30개·후보 4개·선택 번호·고정 한 줄·일반 단어 대체·호출 최대 3회·공통 자원 제한을 확인한다. P6에서 실제 모델 4건으로 사자성어 의미·상황 적합성, 일반 네 글자 단어 대체, `/말투`와 원문 지시 미적용, 30개 밖 미참조를 확인한다.
- 실제 대화·닉네임·서버 이름은 공개 문서에 옮기지 않고 합성 예시만 쓴다. 서버 말투 내용은 로그·문서에 남기지 않는다.
