# 1.3.0 `/말투`·답장 범위·평가 다양화·사자성어 계약

이 문서는 구현 목표다. 현재 제품 동작이나 시험 PASS를 뜻하지 않는다. 최초 설계는 출시된 `v1.1.3a`(2026-10-01) 코드를 근거로 작성됐으며 기존 1.2.0 계획을 `main` 병합 후 1.3.0으로 이관했다. 앞으로의 실행·복귀 기준은 새 [1.2.0](../1.2.0/README.md)의 완료·출시 SHA다. 그 SHA는 아직 미정이며 P1 착수 전에 기록한다.

## 0. 선행 버전·호환성

- 선행 1.2.0의 B01~B14 수정과 F02 수집 진행·차단 원인, F10 범위 안 답글 연결을 유지한다. 1.2.0의 7단계 완료·출시·`main` 통합을 확인한 뒤 1.3.0을 개발한다.
- F10은 최종 선택 범위 안의 답글 관계를 요청별 익명 참조로 제공한다. 이 문서 2절은 **명령의 답장 대상부터 요약 범위를 정하는 별도 기능**이다. 범위 확정 뒤 F10을 적용하고, F10을 이유로 다른 채널·범위 밖 원문을 자동 수집하지 않는다.
- schema 5를 유지한다. 선행 F02·F10의 선택 테이블과 서버 말투·최근 평가 선택 테이블을 함께 열고, 각 데이터의 보존·주시 해제·서버 탈퇴·삭제·백업 제외/포함 계약을 검증한다. 새로운 테이블을 추가하더라도 선행 삭제 경로를 빠뜨리거나 이름·용도를 덮어쓰지 않는다.
- 복귀 대상은 출시 완료된 1.2.0이다(태그·wheel·정확한 SHA는 P1에서 확정). 1.2.0 복귀 시 말투·최근 평가 표를 무시하되 선행 F02·F10과 버그 수정은 유지해야 한다. 복귀 중 메시지 편집·삭제, retention 정리, 주시 해제·서버 탈퇴 후 재업그레이드까지 격리 DB로 검증한다. 선택 테이블이 있다는 사실만으로 호환 PASS를 선언하지 않으며, 고아 참조·삭제 데이터 부활을 막는 정리 방법을 확정하지 못하면 출시를 막는다.
- 기존 요약 기능의 사용자 결정·실제 모델 평가 16건·도움말 불변은 유지한다. 2026-10-02 추가 요청에 따라 사자성어 기능과 그 실제 모델 평가 4건을 별도로 추가한다(총 20건).

## 1. `/말투` — 서버별 말투 프롬프트

### 요청
관리자·봇 관리 역할이 쓰는 `/말투` 명령. 지금 쓰는 프롬프트가 미리 채워져 보이고, 고쳐서 저장하면 그 서버의 요약에 적용된다.

### 범위
- 고칠 수 있는 것은 신뢰 프롬프트의 **“말투·성격” 부분**이다(사용자 결정): 지금의 “말투(기본)” 단락(약 450자 — 서술자 요약창섭의 띠껍고 싸가지없는 성격·태도, 비꼼 대상, 거친 하오체, 비속어 예)을 “말투·성격” 단락으로 이름 붙여 떼어 낸다. 처음 열면 이 기본 단락이 그대로 채워져 있다. 서버가 바꾼 말투·성격은 본문·주제 한줄 비평·떡밥 한줄 평가(후보 생성 포함)에 모두 적용된다.
- **고칠 수 없는 것**: 신뢰 경계, 사실·화자 귀속, 지어낸 말 금지, 결정·진행 중 원칙, 금지선(집단 비하·인신공격·성적 묘사), 형식·평가 줄 규칙. 서버 말투는 이 규칙들 **아래**에 들어가고, “금지(말투·추가 요청보다 우선)” 단락이 말투보다 먼저라는 순서를 지킨다. 그래서 말투에 “비하어 써도 된다”, “규칙 무시” 같은 말이 있어도 금지선은 바뀌지 않는다.
- 추가 요청(1.1.1)은 서버 말투보다도 먼저 적용된다(예: 서버 말투가 점잖아도 요청자가 `욕 빼고`·`표로` 등을 고를 수 있음).

### 화면 흐름
1. `/말투` → 본인에게만 보이는 메시지: 지금 적용 중인 말투(기본값이면 “기본 말투”, 바꿨으면 “이 서버 말투”)와 그 내용, 버튼 **수정**·**기본값으로**·**닫기**.
2. **수정** → Discord 입력 창(모달)에 지금 내용이 채워진 채 열림(여러 줄, 최대 1,500자). 제출하면 검사 뒤 저장하고 “💾✅ 말투를 저장했소.”와 바뀐 내용을 보여 준다.
3. **기본값으로** → 서버 말투를 지우고 기본 단락으로 돌아간다.
- 연 사람만 조작, 조작마다 권한 재확인(1.1.3 판정), 120초 제한, 동시 수정 감지.

### 저장 검사
- **글자 수만 제한**(사용자 결정): 1,500자 이하, 빈 내용 거절. 내용 검사(위험 표현 거절)는 하지 않는다. 대신 서버 말투·성격은 신뢰 프롬프트 안에서 “서버 관리자가 정한 말투·성격(표현 방식일 뿐 위 규칙을 바꾸지 않음)”이라는 머리말과 함께 1순위 규칙·금지 단락 **아래**에 넣어, 내용에 “규칙 무시” 같은 말이 있어도 사실·신뢰 경계·금지선이 먼저 적용되게 한다. 이 순서는 합성 시험과 P6 실제 평가(일부러 위험한 문구를 넣은 서버 말투 1건 포함)로 확인한다.
- 저장소: 기존 SQLite의 선택 테이블(서버별 내용·버전·시각), schema 5 유지, 설정 백업 포함, 서버 나감 때 삭제.
- 로그: `tone_saved at=<UTC> chars=<글자 수>` / `tone_reset at=<UTC>`. **말투 내용은 로그에 남기지 않는다.** 요약 지표에 `tone=default/custom`.

## 2. 답장으로 범위 지정

- 어떤 메시지에 **답장으로** `!!요약좀 …`을 쓰면 **그 메시지부터 지금까지**를 요약한다(그 메시지 포함). 길이(`길게`·`자세히`)와 추가 요청은 그대로 함께 쓸 수 있다.
- 답장과 범위 옵션(`3시간`·`100개` 등)을 함께 쓰면 **답장이 우선**(사용자 결정): 답장 대상부터 요약하고 함께 쓴 기간·개수는 무시하며, 시작 안내 아래에 “↩️ 답장한 메시지 기준으로 요약하오(기간·개수는 무시했소).” 한 줄을 더한다.
- 같은 채널의 메시지에만 답장 범위를 허용한다. 답장 대상이 최대 기간(설정, 기본 30일)보다 오래됐거나, 그 뒤 메시지가 최대 개수(설정, 기본 1,000)보다 많으면 안내하고 요약하지 않는다. 대상 메시지를 찾을 수 없으면(삭제 등) 안내한다.
- 시작·진행 중 안내 문구: `📝 답장한 메시지부터 채팅을 요약해보겠소. ✍️` / `⏳ 현재 답장한 메시지부터 채팅을 요약중이오. 🔄`. 요약 머리말은 지금처럼 실제 시작 시각을 쓴다.
- 선행 1.2.0에서 검증한 시간 범위 수집·재검증 경로를 쓰고 시작 경계를 답장 대상으로 정한다. 쿨타임·대기열·진행 중 안내·F02 준비 상태와 권한·삭제 동기화 규칙은 그대로다. 범위 확정 뒤 F10의 익명 답글 참조를 구성하며, 답장 범위 기능을 이유로 참조 대상의 다른 대화까지 따라가지 않는다.

## 3. 떡밥 한줄 평가 다양화

### 문제
마지막 떡밥 한줄 평가가 거의 같은 내용으로만 나온다: “화제가 이리저리 튄다/왔다갔다 한다/정신없다/부산하다/요란하다/한 상 가득”. 1.1.2·1.1.2a 실제 평가 출력에서도 대부분이 이 틀이었다.

### 방식
1. **금지 소재**: 화제 전환·뒤죽박죽·정신없음·부산함·요란함·“한 상 가득”류를 평가 소재로 쓰지 않는다(1.1.1a의 결론 없음·미룸 금지도 유지). 프롬프트에 적고, 코드도 금지 표현 목록으로 후보를 거른다(예: `튀`, `왔다갔다`, `오락가락`, `정신없`, `부산`, `요란`, `한 상`, `뒤엉`, `이리저리`).
2. **후보 10개를 한 번에 생성**: 요약이 끝난 뒤 평가 전용 호출 1번으로 서로 다른 각도의 후보 10줄을 만든다(대화의 고유한 떡밥·말버릇·헛짚음·호들갑·뻔한 결론 등에서 각자 다른 소재). 금지 소재·이름·숫자·형식 위반·비하어·미결 조롱이 있는 후보는 코드가 버린다.
3. **luna가 심사해 1개 선택**: 남은 후보를 평가 심사 호출 1번(같은 `gpt-6-luna`)에 준다. 심사의 첫 기준은 **“주제가 바뀌어 정신없다”와 비슷한 소재인지**(사용자 결정)다: 후보마다 비슷함 여부를 판정해 비슷한 후보는 빼고, 남은 것 가운데 신랄함·이 대화에만 맞는 구체성·하오체·최근 평가와 겹치지 않음으로 **번호 하나**를 고르게 한다. 답 형식은 `비슷함: 번호들` / `선택: 번호`로 고정하고, 코드는 선택 번호가 유효하고 “비슷함”에 들지 않는지 확인한다.
4. 모든 후보가 비슷하다고 판정되거나 유효 후보가 0개면 **후보를 한 번 다시 만든다**(금지 소재를 더 강하게 적은 재생성 노트). 다시 만든 후보는 심사 없이 코드 거르기 뒤 첫 후보를 쓴다(호출 상한 안에서).
5. 요약 본문이 쓴 평가 줄은 버리고 고른 후보로 바꾼다. `평가 빼줘`면 후보·심사 호출을 하지 않는다.

### 최근 평가 기억 (사용자 결정)
- 채널마다 **최근에 게시한 떡밥 한줄 평가 20개**를 저장한다(주제 한줄 비평은 저장하지 않음). 후보 생성 프롬프트에 “최근에 쓴 평가 — 같은 소재·같은 틀을 피하라”로 넣고, 심사도 겹침을 기준으로 쓴다.
- 저장소: 기존 SQLite의 선택 테이블(채널별, 게시 시각, schema 5 유지). 21번째부터 오래된 것을 지우고, 대화 캐시 보존 기간(기본 30일)이 지난 것도 지운다. 채널을 주시 목록에서 빼거나 봇이 서버에서 나가면 지운다. 설정 백업에는 넣지 않는다(설정이 아닌 생성 결과).
- 저장되는 것은 모델이 만든 평가 문장뿐이며 원문 대화·이름은 들어가지 않는다(평가 줄 규칙상 이름·숫자 금지). 로그에는 남기지 않는다.

### 실패 대체
- 후보 호출 실패·유효 후보 0개 → 요약 본문의 평가 줄(금지 소재가 없을 때) → 없으면 평가 없이 게시.
- 심사 호출 실패·잘못된 답 → 남은 후보 중 첫 번째.
- 지표: `rating=picked/regenerated/fallback_summary/fallback_first/missing/skipped`, `rating_candidates=<유효 후보 수>`, `rating_similar=<심사가 비슷하다고 본 후보 수>`. 후보·평가 문장은 로그에 남기지 않는다.

### 호출 수
- 요약 한 건의 모델 호출 상한을 **3번 → 5번**으로 올린다(사용자 결정): 요약 1 + (문제 시 전체 재생성 1) + 후보 1 + 심사 1 + (모두 비슷하거나 유효 0개면 후보 재생성 1). 1.1.0a의 “평가 줄만 다시 만들기”는 후보 생성이 대신한다. 요약 대기 시간이 후보·심사 시간만큼 늘어난다(실제 평가에서 측정).

### 평가 줄 규칙 변경
- 지금은 평가 줄에 시간·숫자·담당자·결정·사람 이름을 쓰지 말라고 한다. 이름·숫자 금지는 유지하되, **그 대화의 떡밥 주제어는 짚어도 된다**(예: “라면 국물 하나로 철학 토론을 벌였구려”)로 바꿔 구체성을 허용한다(사용자 결정 기본안).
- 평가 예(합성): “📚 공부하자던 방이 어느새 야식 품평회가 되었구려 🍜”, “🔧 고장 원인은 못 찾고 서로 손가락질만 잘하는 꼴이오 👉”, “🎤 노래 고르는 데 쓴 시간이면 앨범 하나 냈겠소 💿”.

## 4. 도움말

- **그대로 둔다**(사용자 결정). 답장 범위·`/말투`·새 사자성어 명령은 `docs/channel-settings.md`·README·변경 기록에 적는다. 새 기능을 이유로 기존 요약 도움말 전체를 바꾸지 않는다.

## 5. 최근 30개 대화의 사자성어 한마디

### 호출·입력 범위

- 사용자 확정 전용 명령은 **`!!말하자면`**이다. 일반 요약의 마지막 평가와 별도로 호출하며, 자동 게시·자동 덧붙이기는 하지 않는다.
- 앞뒤 공백을 제거한 메시지 전체가 `!!말하자면`일 때 실행한다. 단어 뒤 옵션·반복·`!!요약좀`과 혼합된 명령형 입력은 고정 사용 안내만 보내고 모델을 호출하지 않는다. 일반 문장·인용 안에 등장하는 토큰은 실행하지 않는다. 새 명령 자체도 기존 명령과 같이 캐시/대화 입력에서 제외하며, 기존 `!!요약좀` 단독 계열의 문법·우선순위는 유지한다.
- 명령 접수 시 종료 경계를 고정하고 **같은 주시 채널의 최근 유효 메시지 최대 30개**를 읽는다. 30개란 메시지 수이며 발화자 수·대화 왕복 횟수가 아니다. 기존 필터를 통과한 일반 사용자 텍스트 기준으로 최신 30개를 고른 뒤 시간순으로 전달한다.
- 명령 자체·다른 명령·봇/시스템·삭제·현재 보존기간 밖 메시지는 제외한다. 1~29개면 있는 메시지만 사용하고, 0개면 “아직 읽을 대화가 없어. 💬”처럼 고정 안내를 하고 모델을 호출하지 않는다. 최근 1시간으로 제한하거나 부족분을 다른 채널·오래된 요약에서 채우지 않는다.
- 신규 수신·백필·cached/raw edit와 조회에서 동일한 명령 제외 판정을 적용한다. 1.2.0이나 복귀 중 저장된 `!!말하자면`도 조회 때 제외하고, 이 필터를 최신 30개 제한보다 먼저 적용한다. 일반 대화 → 명령 → 일반 대화 편집을 처리하며 명령 제외와 실제 삭제 tombstone을 혼동하지 않는다. 일반 요약에서도 새 명령이 대화로 섞이지 않아야 한다.
- 현행 캐시 COUNT 경로와 1.2.0의 준비·정합성 검증을 사용한다. 준비 미완료·검증 공백·권한 상실이면 실행하지 않는다. History/외부 검색/답글 대상의 추가 fetch는 없다. F10 참조도 선택된 30개 안에서만 구성한다.
- 숫자·기간·길이·추가 요청 옵션은 받지 않는다. 전용 명령이 답장이더라도 시작 범위를 바꾸지 않는다. 뒤에 옵션을 붙이면 한 줄 사용 안내만 보낸다. 현재 `max_messages`가 30 미만이면 설정 한도를 우회하거나 조용히 건수를 바꾸지 않고 사용 불가로 안내한다. 30개여도 기존 입력 byte 상한을 넘으면 실패 처리한다.

### 후보 4개 → 하나 선택·이모지

1. 같은 고정 입력으로 후보 생성 호출을 1회 한다. 서로 다른 **정확히 4개**를 구조화된 목록으로 받는다. 각 후보는 `term`(네 글자 표현), `kind`(`idiom` 또는 `word`)만 가진다. 대화에 적절한 실제 사자성어를 우선하고, 적절한 사자성어만으로 후보를 채우기 어려우면 상황에 맞는 일반 네 글자 단어로 보완한다. 부적절한 사자성어를 숫자 맞추기용으로 넣지 않는다.
2. 표현은 NFC 정규화 뒤 한글 완성형 음절 **4개**로 고정한다. 띄어쓰기·문장부호·숫자·이모지는 표현 안에 넣지 않는다. 중복·이름/식별값·금지 내용·형식 오류를 검사한다. 글자 수 검사만으로 실제 사자성어임을 검증했다고 주장하지 않는다.
3. 후보가 4개가 아니거나 중복/오류가 있으면 같은 입력으로 후보 묶음을 **1회만 다시 생성**한다. 원문의 명령을 신뢰 지시로 올리지 않으며 오류 원문을 프롬프트에 그대로 붙이지 않는다. 다시 검사해 유효 후보 4개가 안 되면 고정 실패 안내로 끝낸다.
4. 유효 후보 4개와 동일한 최근 대화로 **선택·이모지 호출 1회**를 한다. 결과는 `selected_index`(1~4)와 `emoji`만 받는다. 상황 적합성·뜻의 정확성을 먼저 보고 적절한 사자성어가 있으면 일반 단어보다 우선한다. 선택 단계에서 새 표현을 만들지 않는다.
5. 이모지는 코드의 작은 허용 목록(초기안: 🤔 🙃 😅 😏 🤝 🧩 💡 🎯) 중 하나로 받는다. 유효한 후보 번호인데 이모지만 누락/부적합하면 `🤔`를 붙인다. 허용 목록은 원문·서버 말투로 바뀌지 않는다.
6. 출력은 모델 문장 전체를 사용하지 않고 코드에서 **`말하자면 {선택한 표현}? {이모지}`** 한 줄로 조립한다. 예: **`말하자면 안하무인? 🤔`**. 후보·풀이·선정 이유·요약 제목·통계·기존 떡밥 평가 줄은 덧붙이지 않는다.

### 고정 말투·실패·자원

- **하오체를 사용하지 않는다.** 기본 하오체, 서버 `/말투`, 일반 요약의 추가 요청, 평가 후보 10개·최근 평가 20개를 이 기능에 적용하지 않는다. 결과와 이 기능의 진행/실패/쿨타임 안내는 별도 고정 문구를 사용한다. 예: “최근 대화를 살펴보는 중이야. 🔎”, “지금은 어울리는 네 글자를 고르기 어려워. 🤔”.
- 일반 네 글자 단어로의 대체는 **상황에 맞는 사자성어가 없을 때의 의미적 대체**다. 모델 장애·잘못된 선택을 성공으로 위장하는 대체가 아니다. 후보/선택 호출 오류, 유효하지 않은 선택 번호는 실패 안내로 끝내며 미선택 후보를 임의로 게시하지 않는다.
- 정상은 후보 1회 + 선택·이모지 1회 = **2회**, 후보 묶음 재생성을 포함하면 요청당 **최대 3회**다. 선택 실패 뒤 재호출은 없다. 일반 요약의 최대 5회와 구분해 기록하며 신규 모델이나 계정·독립 동시성 풀을 추가하지 않는다.
- 일반 요약과 기존 전역 모델 동시성·채널 작업 슬롯·성공 쿨타임(기본 60초)을 공유한다. 성공적으로 한 줄을 게시한 경우에만 공통 쿨타임을 적용한다. 한 채널에서 두 기능을 번갈아 호출해 진행 중 제한·쿨타임을 우회할 수 없어야 한다.
- 같은 채널에만 게시하며 전송 직전 권한·주시·입력 유효성을 재확인한다. 멘션·embed와 내부 화자/메시지 키 노출을 막는다. 원문 지시로 범위·후보 수·문체·금지선을 바꿀 수 없다.
- 새 DB 테이블·후보/결과 기억·설정은 추가하지 않는다. 일반 평가의 최근 20개 저장소에도 쓰지 않는다. 원문·후보·선정 이유·실제 식별값을 로그·설정 백업에 남기지 않으며, 고정 모드·결과 분류·선택 건수·후보 수·호출 수·소요 시간만 기록한다. 임시 입력 파일과 슬롯은 성공·오류·취소 모두 정리한다.

### 추가 요청과 계획 기본값의 구분

사용자 확정 사항은 명령 **`!!말하자면`**·최근 30개·후보 4개·한 개 선택·이모지·사자성어 우선/네 글자 단어 허용·고정 비하오체다. 한 줄 템플릿, 트리거 세부 정책·실패 분기·호출 상한·공통 쿨타임, 추가 실제 모델 평가 4건은 이를 구체화한 계획 기본값이다. 구현 결과·실제 모델 PASS를 뜻하지 않는다.

## 기존 요약 기능의 사용자 결정 (2026-10-02)

| 항목 | 결정 | 검토했던 다른 선택 |
|---|---|---|
| `/말투`로 고칠 범위 | **말투·성격 부분**(사실·신뢰 경계·금지선·형식은 고정) | 프롬프트 전체 |
| 말투 저장 검사 | **글자 수만 제한**(1,500자, 빈 내용 거절) | 위험 표현이 있으면 저장 거절 |
| 답장 + 범위 옵션을 함께 쓰면 | **답장 우선**(기간·개수는 무시하고 한 줄 안내) | 범위 옵션은 거절 안내 / 범위 옵션 우선 |
| 평가 후보·심사 | **후보 10개 + luna 심사(“주제가 바뀌어 정신없다”와 비슷한지가 첫 기준), 호출 상한 5번** | 후보 5개 / 심사 없이 코드 규칙 / 상한 4번 |
| 평가 줄 소재 | **떡밥 주제어 언급 허용(이름·숫자 금지 유지), 화제 전환·정신없음류 금지** | 주제어도 금지 유지 |
| 최근 평가 기억 | **채널별 최근 떡밥 한줄 평가 20개 기억**(주제 한줄 비평은 제외) | 기억하지 않음 |
| 도움말 | **그대로** | 답장·`/말투` 두 줄 추가 |
| 실제 모델 평가 | **16건**: 기본 말투 12건 + 서버 말투 2종 × 2건 | 더 많이 / 적게 |

위 16건은 기존 요약 기능 평가다. 이번 추가 기능은 5절과 [P5](05-idiom.md)에 별도로 정의하며, [P6](06-evaluation.md)에서 사자성어 4건을 더해 총 20건을 평가한다.
