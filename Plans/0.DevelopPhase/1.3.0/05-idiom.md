## 사용자 동작

사용자 확정 전용 명령은 **`!!말하자면`**이다. 일반 요약에 자동으로 붙이지 않는다. 명령 직전 현재 채널의 유효한 대화 메시지 최대 30개만 읽고, 서로 다른 후보 4개를 만든 뒤 하나를 선택해 이모지를 붙인다.

결과는 코드가 **`말하자면 {네 글자 표현}? {이모지}`** 한 줄로 조립한다. 예: `말하자면 안하무인? 🤔`. 하오체와 서버 `/말투`를 적용하지 않는다. 적절한 사자성어가 없으면 상황에 맞는 일반 네 글자 단어를 사용하며, 근거 없이 사자성어라고 설명하지 않는다. 후보 목록·풀이·선정 이유는 게시하지 않는다.

## 작업

1. `parser.py`와 `discord.py`에 독립 트리거 **`!!말하자면`**과 별도 기능 경로를 연결한다. `!!요약좀` 뒤의 추가 요청이나 별칭으로 해석하지 않는다. 단독 명령만 받으며 범위·길이·말투 옵션은 받지 않는다. 명령이 답장이어도 P3의 답장 범위로 바뀌지 않는다. 아래 트리거 정책을 적용하며 기존 `!!요약좀` 파서의 반복 트리거·도움말 우선 계약은 유지한다.
2. `cache_collector.py`, `message_store.py`, `range_request.py`의 검증된 COUNT 경로를 이용한다. 명령 접수 시 종료 경계를 고정하고 필터 뒤 최신 30개를 선택해 시간순으로 전달한다. 명령 자체·봇/시스템·명령 메시지·삭제·보존기간 밖 원문은 제외한다. 1~29개면 있는 대화만, 0개면 모델 호출 없이 안내한다. 추가 History·답글 대상 fetch는 하지 않는다.
3. 사자성어 전용 후보 생성·선택 프롬프트와 구조화 결과 검사를 만든다. 후보 4개·중복 제거·한글 네 글자·후보 종류를 검증하고, 선택 결과가 실제 후보 번호를 가리키는지 확인한다. 일반 요약 엔진의 하오체·평가 10개·최근 평가 20개·서버 말투는 이 경로에 전달하지 않는다.
4. 후보 생성 1회 → 선택·이모지 1회를 기본으로 한다. 후보 묶음이 불완전하면 같은 입력으로 1회만 다시 생성한다. 선택 단계까지 포함해 요청당 최대 3회이며 실패 시 무한 재시도·임의 후보 게시를 하지 않는다. 세부 실패 분기는 계약 5절을 따른다.
5. 기존 전역 모델 동시성·채널 작업 슬롯·성공 쿨타임을 일반 요약과 공유한다. 게시 직전 권한·주시·입력 유효성을 재확인하고 멘션·embed를 억제한다. 이 기능의 진행·실패 안내도 하오체 없이 고정한다. 새로운 DB 이력·후보 기억은 만들지 않는다.

## 검증·완료 기준

| 검사 | 실행과 합격 기준 | 결과 |
|---|---|---|
| `T130-P5-A` | 0/1/29/30/31개, 필터 대상이 섞인 입력, 동시 도착·동일 시각 경계, retention·삭제·준비 미완료·주시 해제·권한 회수·답장 명령을 현행 workflow로 검증한다. 최신 유효 메시지 최대 30개만 두 호출에 동일하게 전달하며 이전 원문·다른 채널·참조 대상 fetch가 0회다. 빈 입력·허용 한도 미달·준비 미완료에서 모델 호출이 없다. | NOT_RUN |
| `T130-P5-B` | 후보 정확히 4개·중복·한글 네 글자/NFC·잘못된 종류·구조·선택 번호·허용 이모지, 후보 재생성 성공/실패, 후보/선택 호출 오류를 검사한다. 정상 2회·후보 재생성 시 최대 3회, 최종 한 줄 고정 형식·후보 집합 소속을 보장한다. 서버 말투·원문 지시·추가 옵션으로 형식/범위가 변하지 않는다. | NOT_RUN |
| `T130-P5-C` | 일반 요약과의 병렬·동일 채널 경합·성공 쿨타임·취소·게시 실패·임시 파일 정리·입력 byte 상한·권한 재검사를 검증한다. 일반 요약 실행 중의 BUSY·쿨타임 안내도 이 명령에는 고정 비하오체로 전달한다. 성공 게시 때만 공통 쿨타임이 생기고 일반 요약의 5회 상한·최근 평가 저장·말투·도움말 동작은 유지된다. 원문·후보·선정 이유·실제 식별값이 로그/설정 백업에 추가되지 않는다. 전체 회귀 통과. | NOT_RUN |

`T130-P5-A`에는 독립 트리거 라우팅도 포함한다. 앞뒤 공백을 제외한 단독 `!!말하자면`만 실행한다. `!!말하자면 100개`, `!!말하자면 길게`, 반복·혼합 명령은 고정 사용 안내만 보내며 모델을 호출하지 않는다. 일반 문장/인용 안의 토큰, 봇·DM·비주시 입력은 실행하지 않는다. 새 명령이 대화 캐시에 저장되거나 이후 요약·사자성어 입력에 포함되지 않는지도 확인한다.

기존 1.2.0/복귀 중 캐시에 들어간 새 명령도 읽기 필터로 제외하며, 필터는 최신 30개 LIMIT보다 먼저 적용한다. 신규 수신·백필·cached/raw edit를 모두 검사하고 일반 대화 → 명령 → 일반 대화 편집도 정상 반영한다. 명령 제외를 영구 삭제 tombstone으로 처리하지 않는다. P5-C의 말투 검사는 BUSY·쿨타임뿐 아니라 준비 미완료·실패 안내도 포함한다. 비주시·DM처럼 기존에 무응답인 경계는 무응답을 유지한다.

같은 구현 SHA의 합성 검사 결과와 호출 수·선택 건수·한계를 증거에 남긴다. 구현 C → LXC 검증·증거 E → E의 원격 반영·CI 성공 → 종료 D의 원격 반영·필요 CI 확인 뒤 완료한다. 실제 사자성어의 의미·상황 적합성은 [P6](06-evaluation.md)에서 별도로 확인하며 합성 대역 PASS로 대체하지 않는다.
