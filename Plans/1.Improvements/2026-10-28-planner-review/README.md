## 검토 방법

- 네 기획자(에이전트)가 서로 독립적으로, 읽기 전용으로 같은 커밋을 검토했다. 소스·테스트·문서·증거를 읽었고, 운영 서버 접속·실제 모델 호출·Discord 접속·테스트 실행은 하지 않았다(UX 검토자만 순수 파서 함수 두 개를 로컬에서 직접 불러 확인).
- 통합 단계에서 한 가지 사실만 운영 LXC에서 확인했다. 배포 전 DB 사본이 남아 있는지(QA-07)로, 파일 이름·크기·날짜만 봤다(아래 "통합 중 확인한 사실").
- 근거 `경로:행`은 기준 커밋 기준이다. 실제 대화·닉네임·서버 정보는 어느 문서에도 넣지 않았다.
- 2026-10-02 검토(`Plans/1.Improvements/01–06`, v1.1.3a 기준) 뒤 고쳐진 항목(B01–B14 대부분)은 빼고, 아직 남은 것만 "여전히 남음"으로 다뤘다.

## 강점 (네 문서 공통)

- **실패하면 게시하지 않는 출력 파이프라인과 격리 실행**: 자료 블록 난수 표식, 사진 읽기 전용 마운트, 네트워크·도구 차단, 민감정보 없는 구조화 로그(01 S2, 03 강점 1·4, 04 강점 1·2).
- **멘션 사고 방지와 공개 소음 억제**: `AllowedMentions.none()`, 비공개 설정 화면, 명령 흔적 없는 결과(01 S1·S2).
- **`/셀프디스`의 동의 구조**: 본인 발언만 쓴다. 놀림 기능의 기준으로 삼을 만하다(02 강점 2, 04 강점 4).
- **0호출 재미가 많다**: 처형·순위·호출·프리셋은 모델을 부르지 않는다(02 강점 4).
